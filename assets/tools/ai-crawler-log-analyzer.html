AI crawler log analyzer

Paste lines from your access log, or choose the file, and this AI crawler log analyzer counts the hits from GPTBot, ClaudeBot, PerplexityBot and other AI crawlers. For each one you get its top pages, its status codes and when it was first and last seen, with a CSV download. The log is read in your browser and is not uploaded.

Two limits to keep in mind. A user agent can be faked, so each hit is a claim and not proof of who sent it. And a crawl is not a visit from a person: a bot that reads a page cannot buy anything.

How the AI crawler log analyzer works

  1. Each line is read as common or combined log format. Blank lines are skipped. A line in any other shape is counted as not parsed and listed with its line number.
  2. The user agent is searched for the crawler names in the list below, in any case. A line whose user agent names none of them counts as other traffic.
  3. Hits are grouped by crawler, then by page. The part of the path after ? is dropped, so /blog/setup?page=2 counts as /blog/setup.
  4. Times are converted to UTC with the offset in each line, so lines from servers in different time zones compare correctly. The lines can be in any order.
  5. One CSV has a row per crawler. The other has a row for every page each crawler asked for, not only the top 10 shown on the page. Neither holds IP addresses.

Lines are read in small batches, so the page keeps responding on long logs. A large paste is kept in memory and not drawn in the box.

Common and combined log format

The combined format is the common format with two more fields, the referrer and the user agent:

common:   192.0.2.10 - - [02/Nov/2026:08:15:02 +0000] "GET /pricing HTTP/1.1" 200 5120
combined: 192.0.2.10 - - [02/Nov/2026:08:15:02 +0000] "GET /pricing HTTP/1.1" 200 5120 "-" "GPTBot/1.2"

Only the combined format says who asked, so no crawler can be named in a common format line. Those lines are counted apart. Nginx uses the combined format by default, and the Apache documentation shows how to switch it on. Extra fields after the user agent are ignored, and a virtual host at the start of the line is fine. JSON logs are not read.

If the log is over 50 MB, keep only the lines that name an AI crawler and load the result. The unnamed traffic is then left out:

grep -iE "GPTBot|OAI-SearchBot|ChatGPT-User|ClaudeBot|Claude-(SearchBot|User)|Perplexity(Bot|-User)|Google-Extended|Applebot-Extended|Amazonbot|Amzn-(SearchBot|User)|meta-(externalagent|webindexer|externalfetcher)|DuckAssistBot|CCBot|Bytespider" access.log > ai.log

How to read the result

  • Training, search and answer bots differ. An answer bot such as ChatGPT-User opens a page because someone asked an assistant. A training bot such as GPTBot collects pages for models. Read them apart.
  • Many 404 codes. The crawler asks for pages that are gone. Redirect the ones that moved.
  • Codes 403 or 429. Your server, firewall or CDN turns the bot away, whatever robots.txt says.
  • Code 304. The page had not changed since the last fetch, so it was not sent again.
  • Requests for /robots.txt. The crawler is checking your rules. To change them, use the robots.txt generator for AI crawlers.
  • No hits at all. The log may cover a short time, the format may lack the user agent, or a CDN may answer from its cache so the request never reaches your server.

A user agent can be faked, and a crawl is not a visit

Anyone can send a request that calls itself GPTBot. Before you act on a number, compare the IP addresses in those lines with the list the operator publishes: OpenAI, Anthropic, Perplexity and DuckDuckGo publish theirs. This tool does not check addresses.

A crawl also tells you nothing about sales. A bot that reads a page may lead to a cited link, the link may bring a person, and the person may buy. To judge AI search, measure those people: is AI search traffic worth anything?

AI crawler log analyzer FAQ

How do I find AI crawlers in my access log?

Look for their names in the user agent field of each line, such as GPTBot, ClaudeBot or PerplexityBot. Paste the lines here, or choose the file, and the hits are counted per crawler.

Which log formats can I paste?

The common and combined formats that Apache and Nginx write. Common format lines have no user agent, so they are counted but no crawler can be named in them. JSON logs are not read.

Can a crawler's user agent be faked?

Yes. Any program can send any user agent, so treat a hit as a claim. To check it, compare the IP address in the log line with the addresses the operator publishes.

Is an AI crawler hit the same as a visit?

No. A crawl is a bot reading a page. A visit is a person opening your site, for example by clicking a link in an assistant's answer, and only a person can buy.

How large a log can it read?

Up to 200,000 lines that are not blank, or a 50 MB file. Lines past the limit are counted and left out. For a larger log, keep only the AI crawler lines with grep first.

Is my log sent anywhere?

No. The lines are read in your browser with plain JavaScript, and the CSV files are created on your device.
