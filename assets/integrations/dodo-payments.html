integrations / dodo-payments

Dodo Payments revenue attribution: each payment joined to the visit behind it.

Virling reads Dodo Payments payments, refunds, disputes and subscriptions with one API key and no webhook, and the script tags your payment links on its own, so each payment shows the channel, referrer and page behind it. Open source, one Rust binary, or hosted.

Start free trial See the demo

The script keeps a visitor ID in a first-party cookie. When a Dodo payment carries that ID, Virling credits it to one of that visitor's sessions in the lookback window, by default the last one that was not Direct, so a buyer who first came from a newsletter and later typed your address is still credited to the newsletter. See Model and lookback window.

Connect with one API key, no webhook

  1. Create an API key in the Dodo Payments dashboard. Dodo's guide: API reference introduction.
  2. Paste it into Virling, under Payment connections in site settings.

Virling adds nothing to your Dodo account: there is no webhook to register and no endpoint for Dodo to reach, so it works the same on a self-hosted server without a public https address. Everything below is read over the API with that key.

Live and test keys

Dodo issues separate keys for live mode and test mode, on separate API hosts. Virling tries a pasted key against live.dodopayments.com first and test.dodopayments.com second, and remembers which one accepted it, so you never pick a mode by hand. A site has one Dodo Payments connection: replacing a test key with a live one switches the mode, and the test payments already imported stay in your reports.

What is read, and how often

  • Succeeded payments from the last 90 days on the first run, then new ones every minute. Dodo lists payments by the time they were created, so Virling walks one day at a time, re-reads the last 30 minutes on each round, and once an hour re-reads the last 30 days to catch renewals that succeed days after they were created.
  • Refunds, from Dodo's refund list. A refund made after you connect updates its payment even when that payment is older than the 90-day import.
  • Disputes, from the payment itself.
  • Subscriptions, for Retention. Active and on hold subscriptions count as still paying.

Dodo allows 240 requests per minute, so Virling makes at most a couple of extra lookups per round, such as a payment's refunds or a subscription's payments, and continues on the next round. A large backfill can take a few minutes to finish.

Products and payment links

Static payment links on checkout.dodopayments.com/buy/... need no code. When a visitor clicks one, the script adds metadata_virling_vid=<visitor ID> to the link, unless it is already there, and Dodo stores it as the payment's metadata.virling_vid, which is what Virling reads. The link must be a normal <a href> on a page that runs the script.

For a checkout session you create on your server, set it in metadata from the virling_vid cookie:

const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: "pdt_...", quantity: 1 }],
  return_url: "https://yourdomain.com/thanks",
  metadata: { virling_vid: req.cookies.virling_vid },
});
// Send the customer to session.checkout_url

If you build a payment link URL in your own code instead of an <a href>, add the parameter yourself:

const url = new URL("https://checkout.dodopayments.com/buy/pdt_...");
const vid = window.virling?.vid?.();
if (vid) url.searchParams.set("metadata_virling_vid", vid);
location.href = url.href;

When one Dodo account sells more than this site's products, list the site's product IDs in site settings, under Payment connections, in Only these product IDs, separated by commas. Virling then imports only payments, refunds and subscriptions for those products, and a subscription payment counts for its subscription's product. Saving the list imports the last 90 days again; payments already imported for other products stay until you disconnect and connect again.

Refunds and disputes

A succeeded refund lowers the revenue of its payment, on that payment's date, so the channel credited with it drops too. A partial refund leaves the payment partly refunded; a full one marks it refunded. A dispute that Dodo records as lost or accepted counts as a full refund, since the money went back to the customer. Disputes are read when Virling reads the payment, so for one decided later use Replace key to read the last 90 days again.

Subscriptions and renewals

For a subscription payment, Virling looks up the subscription's succeeded payments in Dodo. The first paid one is the first payment and every later one is a renewal that keeps its channel. A $0 payment that starts a free trial is kept only to credit the subscription's first paid charge, which goes to the visit before the trial when it has no visitor ID of its own. See Renewals.

Check it in test mode

  1. Connect a test mode key. With it Virling reads test payments and refunds.
  2. Open a private window and visit a page that runs the script through a tagged link, such as https://yourdomain.com/?utm_source=test&utm_medium=email.
  3. In the same window, go to a test checkout your server creates with metadata.virling_vid, or a test link with metadata_virling_vid added in your own code, and pay with a test card. The script does not add the visitor ID to test links.
  4. Wait a minute for the next sync, then open the payments list at /app/yourdomain.com/payments. The payment shows the test source and the Email channel of your tagged visit instead of Unattributed. Open it to see its visitor ID and its journey, which should start at your tagged visit.

Use a new email address for each test: a later payment by the same customer is a renewal and keeps the first payment's channel. If you sell only through static payment links, connect the live key, make one small live payment through a link and refund it. If a step fails, see Test your setup.

What you can see

With Dodo payments flowing in, the dashboard cards that help most are:

  • Channels: visitors, revenue and revenue per visitor for each channel, with Source and Campaign tabs, and Refunded, the share of a row's payments refunded in whole or part.
  • Location: visitors, revenue and revenue per visitor by country, city and language, useful when Dodo sells to buyers in many countries.
  • Goals: the Funnel tab shows the share that reached Visit, Signup, Checkout started and Paid, with the drop between steps.
  • Profit by channel: appears once you type your monthly spend per channel in Site settings, with spend, credited revenue, profit and the return per dollar spent.

Why a Dodo payment stays Unattributed

It still counts toward revenue, with no channel credited, unless the same customer has an earlier payment or trial that was:

  • A checkout session created with no virling_vid in its metadata, or a payment link built in code without metadata_virling_vid.
  • A payment link opened from an email, a QR code or another site, or clicked with the script blocked or cookieless mode on.
  • A payment from before the script was on your site, which usually includes the 90-day import.

Dodo payments are not matched by email. To find the cause for one payment, see Unattributed revenue.

Frequently asked questions

How do I see which channel a Dodo Payments payment came from?

Connect Dodo Payments to Virling with an API key. Virling reads each payment's metadata.virling_vid and ties it to the visit before it, and static payment links need no code.

Do live and test keys both work for Dodo Payments?

Yes. Virling tries the key against live.dodopayments.com first and test.dodopayments.com second, and remembers which one accepted it.

Does Virling add a webhook in Dodo Payments?

No. Virling reads payments, refunds, disputes and subscriptions with the API key alone and adds nothing to your Dodo account, so it also works on a server without a public https address. Disconnect deletes the stored key; delete the key in Dodo Payments too to revoke access.

Which channel do Dodo Payments renewals get?

The channel of the subscription's first paid payment. Virling looks up the subscription's succeeded payments in Dodo, so a $0 trial start is not the first payment, and the first paid charge goes to the visit before the trial when it has no visitor ID of its own.

Are Dodo Payments refunds and disputes taken off the channel?

Yes. A succeeded refund lowers the revenue of its payment, on that payment's date, so the channel credited with it drops too. A lost or accepted dispute counts as a full refund when Virling reads the payment, so for a later one use Replace key to read the last 90 days again.

Why is a Dodo Payments payment Unattributed?

Usually because the payment has no metadata.virling_vid: the checkout session was created without it, or a payment link was opened from an email or another site, or built in code without metadata_virling_vid.

Can Virling import only some Dodo Payments products?

Yes. When one Dodo account sells more than this site's products, list the site's product IDs in site settings, under Payment connections, in Only these product IDs, separated by commas. Virling then imports only payments, refunds and subscriptions for those products.
