integrations / dodo-payments

Dodo Payments revenue attribution: each payment joined to the visit behind it.

Virling ties each Dodo Payments payment to the visit that came before it, so your analytics show which channel, referrer and page bring paying customers, not just visitors. Open source, one Rust binary, or hosted.

Start free trial See the demo

Virling reads Dodo Payments payments, refunds and subscriptions with an API key.

Create an API key

  1. Create an API key in the Dodo Payments dashboard. Dodo's guide: API reference introduction.
  2. Paste it into Virling.

Live mode and test mode keys both work. Virling tries the key against live.dodopayments.com first and test.dodopayments.com second, and remembers which one accepted it.

What is imported

  • Payments from the last 90 days on the first run, then new ones every minute. Listing walks one day at a time and re-reads the last 30 minutes on each round, so payments that succeed late are not missed.
  • Refunds and disputes. Refunds update the payment they belong to. Lost or accepted disputes count as refunded, since the money went back to the customer.
  • Renewals. For a subscription payment, Virling looks up the subscription's paid payments. Every payment after the first paid one is marked as a renewal, so the first charge after a free trial counts as the first payment.

To stay inside Dodo's limit of 240 requests per minute, Virling makes at most a couple of extra lookups per round and continues on the next round. A large backfill can take a few minutes to finish.

How a payment finds its visitor

Virling reads metadata.virling_vid on the payment.

### Payment links

Static payment links on checkout.dodopayments.com/buy/... need no code. When a visitor clicks one, the script adds metadata_virling_vid=<visitor ID> to the link, unless it is already there, and Dodo stores it as the payment's metadata.virling_vid. The link must be a normal <a href> on a page that runs the script.

### Checkout sessions

For a checkout session you create on your server, set it in metadata from the virling_vid cookie:

const session = await client.checkoutSessions.create({
  product_cart: { product_id: "pdt_...", quantity: 1 },
  return_url: "https://yourdomain.com/thanks",
  metadata: { virling_vid: req.cookies.virling_vid },
});
// Send the customer to session.checkout_url

If you build a payment link URL in your own code instead of an <a href>, add the parameter yourself:

const url = new URL("https://checkout.dodopayments.com/buy/pdt_...");
const vid = window.virling?.vid?.();
if (vid) url.searchParams.set("metadata_virling_vid", vid);
location.href = url.href;

Check it in test mode

  1. Connect a test mode key. With it Virling reads test payments and refunds.
  2. Open a private window and visit a page that runs the script through a tagged link, such as https://yourdomain.com/?utm_source=test&utm_medium=email.
  3. In the same window, go to a test checkout your server creates with metadata.virling_vid, or a test link with metadata_virling_vid added in your own code, and pay with a test card. The script does not add the visitor ID to test links.
  4. Wait a minute for the next sync, then open the payments list at /app/yourdomain.com/payments. The payment shows the test source and the Email channel of your tagged visit instead of Unattributed. Open it to see its visitor ID and its journey, which should start at your tagged visit.

Use a new email address for each test: a later payment by the same customer is a renewal and keeps the first payment's channel. A site has one Dodo Payments connection, and test payments stay in your reports after you replace the key with a live one. If you sell only through static payment links, connect the live key, make one small live payment through a link and refund it. If a step fails, see Test your setup.

What you can see

Once payments come in, these cards on the dashboard answer questions a seller asks:

  • Which channels bring paying customers, not only visits? The Channels card lists visitors, revenue and revenue per visitor for each channel, with Source and Campaign tabs for the site or tagged campaign behind it.
  • Which countries do buyers come from? The Location card shows visitors, revenue and revenue per visitor by country, city and language.
  • Where do visitors drop off before paying? The Goals card's Funnel tab shows the share that reached Visit, Signup, Checkout started and Paid, with the drop between steps.
  • Which channel's payments get refunded? The Channels card also shows Refunded, the share of a row's payments that were refunded in whole or part.
  • Does a channel earn more than it costs? The Profit by channel card appears once you type your monthly spend per channel in Site settings. It shows spend, credited revenue, profit and the return per dollar spent.

What stays Unattributed

These payments still count toward revenue, but no channel is credited, unless the same customer has an earlier payment or trial that was credited:

  • Payments from a checkout session created with no virling_vid in its metadata, or from a payment link built in code without metadata_virling_vid.
  • Payments from a payment link opened from an email, a QR code or another site, or by a visitor with no visitor ID because the script was blocked or cookieless mode was on.
  • Payments from before the script was on your site, which usually includes the 90-day import.
  • Payments with a visitor ID when no visit of that visitor falls inside the lookback window.
  • Renewals, usually, when the first payment is Unattributed or older than the first import.

Dodo Payments payments are not matched by email. To find the cause for one payment, see Unattributed revenue.

Frequently asked questions

How do I see which channel a Dodo Payments payment came from?

Connect Dodo Payments to Virling with an API key. Virling reads each payment's metadata.virling_vid and ties it to the visit before it, and static payment links need no code.

Do live and test keys both work for Dodo Payments?

Yes. Virling tries the key against live.dodopayments.com first and test.dodopayments.com second, and remembers which one accepted it.

How are refunds and renewals handled for Dodo Payments?

Refunds update the payment they belong to, lost or accepted disputes count as refunded, and every payment after the first paid one of a subscription is marked as a renewal.

Which channel do Dodo Payments renewals get?

Every payment after a customer's first keeps the channel of the first one. The first payment after a free trial is credited to the visit before the trial when it has no visitor ID of its own. If the first payment is older than the first import, renewals are usually Unattributed.

Are Dodo Payments refunds and disputes taken off the channel?

Yes. A succeeded refund lowers the revenue of its payment, on that payment's date, so the channel credited with it drops too. A lost or accepted dispute counts as a full refund when Virling reads the payment, so for a later one use Replace key to read the last 90 days again.

Why is a Dodo Payments payment Unattributed?

Usually because the payment has no metadata.virling_vid: the checkout session was created without it, or a payment link was opened from an email or another site, or built in code without metadata_virling_vid.

Can Virling import only some Dodo Payments products?

Yes. When one Dodo account sells more than this site's products, list the site's product IDs in site settings, under Payment connections, in Only these product IDs, separated by commas. Virling then imports only payments, refunds and subscriptions for those products.
