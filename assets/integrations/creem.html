integrations / creem

Creem revenue attribution: each payment joined to the visit behind it.

Virling adds a signed webhook to your Creem account with a scoped key, then ties each completed checkout to the visit before it, so you see which channel, referrer and page bring paying customers. Open source, one Rust binary, or hosted.

Start free trial See the demo

Each checkout you create carries the visitor ID from Virling's first-party cookie, and Creem hands it back when the checkout completes. Virling then credits the payment to one of that visitor's sessions in the lookback window. How Virling works explains the join, and Model and lookback window which session gets the credit.

Key scopes

Creem API keys are scoped, and Virling asks for no more than it uses:

  1. In Creem, open Developers, then API keys, and create a key. Creem's guide: API introduction.
  2. Give it transactions:read, which is required. Add subscriptions:read so Retention can tell who still pays; without it, retention falls back to payment recency. Add webhooks:write so Virling can add its webhook; on an https server, connecting without it fails with a message asking for that scope. No other scopes are needed.
  3. Paste it into Virling.

A key that starts with creem_test_ is tried against test-api.creem.io first, and any other key against api.creem.io first, then the other host.

Why Creem needs a webhook

Creem returns checkout metadata only in webhooks, not on transactions, so the transaction list alone can never say which visitor paid. When you connect, Virling adds one webhook for checkout.completed that points at https://<your Virling>/api/webhooks/creem/<site ID>, and keeps its signing secret encrypted. Each delivery is checked against the creem-signature header, an HMAC-SHA256 of the body.

Creem can only deliver to a public https address. A self-hosted server on plain http still imports every transaction, but none of them get a visitor ID. After moving to https, set VIRLING_BASE_URL and use Replace key to add the webhook.

Virling reads virling_vid from, in order: the checkout's metadata, the subscription's metadata, then the customer's metadata. Set it when you create the checkout on your server:

const res = await fetch("https://api.creem.io/v1/checkouts", {
  method: "POST",
  headers: { "x-api-key": process.env.CREEM_API_KEY, "content-type": "application/json" },
  body: JSON.stringify({
    product_id: "prod_...",
    success_url: "https://yourdomain.com/thanks",
    metadata: { virling_vid: req.cookies.virling_vid },
  }),
});
// Send the customer to (await res.json()).checkout_url

Use https://test-api.creem.io with a test mode key.

A hosted product link, the same for every visitor, carries no visitor ID: the script does not add one to Creem links, so create the checkout on your server instead.

How far back history goes

  • First import: transactions from the last 90 days, newest first. They count as revenue, but those from before the webhook carry no visitor ID and are usually Unattributed.
  • After that: new transactions every minute.
  • Refunds and chargebacks: transactions from the last 60 days are read again every 6 hours, so a refund can take that long to show. A refund on an older transaction is not picked up automatically.

A refund lowers the revenue of its transaction, on that transaction's date, and a chargeback counts as a full refund.

Creem renewals and trials

  • Renewals. Every payment after a customer's first is a renewal and keeps the channel of the first payment. See Renewals.
  • Free trials. A completed checkout with nothing to pay starts a trial, and the customer's first paid transaction is credited to that trial.
  • Subscription status, read once an hour with subscriptions:read. Active, trialing and past due subscriptions count as still paying, and one scheduled to cancel counts until its current period ends.

When a Creem payment has no channel

The payment counts toward revenue either way. It is credited to no channel, unless the customer has an earlier credited payment or trial, when:

  • No webhook brought its checkout: it is from before you connected, or Virling was not reachable over https.
  • The checkout, the subscription and the customer all lack virling_vid in their metadata.
  • The visitor had no ID, because the script was blocked or cookieless mode was on.

Creem payments are not matched by email. For one payment, see Unattributed revenue.

Frequently asked questions

How do I see which channel a Creem payment came from?

Connect Creem to Virling with a scoped API key and set virling_vid in the checkout metadata. Virling adds a checkout.completed webhook and ties each payment to the visit before it.

Which scopes does the Creem key need?

transactions:read, plus subscriptions:read for Retention and webhooks:write so Virling can add its webhook. No other scopes are needed.

Why does Creem need a webhook?

Creem returns checkout metadata only in webhooks, not on transactions. Without an https address for Virling, payments still import but stay Unattributed.

How are Creem renewals and trials credited?

Every Creem transaction after a customer's first is a renewal and keeps the first payment's channel. A completed checkout with nothing to pay starts a trial, and the customer's first paid transaction is credited to it.

Are Creem refunds and chargebacks taken off the channel?

Yes. A refund lowers the revenue of its transaction, on that transaction's date, so the channel credited with it drops too, and a chargeback counts as a full refund. Transactions from the last 60 days are read again every 6 hours, so a refund can take that long to show, and one on an older transaction is not picked up automatically.

Why is a Creem payment Unattributed?

Usually because the checkout had no virling_vid in its metadata, or no webhook brought it: the payment is from before you connected, or Virling was not reachable over https.

How far back does Creem history go?

The first import reads transactions from the last 90 days. They count as revenue, but those from before the webhook carry no visitor ID and are usually Unattributed.

Does disconnecting remove Virling's Creem webhook?

No. Disconnect deletes the stored key and stops syncing, and imported payments stay in your reports. Delete the key and Virling's webhook in Creem too, since disconnecting does not remove them there.
