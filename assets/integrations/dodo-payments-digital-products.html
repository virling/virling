integrations / dodo payments for digital products

See which channel sells your ebooks, templates and courses on Dodo Payments.

For creators who sell ebooks, templates, courses and other digital downloads through Dodo Payments. Virling ties each payment to the channel and campaign that brought the buyer, so you see which launch post, newsletter or creator brought the money, not just the clicks. Open source under AGPL, hosted or self-hosted.

Start free trial See the demo

Dodo Payments records who bought and how much, but not the visit that brought them. A launch post, a newsletter mention or a creator's video sends a wave of visitors, and a few of them buy. Virling joins the two through the visitor ID the script passes into checkout, and reads Dodo Payments with an API key, without changing anything there.

What you get

  • Each sale credited to a channel and campaign. Payments are imported and joined to the visits before them. Every visit gets one channel from its first pageview: Paid, Email, AI, Organic search, Communities, Social, Referral or Direct. By default a payment goes to the latest visit in the last 90 days that was not Direct.
  • Revenue per source, campaign and landing page. The dashboard lists visitors, revenue and revenue per visitor for each channel, source, campaign and landing page, so a post that sent many visitors and no sales stands apart from a small one that paid.
  • Newsletters and creators measured by sales. Hacker News, Reddit and Product Hunt count as Communities, and a link tagged utm_medium=newsletter counts as Email. Give each sponsor or creator a tagged link and compare them by revenue.
  • Refunds and disputes taken off. Refunds update the payment they belong to, and lost or accepted disputes count as refunded, since the money went back to the buyer. The last 30 minutes are read again on each round, so payments that succeed late are not missed.
  • Only the products of this site. If one Dodo account sells more than this store, list its product IDs under Only these product IDs and Virling imports only those payments.
  • Time to pay. The Time to pay card shows the median time from first visit to first payment per channel, so you see how long buyers from each channel take to decide.

Set it up

  1. Add the site. Click + Add a site and enter your domain, such as yourstore.com, and its timezone.
  2. Install the script. Paste the tag before </head> on every page that links to your Dodo Payments checkout. Leave cookieless mode off, since checkout needs the visitor ID.
  3. Connect Dodo Payments. Create an API key in the Dodo Payments dashboard and paste it under payments. Live mode and test mode keys both work. The last 90 days are imported, then new payments every minute.
  4. Link checkout to visits. Static payment links on checkout.dodopayments.com/buy/... need no code: keep the link as a normal <a href> on a page that runs the script, and the script adds metadata_virling_vid=<visitor ID>, which Dodo stores as the payment's metadata.virling_vid. For a checkout session you create on your server, set virling_vid in metadata from the cookie. For a payment link URL you build in the browser:
const url = new URL("https://checkout.dodopayments.com/buy/pdt_...");
const vid = window.virling?.vid?.();
if (vid) url.searchParams.set("metadata_virling_vid", vid);
location.href = url.href;

Make a test purchase from a page that runs the script, wait for the next sync, and the payment shows a channel instead of Unattributed. The full walkthrough is in how to track Dodo Payments revenue by traffic source, and Dodo Payments UTM tracking covers passing source data through checkout. Every setting is on the Dodo Payments integration page, and other providers are on revenue attribution for digital products.

What to know

  • Sales made before the visitor ID was passed into checkout are Unattributed. They still count toward revenue.
  • A buyer who pays from a link in an email or a DM, without visiting your site first, has no visit to credit and is Unattributed.
  • Payment links must be normal <a href> links on a page that runs the script. Nothing is added in cookieless mode.
  • To stay inside Dodo's limit of 240 requests per minute, Virling makes at most a couple of extra lookups per round, so a large backfill can take a few minutes to finish.

Open source

Virling is open source under AGPLv3, and the code is on GitHub. Use the hosted service, or self-host it as one binary with every feature. In a load test on 2026-10-31, in a container limited to one vCPU and 1 GB of RAM, it ingested 100,000 pageviews at 2,829 a second with none failed and a p99 of 34 ms, and used 157 MB of memory after the ingest.

Frequently asked questions

How do I see Dodo Payments sales by traffic source?

Connect Dodo Payments to Virling with an API key and add the Virling script to your site. Static payment links on checkout.dodopayments.com need no code: the script adds the visitor ID, and Dodo stores it in the payment metadata. Each sale is then credited to the visit before it, with its channel, source, campaign and landing page.

Do I need to write code for Dodo Payments payment links?

No. Normal links to checkout.dodopayments.com/buy/... on a page that runs the script get metadata_virling_vid added when the page loads and when a visitor clicks. Only a checkout session you create on your server needs virling_vid set in its metadata.

Which newsletter or creator brought a sale?

Tag the link you give them with utm_source and utm_medium=newsletter, or make a tracked link. Every visit gets a channel, source and campaign from its first pageview, so the Source and Campaign tabs show revenue per newsletter, creator or post.

Does Virling change anything in my Dodo Payments account?

No. Virling only reads payments, refunds and subscriptions, and never creates, changes or refunds anything. Live mode and test mode keys both work.
