An engineer who starred your repo in March and typed your address to buy in May looks like a Direct visit, and Stripe has no visit at all. Virling reads Stripe with a read-only key and credits each payment to the visits before it, through the visitor ID your checkout passes on. How Virling works has the details.

Your README and docs as channels

  • Each README link on its own row. GitHub sends only its origin as the referrer, so the install section, the badge and the release notes all look like one GitHub visit. Tag each link with its own campaign, such as ?utm_source=github&utm_medium=referral&utm_campaign=readme, and the Campaign tab shows the revenue each placement brought.
  • Docs pages as landing pages. A docs page that starts a visit is that visit's landing page, so the Landing pages card shows which guide or API reference brought developers who later paid. With the script on docs.yourtool.dev, the docs share one visitor ID with your site and app.
  • Time from first read to first payment. The Time to pay card shows, per channel of the first visit, the median time from that visit to the first payment. Developers often evaluate for weeks, so if that is longer than the default 90-day window, set the window to 365 days in Site settings so the Channels card still credits the visits that found you.

GitHub and package registry referrers

  • GitHub visits land in Referral, on a GitHub row in the Source tab.
  • npm, crates.io, PyPI and other registries are not on a known list, so a click from one lands in Referral under its own host, such as npmjs.com. A registry page that sends no referrer leaves the visit Direct, so put a tagged URL, such as ?utm_source=npm, in the homepage field of your package metadata.
  • Hacker News, Lobsters and DEV land in Communities with no tag, when the referrer arrives.

From open source user to paying customer

Most people who run your open source code never pay, and those who self-host it never reach Stripe at all, so they are not in the revenue. What you can see is the path of those who do pay: send a signup goal when an account is created, and the Funnel tab of the Goals card shows, per channel you filter by, how many visitors reach Signup, Checkout started and Paid. A free tier account is a visitor, not a customer, until Stripe records a charge.

Metered billing on Stripe

  • Usage invoices keep the first channel. Usage billed on the subscription's invoice at the end of a period has billing reason subscription_cycle. Virling marks its charge as a renewal and credits the channel, campaign and landing page of the customer's first payment, matched by Stripe customer ID, whatever the amount is that month.
  • Threshold invoices too. An invoice Stripe sends early because usage crossed a billing threshold is not a subscription_cycle invoice, but any payment after a customer's first one counts as a renewal, so it keeps the same channel.
  • Charge a base fee at checkout. A plan that bills only usage starts with a Checkout total of 0, which Virling stores as a trial start. The first usage charge is credited to the visits before that checkout, but it is marked as a renewal, and Retention leaves out customers whose earliest payment is a renewal. A base fee paid at checkout avoids that gap.
  • MRR leaves metered items out. MRR is the list price of fixed recurring items, so a subscription with metered or tiered items is not in MRR. What those items bill still counts in revenue.

Set it up for a developer tool

  1. Add the site. Click + Add a site and enter your domain, such as yourtool.dev, and its timezone.
  2. Install the script on the site, the docs and the app. Paste the tag before </head> on all three, with the same data-site. The virling_vid cookie is set on your registrable domain, so yourtool.dev, docs.yourtool.dev and app.yourtool.dev share one visitor ID. Leave cookieless mode off. If your docs are on another domain, read whether your docs bring paying customers first.
  3. Tag your GitHub and registry links. Give each README placement and each package homepage its own campaign. GitHub revenue tracking has the links to copy.
  4. Connect Stripe. Create a restricted key with Read on Charges, Checkout Sessions, Customers, Events, Invoices, Subscriptions and PaymentIntents, and paste it under payments. The last 90 days are imported, then new payments every minute.
  5. Pass the visitor ID to checkout. Set client_reference_id to the virling_vid cookie, or use metadata.virling_vid if you already use that field.
  6. Track signups. Call virling("goal", "signup") after a free signup.
// A plan with a base fee and metered usage through Stripe Checkout
await stripe.checkout.sessions.create({
  mode: "subscription",
  line_items: [
    { price: "price_base...", quantity: 1 },
    { price: "price_usage..." },
  ],
  client_reference_id: req.cookies.virling_vid,
  // ...
});

To check it, open your site in a private window from a tagged README link, buy a paid plan, wait a minute for the next sync and open the payments list. The payment should show your readme campaign instead of Unattributed. Refund it in Stripe afterwards.

Hacker News launch revenue covers a launch there. Every setting is on the Stripe integration page, and Virling for developer tools covers other payment providers.

What to know

  • A Payment Link or Checkout opened straight from a README, a terminal or a package page carries no visitor ID and shows as Unattributed. Send developers to a page on your site first.
  • Payments older than the 90-day backfill are not imported, so usage invoices of subscriptions that started before that are Unattributed.
  • A team that buys more seats on the same Stripe customer keeps the channel of its first payment, so seat growth counts toward the channel that brought the team.

Frequently asked questions

Which channel brings my paying customers on Stripe?

Connect Stripe to Virling with a read-only restricted key and pass the virling_vid visitor ID into Checkout as client_reference_id or metadata.virling_vid. Each payment is credited to the visits before it, so the Channels card and its Source and Campaign tabs show whether GitHub, your docs, Hacker News or a search brought the developers who pay.

How is usage-based billing on Stripe attributed?

When usage is billed on the subscription's invoice at the end of each period, that invoice has billing reason subscription_cycle, so Virling marks its charge as a renewal and credits the channel of the customer's first payment, matched by Stripe customer ID. If the subscription started with a Stripe Checkout total of 0, the first charge is credited to the visits before that checkout, as long as Stripe was connected by then.

Are visits from npm, crates.io or PyPI tracked?

Yes, when the registry sends a referrer: the visit lands in the Referral channel under the registry's host, such as npmjs.com. When it sends none, the visit is Direct, so tag the homepage URL in your package metadata with a utm_source such as npm and it lands in Referral under that source.

Can I link a Stripe Payment Link from my README?

You can, but a Payment Link opened from GitHub or any other site carries no visitor ID, so the payment shows as Unattributed. Link the README to a page on your own site that runs the script, and put the Payment Link there as a normal link.

Does a free tier signup count as revenue?

No. Virling counts payments from Stripe. A developer on your free tier is a visitor, and you can send a signup goal to see the step. A Stripe trial start, a checkout.session.completed event with a total of 0, is never counted as revenue, a payment or a customer.

Can Virling change anything in my Stripe account?

No. It uses a restricted key with Read permission only and refuses secret keys that start with sk_live_ or sk_test_. It never creates, changes or refunds anything.
