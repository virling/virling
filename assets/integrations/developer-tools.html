Revenue attribution for developer tools.

Developers find tools on GitHub, Hacker News, dev.to, in your docs and through AI assistants, then pay weeks later. Most of those visits show up as Referral or Direct in a pageview counter. Virling joins each payment to the visit that came before it, so you see which of them bring paying customers. For developer tools, APIs and open source projects with a paid tier.

A developer rarely pays on the first visit. They star the repository, read the docs, try the free tier and come back when a project needs it. Virling credits each payment to a visit before it, by default the latest visit that was not Direct inside a 90-day lookback window, and you can switch the site to first touch to credit the visit that introduced the buyer.

Where developers come from, and why it looks like Direct or Referral

Every session gets one channel from its first pageview. The places developers actually come from land in different ones, and many arrive with no referrer at all:

  • GitHub: github.com is not a community host, so clicks land in Referral and show as GitHub in the Source tab. GitHub sends only its origin, not the README, issue or release the link was on. See GitHub revenue tracking.
  • Hacker News and dev.to: both are community hosts, so clicks land in Communities. See Hacker News launch revenue and dev.to and Medium.
  • Package registries, newsletters and other blogs: any host not on a known list is Referral, under its own domain.
  • AI assistants: clicks from chatgpt.com, claude.ai, perplexity.ai, gemini.google.com and other known assistants land in AI.
  • Terminals, editors, desktop apps, notification emails and copied links: no referrer and no tag, so they are Direct.

Tag the links you control, in the README, release notes, CLI output and package description, with utm_source and one utm_campaign per placement. A click that arrives with no referrer then keeps its source, and the Campaign tab splits placements the referrer cannot.

Docs and app subdomains as one site

Developers move between the marketing site, the docs and the app before they pay. With data-site="example.com", pages on docs.example.com and app.example.com count for the same site, share the virling_vid cookie, and links between them are not exits. Referrers from your own domain and its subdomains are ignored, so reading the docs never changes the channel the visit came from.

Docs or an app on a separate domain, such as example.dev, keep their own cookie. Add that domain under Same-visit domains in Site settings: clicks to it are no longer counted as exits, and a return from it continues the visit instead of starting a new one. A return from GitHub login, Google and Apple sign-in and the supported checkouts already continues the visit. See Add the script.

Ask an assistant which channel pays

Virling serves a read-only MCP server, so an assistant such as Claude, Claude Code or ChatGPT can read your reports and answer questions like "which channel made the most money last month?". It signs in with OAuth or an API key, reads every site of your account and cannot change anything.

  • get_breakdown: visitors and credited revenue per channel, referrer, campaign, landing page or page.
  • get_channel_verdicts: one plain line per channel against the period before.
  • get_retention: customers still paying, LTV, refund rate and 30-day churn per first-payment channel.
  • get_ai_answers: how often assistants name your site for your buyer questions, and the visitors and revenue they sent.

The channel_review prompt asks for keep, fix or cut on each channel by revenue, value per visitor and retention. For Claude Code, the virling plugin bundles the MCP server and an agent skill.

Frequently asked questions

Why does GitHub show as Referral and not Communities?

Virling has a fixed list of community hosts, such as news.ycombinator.com, reddit.com, dev.to and lobste.rs. github.com is not on it, so a click from GitHub lands in Referral and shows as GitHub in the Source tab. GitHub sends only its origin as the referrer, so give each README or release link its own utm_campaign to tell them apart.

Do visits to my docs subdomain count as the same visit?

Yes. With data-site set to your domain, pages on subdomains such as docs.example.com and app.example.com count for the same site, share the visitor ID cookie, and moving between them never changes the channel. Docs on a separate domain keep their own cookie; add that domain under Same-visit domains in Site settings so clicks to it are not exits and a return from it continues the visit.

Does Sign in with GitHub start a new visit?

No. A return from GitHub login, like a return from Google or Apple sign-in or from a supported checkout, continues the visit the developer was already on, so the channel they first came from keeps the credit.

Can I ask an AI assistant which channel pays?

Yes. Virling serves a read-only MCP endpoint. Connect it to an assistant such as Claude or ChatGPT and ask which channel made the most money last month; it reads the same breakdowns, retention and AI answers the dashboard shows and cannot change anything.

Is Virling itself open source?

Yes, under AGPLv3. The code is at github.com/virling/virling. You can self-host it as one Rust binary, or use the hosted version with a 14-day free trial.
