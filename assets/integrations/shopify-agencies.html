integrations / shopify for agencies

Show each Shopify client which channel drives their sales.

For agencies that build and market several client Shopify stores. Virling ties every order to the channel and campaign that brought the buyer, on a separate site per client, and gives each client a branded report they open without a login. Open source under AGPL, hosted or self-hosted.

Clients ask one question: which channel paid. Shopify records the order, and your ads, emails and posts bring the visit, but the two rarely meet. Virling joins them for each client store, so the answer comes from their own orders. For clients who take payment through Stripe instead, see client Stripe revenue by channel.

What your agency gets

  • One site per client store. Each client domain has its own script and its own Shopify connection, so every client's revenue stays on their site. Sites with the same client name are grouped in the site switcher and on All clients, with visitors and revenue over the last 30 days and a total per client.
  • Orders by channel and campaign. The Channels card lists visitors, revenue and revenue per visitor for each channel, with the sources and UTM campaigns behind it. Payments lists every order with the channel it was credited to.
  • Sharing without logins. A client link opens a site's report with your agency name, logo and colours, and can be revoked at once. A weekly email sends the same report to up to 10 client addresses.
  • Public dashboard. A read-only page anyone can open without signing in, which never shows emails or customer IDs, for clients who want to share their numbers.
  • API and MCP. One API key lists every client site and reads each one, and the same key connects an AI assistant through the MCP server to ask which channel paid. Start from these questions to ask an AI assistant about client revenue.
  • Team members for your own staff, who see and manage every site on the account.

Before the first call

Ask the client for these, so setup does not stall halfway.

  • The domain and timezone. The domain shoppers visit, and the timezone their reports should use. A client with more than one domain gets one site per domain under the same client name.
  • Theme access. Someone who can edit theme.liquid, for one tag and one short snippet. Ask whether the store is headless or built with Hydrogen, because then the snippet does not apply and the visitor ID is set from the cart code instead.
  • A custom app with one scope. An Admin API access token, which starts with shpat_, from a custom app that has only read_orders. It does not need product, customer or write scopes.
  • The myshopify.com address. The store's https://your-store.myshopify.com address. The Admin API does not answer on a custom domain.
  • Campaign links. Every link in use in ads, emails, posts and bios, with the UTM tags each one carries today, so you can retag the bare ones. Ask about cart permalinks, Buy Button embeds and other sales channels too, because their orders carry no visitor ID.
  • Spend and recipients. Monthly spend per channel for Profit by channel, and up to 10 addresses for the weekly email.

Set up a client store

  1. Add the script. Click + Add a site, enter the client's domain and timezone, and set their name under Client in site settings. Paste the site's tag before </head> in the store's theme.liquid, with the short snippet from the Shopify integration after it, which stores the visitor ID on the cart so Shopify copies it onto the order.
  2. Connect Shopify. In the client's Shopify admin, create a custom app with only the read_orders scope and install it. Paste its Admin API access token and the store's myshopify.com address into the site's payment setup. Orders from the last 60 days are imported, then new ones every minute.
  3. Tag campaigns. Build every ad, email and post link with the UTM builder, so each campaign shows up by name instead of as Direct. Untagged links are the usual reason orders land there; see why Shopify orders show up as Direct.
  4. Share the report. Under Client report in site settings, add your branding, then create a client link and send it. Turn on the weekly email to send the report on a schedule.

Monthly client reports

The client report and weekly email cover each week, with one plain line per channel against the week before. For a monthly review, pick the month as the dashboard range, read revenue and revenue per visitor from the Channels card, and open orders in Payments to show the journey behind a sale. Enter the client's monthly spend per channel in site settings and Profit by channel shows spend, revenue, profit and return per dollar.

The client marketing report template lays those numbers out in the order clients read them, and how to prove marketing ROI to clients walks through the monthly method. Download PDF on the report saves the page to attach to your own deck.

When a client leaves

  • Save the numbers first. Download PDF on the report saves the page. For raw rows, your API key reads the site's payments, up to 200 per call with an offset for paging, and its breakdowns, up to 1,000 rows each, as JSON. See the Read API.
  • Disconnect Shopify. Disconnect in site settings deletes the stored token.
  • Delete the token in Shopify. Ask the client to also delete the custom app's token in their own Shopify admin.
  • Revoke the client link. Revoke link under Client link in site settings turns the report off at once.
  • Stop the weekly email. Open Client report, click Change schedule and turn off Weekly email.
  • Revoke an API key you shared. A key reads every client site, and keys limited to one site are not available. Revoke it under API keys in account settings and requests with it fail right away.
  • Take the code out of the theme. Remove the script tag and the cart snippet from theme.liquid, or the cart code on a headless store.

Frequently asked questions

How do agencies show Shopify clients which channel drives sales?

Add one Virling site per client store, install the script and the theme snippet that stores the visitor ID on the cart, and connect the store with a read-only order token. Each order is tied to the channel and campaign of the visit before it, and the client sees it through a report link without a login.

Does each client store need its own setup?

Yes. Each client domain is its own site with its own script tag and its own Shopify connection, so every client's orders and revenue stay on their site. Sites with the same client name are grouped under All clients.

Can my clients see their numbers without a Virling account?

Yes. A client link opens that site's report without signing in, with your agency name, logo and colours. You can revoke it at any time, and you can also email the report every week.

Can Virling change anything in a client's Shopify store?

No. The custom app token only has the read_orders scope. Virling cannot change products, customers or orders.

Who can see which client?

Team members on your account see and manage every client site, and an API key reads every site too, so keep both for your own staff. A client link opens only that client's site report. Do not invite a client as a team member.

What does the client see when Virling and the ad platform disagree?

The report shows Virling's numbers only, and nothing connects to an ad platform. Virling counts the orders read from Shopify, net of refunds, and credits each to one visit under the site's model and lookback window. An ad platform may count and credit sales by its own rules, so the two can differ. The default is last non-direct with a 90-day window. Keep it the same on every client's site, and note in the report when a client uses something else.

How many months of Shopify orders load at the start?

About two. The first import reads orders from the last 60 days, the most Shopify gives without an extra permission, then new ones every minute. Orders from before the snippet was on the store count as revenue but are Unattributed, unless their email matches.
