LemonSqueezy revenue attribution: each order joined to the visit behind it.

Virling ties each LemonSqueezy payment to the visit that came before it, so your analytics show which channel, referrer and page bring paying customers, not just visitors. Open source, one Rust binary, or hosted.

Start free trial See the demo

Virling imports LemonSqueezy orders and subscription invoices, so they count toward revenue, and links them to visits through a webhook.

Create an API key

  1. In LemonSqueezy, open Settings, API, and create a key. LemonSqueezy's guide: getting started.
  2. Paste it into Virling.

The key has full access. LemonSqueezy API keys cannot be made read-only and cover every store on your account. Virling reads orders, subscriptions with their prices and store currency, and subscription invoices, adds the webhook described below to each store, and stores the key encrypted. Delete the key in LemonSqueezy at any time to revoke access.

What is imported

  • Orders and subscription invoices from the last 90 days on the first run, then new ones every minute. A subscription's first charge is imported once, as its order.
  • Refunds. Refunds do not change an order's creation time, so Virling rescans the last 60 days for refunds every 6 hours.
  • Renewals. An invoice with billing reason renewal is marked as a renewal.

Checkout attribution

LemonSqueezy only returns checkout custom data in webhooks. When you connect LemonSqueezy, Virling registers a webhook on each of your stores for order_created and subscription_payment_success, pointing at /api/webhooks/lemonsqueezy/ on your Virling address, with a signing secret it stores encrypted. Each webhook is checked against its X-Signature before the visitor ID is attached to the order or invoice. Connecting again with a new key updates the same webhook.

The webhook needs VIRLING_BASE_URL to be a public https:// address that LemonSqueezy can reach. Without one, no webhook is registered and LemonSqueezy payments show as Unattributed.

Checkout links on STORE.lemonsqueezy.com need no code: the script adds checkout[custom][virling_vid] to them. For a checkout you build yourself, pass the visitor ID as custom data. In the browser:

const url = new URL("https://STORE.lemonsqueezy.com/checkout/buy/VARIANT_ID");
const vid = window.virling?.vid?.();
if (vid) url.searchParams.set("checkout[custom][virling_vid]", vid);
location.href = url.href;

Or on your server, when you create a checkout with POST /v1/checkouts, set data.attributes.checkout_data.custom to { "virling_vid": "<the visitor's virling_vid cookie>" }.

Check it in test mode

  1. Switch your LemonSqueezy store to test mode, create an API key there and connect it. Virling must be on a public https:// address. With this key Virling reads test orders and adds its webhook in test mode.
  2. Open a private window and visit a page that runs the script through a tagged link, such as https://yourdomain.com/?utm_source=test&utm_medium=email.
  3. In the same window, click a test mode checkout link on your page and pay with a test card. The script adds the visitor ID to the link.
  4. Wait a minute for the next sync, then open the payments list at /app/yourdomain.com/payments. The payment shows the test source and the Email channel of your tagged visit instead of Unattributed. Open it to see its visitor ID and its journey, which should start at your tagged visit.

Use a new email address for each test: a later payment by the same customer is a renewal and keeps the first payment's channel. A site has one LemonSqueezy connection, and test orders stay in your reports after you replace the key with a live one. If a step fails, see Test your setup.

What you can see

Once orders come in, these cards on the dashboard answer questions a seller asks:

  • Which channels bring orders, not only visits? The Channels card lists visitors, revenue and revenue per visitor for each channel, with a Source tab for the site behind it.
  • Which campaign sold the most? The Channels card's Campaign tab shows the same numbers for each campaign you tagged.
  • Which landing pages do buyers arrive on? The Pages card shows revenue by the first page of the visit, and by the last page before paying.
  • Who bought most recently, and from where? The Recent customers card shows the last 10 paying customers with amount, first source, visits before paying and time to convert.
  • Does a channel earn more than it costs? The Profit by channel card appears once you type your monthly spend per channel in Site settings. It shows spend, credited revenue, profit and the return per dollar spent.

What stays Unattributed

These payments still count toward revenue, but no channel is credited, unless the same customer has an earlier order that was credited:

  • Every payment when VIRLING_BASE_URL was not a public https:// address when you connected, since no webhook is registered. Set it, then use Replace key to add the webhook.
  • Orders and invoices from before the webhook, which includes the 90-day import.
  • Orders from a checkout you create with no virling_vid in its custom data.
  • Orders from a checkout link opened from an email, a QR code or another site, or by a visitor with no visitor ID because the script was blocked or cookieless mode was on.
  • Orders with a visitor ID when no visit of that visitor falls inside the lookback window.
  • Renewals, usually, when the first order is Unattributed or older than the first import.

LemonSqueezy payments are not matched by email. To find the cause for one payment, see Unattributed revenue.

Frequently asked questions

Can Virling link LemonSqueezy orders to visits?

Yes, through a webhook. Virling registers a webhook for order_created and subscription_payment_success on each store, which needs VIRLING_BASE_URL to be a public https address. Without one, LemonSqueezy payments show as Unattributed.

Does the LemonSqueezy API key have to be read-only?

LemonSqueezy API keys cannot be made read-only and cover every store on your account. Virling stores the key encrypted, and you can delete it in LemonSqueezy at any time to revoke access.

How far back does Virling import LemonSqueezy orders?

Orders and subscription invoices from the last 90 days on the first run, then new ones every minute.

Do LemonSqueezy checkout links need code?

No. The script adds the visitor ID to checkout links on STORE.lemonsqueezy.com when they are normal links on a page that runs it. For a checkout you build yourself, pass virling_vid as custom data.

Which channel do LemonSqueezy renewals get?

Invoices with billing reason renewal or updated, and any later order by the same customer, keep the channel of that customer's first order. If that order is older than the first import, its renewals are usually Unattributed.

Why is a LemonSqueezy payment Unattributed?

Usually because no webhook brought its visitor ID: Virling was not on a public https address when you connected, the order is from before the webhook, or a checkout you create has no virling_vid in its custom data. Set VIRLING_BASE_URL, then use Replace key to add a missing webhook.

How are LemonSqueezy refunds counted?

Full and partial refunds lower the revenue of the order or invoice they belong to, on its own date. Orders and invoices from the last 60 days are read again every 6 hours, so a refund can take that long to show, and one on an older order is not picked up automatically.
