integrations / creem for digital products

See which post, launch or link sold your templates, ebooks and courses on Creem.

For creators and indie makers who sell templates, ebooks, courses and other digital products through Creem. Virling ties each sale to the post, launch or link that brought the buyer, so you see which one brought the money, not just the clicks. Open source under AGPL, hosted or self-hosted.

Start free See the demo

Creem records who bought and how much, but not the visit that brought them. A launch post, a newsletter mention or a link in a video sends a wave of visitors, and a few of them buy. Virling joins the two with a scoped Creem API key, one webhook and the visitor ID you pass into checkout.

What you get

  • Each sale credited to the visit that brought the buyer. Transactions are imported and joined to the visits before them, with their channel, source, campaign and landing page. By default a payment goes to the latest visit in the last 90 days that was not Direct.
  • Launches, posts and links compared by sales. Give each launch, newsletter or creator a link tagged with utm_source and utm_campaign, and the dashboard shows visitors, revenue and revenue per visitor for each one, so a post that sent many visitors and no sales stands apart from a small one that paid.
  • Refunds and chargebacks taken off. Transactions from the last 60 days are read again every 6 hours, so later refunds and chargebacks update them.
  • Memberships and repeat payments kept with the first channel. If you sell a course or template library as a subscription, every payment after a customer's first is a renewal and keeps the channel of the first payment.

Set it up

  1. Add the site. Click + Add a site and enter your domain, such as yourstore.com, and its timezone.
  2. Install the script. Paste the tag before </head> on every page that sends buyers to checkout. Leave cookieless mode off, since checkout needs the visitor ID.
  3. Connect Creem. In Creem, open Developers, then API keys, and create a key with transactions:read, plus subscriptions:read for retention and webhooks:write so Virling can add its webhook. No other scopes are needed. Paste it under payments; live and test mode keys both work. The last 90 days are imported, then new transactions every minute.
  4. Pass the visitor ID at checkout. Creem returns checkout metadata only in webhooks, so Virling adds one checkout.completed webhook when you connect and checks each delivery against its signature. It reads virling_vid from the checkout's metadata, then the subscription's, then the customer's. Set it in metadata when you create the checkout on your server:
const res = await fetch("https://api.creem.io/v1/checkouts", {
  method: "POST",
  headers: { "x-api-key": process.env.CREEM_API_KEY, "content-type": "application/json" },
  body: JSON.stringify({
    product_id: "prod_...",
    success_url: "https://yourstore.com/thanks",
    metadata: { virling_vid: req.cookies.virling_vid },
  }),
});
// Send the customer to (await res.json()).checkout_url

Use https://test-api.creem.io with a test mode key. Make a test purchase from a page that runs the script, and the payment shows a channel instead of Unattributed. See which post sold

  • Tagged links, one per place. Make a tracked link for each post, newsletter issue and bio, and point it at your sales page. The Campaign tab shows each one by name, and the Source tab splits a channel by source, such as Reddit or a newsletter.
  • Partner links. Under Partners, add each creator, affiliate or sponsor and the page to open, and give them the short link. They are ranked by revenue, with visitors, paying customers and refund rate. Copy report link gives a partner a read-only page with only their own numbers. Virling does not pay partners.
  • Launch days. Log the day under Launches to see the visitors, new customers and revenue of that day and the day after. Those figures count all traffic on the two days, so use tracked links to tell the places apart.

A made-up example, to show how to read the Campaign tab. A creator sells one $30 ebook through Creem and shares it in three places:

Newsletter issue200$240$1.20
Video description150$30$0.20

The launch post sent the most visitors, but a visitor from the newsletter was worth six times as much. Open any sale under Payments to see the visits before it and which one got the credit.

Why a Creem sale is Unattributed

  • The checkout link was in an email or a bio. A buyer who goes straight to Creem brings no visitor ID. Fix: link to your sales page, and have its buy button ask your server for a checkout with virling_vid in metadata.
  • The link had no tag. With no tag and no referrer, as from many bios, apps and newsletters, the visit lands in Direct, so the sale is credited to Direct rather than to the post. Fix: share a tracked link in each place.
  • Cookieless mode is on. Without the cookie your server has no virling_vid to send. Fix: set Visitor cookie to Cookie in site settings and take data-cookieless off the script tag. If you need consent first, use Until consent: visitors who accept can be credited.

A fix applies to new sales; earlier ones usually stay Unattributed.

What to know

  • Sales from checkouts created without virling_vid in their metadata are Unattributed. They still count toward revenue.
  • A buyer who pays without visiting your site first has no visit to credit and is Unattributed.
  • Transactions older than the 90-day backfill are not imported.
  • The webhook needs Virling to be reachable over https. A self-hosted server on plain http still imports payments, but they stay Unattributed.

Frequently asked questions

Which link sold my digital product on Creem?

Connect Creem to Virling with a scoped API key, add the Virling script to your site and set virling_vid in the metadata of each checkout you create. Virling adds a checkout.completed webhook to read that metadata and credits the sale to the visit before it, with its channel, source, campaign and landing page.

Do Creem checkouts need code to be attributed?

Yes. Creem returns checkout metadata only in webhooks, so the visitor ID has to be in the checkout's metadata. Set metadata.virling_vid to the visitor's virling_vid cookie when you create the checkout on your server with POST /v1/checkouts. Payments without a visitor ID still count toward revenue as Unattributed.

Which scopes does the Creem API key need?

transactions:read, plus subscriptions:read so Retention can tell who still pays, and webhooks:write so Virling can add its one checkout.completed webhook. No other scopes are needed. Live and test mode keys both work.

Are Creem refunds taken off?

Yes. Transactions from the last 60 days are read again every 6 hours, so later refunds and chargebacks update them.

Does Creem test mode work?

Yes. With a test mode key, Virling reads test transactions and adds its webhook in test mode. A site has one Creem connection, and test payments stay in your reports after you replace the key with a live one.

How far back does Creem history go?

The first import reads transactions from the last 90 days. They count as revenue, but those from before the webhook carry no visitor ID and are usually Unattributed.
