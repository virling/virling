integrations / stripe for agencies

Show each client which channel brought their Stripe revenue.

For agencies and freelancers who run marketing for clients that take payments through Stripe. Virling ties every client payment to the channel and campaign that brought the customer, on a separate site per client, and gives each client a branded report they open without a login. Open source under AGPL, hosted or self-hosted.

Clients ask one question: which channel paid. Stripe records the payment, and your ads, emails and posts bring the visit, but the two rarely meet. Virling joins them for each client, so the answer comes from their own Stripe payments.

What your agency gets

  • One site per client. Each client domain has its own script and its own Stripe connection, so every client's revenue stays on their site. Sites with the same client name are grouped in the site switcher and on All clients, with visitors and revenue over the last 30 days and a total per client.
  • Payments by channel and campaign. The Channels card lists visitors, revenue and revenue per visitor for each channel, with the sources and UTM campaigns behind it. Payments lists every Stripe payment with the channel it was credited to, and Retention shows which channels bring customers who keep paying.
  • Refunds and renewals kept current. Refunds, lost disputes and late settlements update payments already imported, and subscription renewals are marked as renewals.
  • Sharing without logins. A client link opens a site's report with your agency name, logo and colours, and can be revoked at once. A weekly email sends the same report to up to 10 client addresses.
  • API and MCP. One API key lists every client site and reads each one, and the same key connects an AI assistant through the MCP server to ask which channel paid.
  • Team members for your own staff, who see and manage every site on the account.

Before the first call

Ask the client for these, so setup does not stall halfway.

  • The domain and timezone. The domain customers visit, and the timezone their reports should use. A client with more than one domain gets one site per domain under the same client name.
  • Site access. Someone who can add one tag to the <head> of every page.
  • A restricted key with read access. A Stripe key that starts with rk_live_, with Read on Charges, Checkout Sessions, Customers, Events, Invoices, Subscriptions and PaymentIntents, and None on everything else. Tell them not to send a secret key, because Virling refuses it.
  • How they take payment. Checkout Sessions and PaymentIntents need a developer who can pass the visitor ID. Payment Links on buy.stripe.com need no code, but ones on a custom domain, or opened from an email or QR code, show as Unattributed.
  • Whether client_reference_id is taken. If they already use it for something else, the visitor ID goes in the session's metadata.virling_vid instead.
  • Campaign links. Every link in use in ads, emails, posts and bios, with the UTM tags each one carries today. Retag the bare ones with the UTM builder so each campaign shows up by name.
  • Spend and recipients. Monthly spend per channel for Profit by channel, and up to 10 addresses for the weekly email.

Set up a client

  1. Add the site. Click + Add a site, enter the client's domain and timezone, and set their name under Client in site settings.
  2. Install the script. Paste the site's tag from its setup screen before </head> on every page of the client's site. Each client gets its own tag, because data-site must match the domain you added.
  3. Connect Stripe. Ask the client for a Stripe restricted key with Read on Charges, Checkout Sessions, Customers, Events, Invoices, Subscriptions and PaymentIntents. Paste it into the site's payment setup and click Connect and backfill. Secret keys are refused. The last 90 days are imported, then new payments every minute.
  4. Pass the visitor ID at checkout. Set client_reference_id on the Checkout Session, or metadata.virling_vid on a PaymentIntent, from the virling_vid cookie. Payment Links on buy.stripe.com need no code. See the Stripe integration and how to track Stripe revenue by traffic source.
  5. Share the report. Under Client report in site settings, add your branding, then create a client link and send it. Turn on the weekly email to send the report on a schedule.

Payments without a visitor ID still count toward revenue, as Unattributed. Make a test payment from a page that runs the script and check that it shows a channel in Payments.

Monthly client reports

For a monthly review, pick the month as the dashboard range, read revenue and revenue per visitor from the Channels card, and open payments to show the journey behind a sale. Enter the client's monthly spend per channel in site settings and Profit by channel shows spend, revenue, profit and return per dollar.

The client marketing report template lays those numbers out in the order clients read them, and how to prove marketing ROI to clients walks through the monthly method. Download PDF on the report saves the page to attach to your own deck.

When a client leaves

  • Save the numbers first. Download PDF on the report saves the page. For raw rows, your API key reads the site's payments, up to 200 per call with an offset for paging, and its breakdowns, up to 1,000 rows each, as JSON. See the Read API.
  • Disconnect Stripe. Disconnect in site settings deletes the stored key.
  • Delete the key in Stripe. Ask the client to also delete the restricted key in their own Stripe Dashboard.
  • Revoke the client link. Revoke link under Client link in site settings turns the report off at once.
  • Stop the weekly email. Open Client report, click Change schedule and turn off Weekly email.
  • Revoke an API key you shared. A key reads every client site, and keys limited to one site are not available. Revoke it under API keys in account settings and requests with it fail right away.
  • Take the code out of the site. Remove the script tag, and the line that passes the visitor ID into checkout.

Frequently asked questions

How do agencies show clients which channel brought their Stripe revenue?

Add one Virling site per client, install the script on the client's site, connect their Stripe account with a read-only restricted key, and pass the visitor ID into their checkout. Each payment is tied to the channel and campaign of the visit before it, and the client sees it through a report link without a login.

Does each client need its own Stripe connection?

Yes. Each client domain is its own site with its own script tag and its own Stripe key, so every client's revenue stays on their site. Sites with the same client name are grouped under All clients.

Can Virling change anything in a client's Stripe account?

No. Virling only accepts a restricted key with read access and refuses secret keys. It never creates, changes or refunds anything. When the engagement ends, Disconnect deletes the stored key.

What if the client uses Stripe Payment Links?

Payment Links on buy.stripe.com need no code. When a visitor clicks one on a page that runs the script, the script adds the visitor ID as client_reference_id, and Stripe copies it onto the Checkout Session.

Who can see which client?

Team members on your account see and manage every client site, and an API key reads every site too, so keep both for your own staff. A client link opens only that client's site report. Do not invite a client as a team member.

What does the client see when Virling and the ad platform disagree?

The report shows Virling's numbers only, and nothing connects to an ad platform. Virling counts the charges read from Stripe, net of refunds, and credits each to one visit under the site's model and lookback window. An ad platform may count and credit sales by its own rules, so the two can differ. The default is last non-direct with a 90-day window. Keep it the same on every client's site, and note in the report when a client uses something else.

How many months of Stripe payments load at the start?

About three. The first import reads charges from the last 90 days, then new payments every minute. Charges from before the script was on the client's site count as revenue but are Unattributed.
