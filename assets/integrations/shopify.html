integrations / shopify

Shopify sales, joined to the visits behind them.

Virling ties each Shopify order to the visit that came before it, so your store sees which channel, campaign and landing page bring buyers, not just traffic. Open source, one Rust binary, or hosted.

Virling reads Shopify orders and their refunds with the Admin API token of a custom app that can only read orders.

Create a token

  1. In your Shopify admin, open Settings, Apps and sales channels, Develop apps, and create an app. Shopify's guide: custom apps.
  2. Under Admin API integration, give it only the read_orders scope, then install the app.
  3. In Virling, paste the Admin API access token, which starts with shpat_, and your store's https://your-store.myshopify.com address. A custom domain does not work here; the Admin API only answers on the myshopify.com address.

What is imported

  • Orders from the last 60 days on the first run, the most Shopify gives without the extra read_all_orders permission, then new ones every minute. Paid, partially refunded and refunded orders count; voided ones count as failed; pending and authorized orders wait until they are paid.
  • Refunds. Every round also reads the orders updated since the last one, so refunds show up within a minute or two.
  • Renewals. An order from a Shopify Subscriptions renewal (source subscription_contract) is marked as a renewal and keeps the channel of the first payment. See Renewals.
  • Subscription status is not read, so Retention uses payment recency for Shopify customers.

How a payment finds its visitor

Virling reads virling_vid from the order's note attributes. No checkout script is involved; see what still works for tracking under Shopify checkout extensibility. Add this to your theme's theme.liquid, after the Virling script, so the visitor ID is stored on the cart, which Shopify copies onto the order:

<script>
// Shopify: in your theme's theme.liquid, after the Virling script.
// It stores the visitor ID on the cart, and Shopify copies cart
// attributes onto the order as note attributes.
addEventListener("load", function () {
  var vid = window.virling && virling.vid && virling.vid();
  if (vid) fetch("/cart/update.js", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ attributes: { virling_vid: vid } })
  });
});
</script>

How each order type is credited

A customer's first order is credited on its own. Any later order by the same customer keeps the first order's channel when that was credited, whichever way it was placed:

Order typeWhat links it to a visitHow it is credited

Express checkout, such as Shop Pay or Buy it nowvirling_vid in the note attributes, when the button goes through the cart. A button that skips the cart may leave it outWith the ID, like any storefront order. Without it, Unattributed unless the email matches an identify event. How the order was paid is not read
Subscription renewalThe customer ID. An order with the source subscription_contract is marked as a renewalKeeps the channel of the customer's first order. If that order was not credited or is older than the first import, usually Unattributed
Renewal from a subscription app with another sourceThe customer ID onlyAs a later order by the same customer, so it keeps the first channel
Admin (draft) or POS orderNo visitor ID, since it is not made from a storefront cartUnattributed, unless its email matches an identify event or the same customer has an earlier order that was credited

Every order in the table counts toward revenue once it is paid, credited or not. Pending and authorized orders wait, so a draft order sent as an invoice shows after the customer pays. An order with a total of 0 is not imported.

Check it with a test order

  1. Put Shopify Payments in test mode or turn on the Bogus Gateway, and add the theme snippet.
  2. Open a private window and visit your store through a tagged link, such as https://yourstore.com/?utm_source=test&utm_medium=email.
  3. In the same window, add a product to the cart, go to checkout from the cart and place a test order.
  4. In your Shopify admin, open the order and check that its note attributes, shown as additional details, include virling_vid.
  5. Wait a minute or two for the next sync, then open the payments list at /app/yourstore.com/payments. The payment shows the test source and the Email channel of your tagged visit instead of Unattributed.
  6. Cancel and refund the order, since a test order is imported like any other paid order. The refund shows within a minute or two.

Use a new customer email for each test: a later order by the same customer is a renewal and keeps the first order's channel. Then repeat the test with each express button you offer. If a step fails, see Test your setup.

What you can see

Once orders come in, these cards on the dashboard answer questions a seller asks:

  • Which channels bring revenue, not only visits? The Channels card lists visitors, revenue and revenue per visitor for each channel, with Source and Campaign tabs for the site, post or tagged campaign behind it.
  • Which landing pages do buyers arrive on? The Pages card shows revenue by the first page of the visit, and by the last page before paying.
  • Which channel's orders get refunded? The Channels card also shows Refunded, the share of a row's payments that were refunded in whole or part.
  • Who bought most recently, and from where? The Recent customers card shows the last 10 paying customers with amount, first source, visits before paying and time to convert.
  • How long do buyers take to order? The Time to pay card shows the median time from first visit to first payment for each channel with at least three first payments in the range.

What stays Unattributed

These orders still count toward revenue, but no channel is credited, unless they match by email as below or the same customer has an earlier order that was credited:

  • Orders with no virling_vid in their note attributes because the snippet was missing, the script was blocked, or cookieless mode was on.
  • Orders from a cart permalink, a Buy Button embed or another sales channel, since their cart was made outside your storefront.
  • Orders from before the snippet was on your store, which usually includes the 60-day import.
  • Orders with a visitor ID when no visit of that visitor falls inside the lookback window.
  • Most renewals whose first order is Unattributed or older than the first import.

By email: an order with no visitor ID is credited when its email exactly matches one your site sent as an identify event before the order synced, and it shows Matched by email. To find the cause for one order, see Unattributed revenue.

Frequently asked questions

How do I see Shopify sales by traffic source?

Connect your store to Virling with a custom app token that can only read orders, and add a short snippet to theme.liquid that stores the visitor ID on the cart. Shopify copies it onto the order, and Virling ties the order to the visit before it.

Which Shopify scope does Virling need?

Only read_orders. Virling cannot change products, customers or orders.

How far back does Virling import Shopify orders?

60 days on the first run, the most Shopify allows without the read_all_orders permission, then new orders every minute.

Do Shop Pay and Buy it now keep the visitor ID?

Virling does not look at how the order was paid, only at whether its note attributes include virling_vid. The theme snippet writes it to the cart, so a button that skips the cart may leave it out. Place a test order with each button you use and check its note attributes.

Are Shopify refunds taken off the channel?

Yes. A full or partial refund lowers the revenue of its order, on that order's date, so the channel credited with the order loses it too. A voided order counts as failed, and a canceled order that was paid counts until it is refunded. Chargebacks are not read.

What happens to orders made outside my storefront?

Orders from cart permalinks, Buy Button embeds or other sales channels have no virling_vid. They count toward revenue as Unattributed, unless the order's email matches one your site sent as an identify event, or the same customer has an earlier order that was credited, whose channel the later order keeps.

Do Shopify guest orders link to a visit?

Yes. The link comes from the order's note attributes, not from a customer account. An order that Shopify returns without a customer counts as its own customer, so later orders are not tied to it.

How are repeat Shopify orders and renewals credited?

Shopify Subscriptions renewals, and any later order by the same customer, keep the channel of that customer's first order. An order from a subscription app with another source is tied to the first order only through the customer. If the first order is older than the first import, renewals are usually Unattributed.
