Polar Next.js checkout metadata: UTM tracking for each order

By Devendra Variya, co-founder of Virling. Published 2026-11-23, updated 2026-11-25.

To tie each Polar order from a Next.js app to the channel that brought the buyer, load the Virling script in your root layout and carry its visitor ID into checkout. Checkout links on buy.polar.sh need no code: the script adds the ID as reference_id. If you create checkout sessions, read the virling_vid cookie in the route handler that calls polar.checkouts.create and set it in metadata. Virling reads the ID back from the order and joins it to every visit behind it, with the UTM tags of each.

This post covers the App Router. For what you see after setup and the reasoning behind a visitor ID, see the general guide to Polar UTM tracking and the Polar integration page. Using Stripe instead? See Next.js Stripe UTM tracking. On SvelteKit instead? See SvelteKit Polar UTM tracking.

Why Polar checkout loses your UTM tags

UTM tags live on the landing URL. Polar checkout runs on Polar's domain and only stores what you pass into it, so the tags of the visit are gone unless you carry them over. Passing one visitor ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too.

Step 1: add the script to the root layout

Use next/script with strategy="afterInteractive" in app/layout.tsx, so it loads once and runs on every route. If you self-host, replace app.virling.com with your Virling server.

import Script from "next/script";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Script src="https://app.virling.com/v.js"
          data-site="yourdomain.com" strategy="afterInteractive" />
      </body>
    </html>
  );
}

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it.

Step 2a: checkout links, no code

Keep the link to buy.polar.sh as a normal <a href> on a page that runs the script. The script adds reference_id=<visitor ID> to it, unless it is already there, and Polar stores it in the order's metadata, where Virling reads it.

<a href="https://buy.polar.sh/YOUR_CHECKOUT_LINK">Buy now</a>

A virling_vid custom field on the link still works too. The no-code link is explained in full in Polar UTM tracking.

Step 2b: checkout sessions in a route handler

If your server creates the checkout session, the browser sends the virling_vid cookie with the request. Read it where you call polar.checkouts.create and set it in metadata:

// app/api/checkout/route.ts
import { NextRequest, NextResponse } from "next/server";
import { Polar } from "@polar-sh/sdk";

const polar = new Polar({ accessToken: process.env.POLAR_ACCESS_TOKEN });

export async function POST(req: NextRequest) {
  const checkout = await polar.checkouts.create({
    products: ["PRODUCT_ID"],
    success_url: "https://yourdomain.com/thanks",
    metadata: { virling_vid: req.cookies.get("virling_vid")?.value },
  });
  // Send the customer to checkout.url
  return NextResponse.redirect(checkout.url, 303);
}

A plain form posts to it, and the browser sends the cookie along:

<form action="/api/checkout" method="POST">
  <button type="submit">Buy</button>
</form>

Virling reads virling_vid from, in order: the order's metadata, the order's custom field data, then the customer's metadata. The full setup is in the Polar docs and on the Polar for SaaS page.

Step 3: connect Polar

In Polar, create an Organization Access Token with the orders:read and refunds:read scopes, plus subscriptions:read so Retention can tell who still pays, and paste it into Virling. Production and sandbox tokens both work. Virling imports orders from the last 90 days on the first run, then new orders every minute. There is no webhook to add to your Next.js app.

Check that it works

  1. Connect a token from the Polar sandbox to Virling.
  2. For the route handler in step 2b, use a sandbox token with checkouts:write in POLAR_ACCESS_TOKEN, a sandbox product ID and server: "sandbox" in new Polar(). It is a different token from the one you give Virling.
  3. Open a private window and visit a page that runs the script through a tagged link, such as https://yourdomain.com/?utm_source=test&utm_medium=email.
  4. In the same window, press Buy on the form that posts to your route handler and pay with a test card.
  5. Wait a minute for the next sync, then open the payments list at /app/yourdomain.com/payments. The payment shows the test source and the Email channel of your tagged visit instead of Unattributed. Open it to see its journey.

Use a new email address for each test, because a later payment by the same customer is a renewal and keeps the first payment's channel. If a step fails, see test your setup.

What the sandbox does not do: the script adds reference_id only to links on buy.polar.sh, so it does not tag sandbox links and step 2a cannot be tested there. To test it, connect your production token, make one small live payment through the link and refund it. A site has one Polar connection, and sandbox orders stay in your reports after you replace the token with a production one.

Why an order stays Unattributed

Open the payment from /app/yourdomain.com/payments and look for Visitor under Details, the visitor ID that came with checkout. If there is none, checkout carried no ID. Then go down this list in order:

  1. It is a renewal. Renewals keep the channel of the customer's first order. Check that order: if it is Unattributed, or older than the first import, its renewals usually are too.
  2. It was a sandbox link. The script does not tag those. Test with the route handler.
  3. The session had no metadata. The route handler did not set metadata.virling_vid, or the request came from another domain, so the cookie was not sent. A session created before the buyer arrives has no cookie to read.
  4. The link skipped your site. A checkout link opened from an email, a QR code or another site carries no visitor ID.
  5. The link was not a normal link. The script only tags an <a href> to buy.polar.sh on a page that runs it, not a URL opened in code.
  6. The link already had a reference_id. The script keeps the one you set, so it cannot add the visitor ID there. Take it off the link, or use a session with metadata.
  7. The visitor had no cookie. In cookieless mode, or before a visitor accepts under Until consent, there is no visitor ID to pass. The same goes for a page where the script is missing or blocked.
  8. It has a visitor, but no visit in the window. That visitor's sessions all started before the lookback window, or after the payment. Choose a longer window if your buyers take longer, and check that the script runs on every page where visitors arrive.
  9. It is older than the script. Orders from before the script was on your site count as revenue but are Unattributed.

Every other cause is in Unattributed revenue. An order made before a fix usually stays Unattributed, so place a new one to check it.

Orders without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to order is in how to track Polar revenue by traffic source.

Frequently asked questions

How do I pass UTM parameters to a Polar checkout in Next.js?

Pass the Virling visitor ID instead. In the route handler that calls polar.checkouts.create, read the virling_vid cookie and set metadata: { virling_vid }. The Virling script records the UTM tags of every visit against that ID, so the order is joined to all of them.

Do Polar checkout links in a Next.js app need code?

No. Keep the link to buy.polar.sh as a normal <a href> on a page that runs the script. The script adds reference_id=<visitor ID> to it, unless it is already there, and Polar stores it in the order's metadata, where Virling reads it.

Where does Virling read the visitor ID on a Polar order?

From virling_vid in, in order: the order's metadata, the order's custom field data, then the customer's metadata.

What happens if the cookie is missing?

The checkout is created without a visitor ID, for example when the script is blocked. The order still counts toward revenue, as Unattributed.

Do I need a Polar webhook in my Next.js app?

No. Virling reads orders from the Polar API with an organization access token and checks for new orders every minute.
