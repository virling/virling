Angular Stripe UTM tracking: pass UTMs to Stripe Checkout

By Devendra Variya, co-founder of Virling. Published 2026-11-24.

Angular Stripe UTM tracking takes one value. Add the Virling script to src/index.html, read the visitor ID in a service with window.virling?.vid?.(), post it to the Node endpoint that creates the Stripe Checkout Session, and set it as metadata.virling_vid. Stripe keeps that one ID on the session, and Virling joins the payment to every visit behind it, with the UTM tags of each, so you see which channel brought the buyer.

The code follows the Angular 22 and Stripe documentation linked in each step. For the same flow in React, see React Stripe UTM tracking. For Payment Links and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Why Angular apps lose UTM tags before checkout

A visitor lands on /?utm_source=newsletter&utm_campaign=launch, then clicks a routerLink to /pricing. By default the router replaces the current query parameters with those of the new link (QueryParamsHandling), so the tags are gone from the URL by the time the visitor clicks Buy. Stripe Checkout then runs on Stripe's domain and only stores what your server passes when it creates the session.

Setting queryParamsHandling="preserve" on every link keeps the tags only for that one visit. The Virling script records them with the landing pageview instead. It hooks into history.pushState, history.replaceState and the back button, so route changes are counted as pageviews and stay in the same session and channel as the landing. Checkout only needs the visitor ID. If the tags never reach your landing page at all, see UTM parameters lost after redirect.

Step 1: add the script to src/index.html

Paste the tag before </head> in src/index.html, the main HTML page of the app (Angular file structure). If you self-host, replace app.virling.com with your Virling server.

<!-- src/index.html -->
<script defer src="https://app.virling.com/v.js"
  data-site="yourdomain.com"></script>

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it. Load it once, here: Angular does not support <script> in component templates (Angular templates).

Step 2: read the visitor ID in a service

The script loads with defer, so checkout code can run before it; wait for it briefly. window.virling?.vid?.() returns null in cookieless mode and nothing when the script is blocked, so the service sends null in both cases:

// src/app/checkout.ts
import { HttpClient } from "@angular/common/http";
import { Injectable, inject } from "@angular/core";
import { from, switchMap } from "rxjs";

declare global {
  interface Window {
    virling?: { vid?: () => string | null };
  }
}

@Injectable({ providedIn: "root" })
export class Checkout {
  private http = inject(HttpClient);

  start() {
    return from(this.visitorId()).pipe(
      switchMap((vid) => this.http.post<{ url: string }>("/api/checkout", { vid })),
    );
  }

  private async visitorId() {
    for (let i = 0; i < 20 && !window.virling?.vid; i++) {
      await new Promise((r) => setTimeout(r, 100));
    }
    return window.virling?.vid?.() || null;
  }
}

In Angular 21 and later HttpClient can be injected by default. In earlier versions, add provideHttpClient() to the providers in app.config.ts (HttpClient setup). The newer @Service() decorator is a shorthand for @Injectable({ providedIn: "root" }) (Angular services); use either.

Call the service from the button. The request is sent only when you subscribe (HttpClient requests):

// src/app/buy-button.ts
import { Component, inject, signal } from "@angular/core";
import { Checkout } from "./checkout";

@Component({
  selector: "app-buy-button",
  template: `<button type="button" [disabled]="busy()" (click)="buy()">Buy</button>`,
})
export class BuyButton {
  private checkout = inject(Checkout);
  protected readonly busy = signal(false);

  protected buy() {
    this.busy.set(true);
    this.checkout.start().subscribe({
      next: ({ url }) => {
        window.location.href = url;
      },
      error: () => this.busy.set(false),
    });
  }
}

The ID is read on click, so this also works with server-side rendering, where window does not exist during the render.

Step 3: create the Checkout Session in Node with metadata

The endpoint holds the Stripe secret key. Install it with npm install express stripe, outside the Angular bundle. It sets the visitor ID as metadata.virling_vid and returns the session URL (Stripe API reference):

// server.mjs
import express from "express";
import Stripe from "stripe";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);
const appUrl = process.env.APP_URL || "http://localhost:4200";
const app = express();
app.use(express.json());

app.post("/api/checkout", async (req, res) => {
  const vid = String(req.body.vid ?? "");
  const session = await stripe.checkout.sessions.create({
    mode: "subscription",
    line_items: [{ price: process.env.STRIPE_PRICE_ID, quantity: 1 }],
    success_url: `${appUrl}/thanks`,
    metadata: /^[A-Za-z0-9-]{8,64}$/.test(vid) ? { virling_vid: vid } : {},
  });
  res.json({ url: session.url });
});

app.listen(3000);

The price stays on the server, so the browser cannot choose its own. For a one-time payment, use a one-time price and set mode to payment. The regular expression drops anything that does not look like a visitor ID, and a missing ID leaves the metadata empty.

Stripe allows 50 metadata keys per object, with up to 40 characters in a key and 500 in a value (Stripe metadata). The key must be exactly virling_vid. Passing the ID as client_reference_id, which holds up to 200 characters, works too; use metadata when that field has your own user or order ID. If you create your own PaymentIntent for Elements, set the same metadata on it.

The full lookup order is in the Stripe docs, and the Stripe integration page shows what Virling imports. The checkout snippet generator writes the server call for other providers.

Test it locally

Send /api requests from ng serve to the Node endpoint with a proxy file (Angular CLI serve):

{
  "/api/**": {
    "target": "http://localhost:3000",
    "secure": false
  }
}

Save it as src/proxy.conf.json, point the serve target in angular.json at it, and restart ng serve:

"serve": {
  "builder": "@angular/build:dev-server",
  "options": {
    "proxyConfig": "src/proxy.conf.json"
  }
}
  1. Add data-dev to the script tag while you test. Without it the script does nothing on localhost, so there is no visitor ID. Put a separate test site of yours in data-site to keep these visits out of your real reports.
  2. Connect a restricted Stripe key that starts with rk_test_ to that test site in Virling, and start the endpoint with your test secret key and a test price: STRIPE_SECRET_KEY=sk_test_... STRIPE_PRICE_ID=price_... node server.mjs.
  3. In a private window, open http://localhost:4200/?utm_source=test&utm_medium=test, go to another route and click Buy.
  4. Pay with the card 4242 4242 4242 4242, any future date and any three-digit CVC (Stripe testing).
  5. Wait a minute for the next sync and open the site's payments list in Virling. The payment should show the test source instead of Unattributed. Open it to see its journey.

Virling reads payments from Stripe, so this needs no webhook on your machine. Before you deploy, remove data-dev, set data-site back to your domain, set APP_URL, and serve /api/checkout from the same domain as the app: the CLI proxy only exists in ng serve. If the API is on another domain, allow the app's origin with CORS. The full checklist is in test your setup.

Usual mistakes

  • The script is in the scripts array of angular.json. It reads data-site from its own tag, so bundled it sends nothing. Keep the plain tag in src/index.html.
  • The ID is read once at startup. The script may not have loaded yet. Read it on click and wait for it, as in the service above.
  • Nothing subscribes to the request. http.post() alone sends nothing.
  • The app uses hash URLs. With HashLocationStrategy the path never changes, so only the first page is counted. The default path URLs are tracked (Angular routing tasks).
  • The ID is only in subscription_data.metadata. That goes to the subscription, which Virling does not read. Set metadata on the session itself.
  • The secret key is in an Angular environment file. Those values are compiled into the public bundle. Keep the key in the environment of the Node process.

If a payment still shows Unattributed, check in the browser console that window.virling.vid() returns an ID, that the request to /api/checkout carries it, and that the session in Stripe has virling_vid in its metadata. How the join works from visit to payment is in how to track Stripe revenue by traffic source. With Express or NestJS behind Angular, see Express Stripe UTM tracking and NestJS Stripe UTM tracking.

Frequently asked questions

How do I pass UTM parameters to Stripe Checkout from an Angular app?

Read the visitor ID in a service with window.virling?.vid?.(), post it to the endpoint that creates the Checkout Session, and set it as metadata.virling_vid. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

Why are my UTM parameters gone after the first route change?

Angular's router replaces the query parameters on navigation unless you set queryParamsHandling to preserve or merge. The Virling script records the tags from the landing pageview, so checkout only needs the visitor ID and you do not have to keep the tags in the URL.

Can I create the Checkout Session in Angular, without a backend?

No. Creating a session needs your Stripe secret key, and everything in an Angular bundle is public. Use a small endpoint or serverless function. If you do not want a backend, link to a Stripe Payment Link instead.

Should I use client_reference_id or metadata.virling_vid?

Either works. Virling reads metadata.virling_vid on the session first, then client_reference_id. Metadata leaves client_reference_id free for your own user or order ID.

Can I put the visitor ID in subscription_data.metadata?

Not for Virling. It reads the charge, its PaymentIntent and the Checkout Session, not the metadata of the subscription. Set metadata.virling_vid on the session itself.

What happens if the visitor ID is missing?

The session is created without it, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.
