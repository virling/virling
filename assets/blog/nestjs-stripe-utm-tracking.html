NestJS Stripe UTM tracking: Checkout metadata from a controller

By Devendra Variya, co-founder of Virling. Published 2026-11-22.

NestJS Stripe UTM tracking comes down to one value. Load the Virling script on your pages, then read the virling_vid cookie with req.cookies.virling_vid in the NestJS controller that creates the Stripe Checkout Session and pass it as client_reference_id, or as metadata.virling_vid if that field is taken. Stripe keeps that one ID, and Virling joins the payment to every visit behind it, with the UTM source and other tags of each, so each payment shows the channel that brought it.

This post covers NestJS on its default Express platform with the stripe Node library. The same steps for plain Express are in Express Stripe UTM tracking, and for the App Router in Next.js Stripe UTM tracking. For Payment Links, metadata limits and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Why Stripe Checkout loses your UTM tags

UTM tags live on the landing URL. Stripe Checkout runs on Stripe's domain and only stores what your server passes when it creates the session, so the tags of the visit are gone unless you carry them over. Passing one visitor ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too.

Step 1: add the script to your pages

Paste the tag before </head> in the layout or static HTML every page uses, whether NestJS renders it or a separate frontend serves it. If you self-host, replace app.virling.com with your Virling server.

<script defer src="https://app.virling.com/v.js"
  data-site="yourdomain.com"></script>

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it.

Step 2: parse cookies in main.ts

Your server receives the cookie with every request from the browser, but NestJS does not parse cookies by itself. Install cookie-parser and @types/cookie-parser, then register it before the app listens:

// src/main.ts
import { NestFactory } from "@nestjs/core";
import * as cookieParser from "cookie-parser";
import { AppModule } from "./app.module";

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.use(cookieParser());
  await app.listen(3000);
}
bootstrap();

Step 3: a checkout service and controller

Keep the stripe client in a service, and let the controller read the cookie and hand it over. The service passes it as client_reference_id:

// src/checkout/checkout.service.ts
import { Injectable } from "@nestjs/common";
import Stripe from "stripe";

@Injectable()
export class CheckoutService {
  private readonly stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

  async createSession(vid?: string): Promise<string> {
    const session = await this.stripe.checkout.sessions.create({
      client_reference_id: vid,
      line_items: [{ price: "price_...", quantity: 1 }],
      mode: "subscription",
      success_url: "https://yourdomain.com/thanks",
    });
    return session.url!;
  }
}
// src/checkout/checkout.controller.ts
import { Controller, Post, Redirect, Req } from "@nestjs/common";
import { Request } from "express";
import { CheckoutService } from "./checkout.service";

@Controller("checkout")
export class CheckoutController {
  constructor(private readonly checkout: CheckoutService) {}

  @Post()
  @Redirect()
  async create(@Req() req: Request) {
    const url = await this.checkout.createSession(req.cookies?.virling_vid);
    return { url, statusCode: 303 };
  }
}

Add both to a module's controllers and providers. When the cookie is missing, the value is undefined and the stripe library leaves the field out. A plain form posts to the route, and the browser sends the cookie along:

<form action="/checkout" method="POST">
  <button type="submit">Subscribe</button>
</form>

When client_reference_id is taken

If you already use client_reference_id for your own user or order ID, put the visitor ID in the session's metadata instead. Virling reads either:

  async createSession(userId: string, vid?: string): Promise<string> {
    const session = await this.stripe.checkout.sessions.create({
      client_reference_id: userId,
      metadata: vid ? { virling_vid: vid } : {},
      line_items: [{ price: "price_...", quantity: 1 }],
      mode: "subscription",
      success_url: "https://yourdomain.com/thanks",
    });
    return session.url!;
  }

If you create your own PaymentIntent for Elements instead of a Checkout Session, set the same metadata on stripe.paymentIntents.create(). The full lookup order is in the Stripe docs, and the Stripe SaaS page shows what you get for subscriptions, trials and renewals.

When the API is on another domain

The browser only sends the cookie to your own domain and its subdomains. If your frontend calls a NestJS API on another domain, read the ID in the browser with window.virling?.vid?.() and send it in the request body. The script loads with defer, so wait for it:

async function visitorId() {
  for (let i = 0; i < 20 && !window.virling?.vid; i++) {
    await new Promise((r) => setTimeout(r, 100));
  }
  return window.virling?.vid?.() || null;
}

async function checkout() {
  const res = await fetch("https://api.example.com/checkout", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ vid: await visitorId() }),
  });
  location.href = (await res.json()).url;
}

On the server, call app.enableCors() for the frontend origin, take the ID with @Body("vid") vid?: string, pass vid || undefined to the service, and return { url } instead of redirecting. The ID is null in cookieless mode, and the payment then counts as Unattributed.

Subscriptions and renewals

Only the first payment needs the visitor ID. A renewal takes the attribution of the customer's first payment, so each monthly or yearly charge of the subscription is credited to the same visit, with no code on your side.

Check that it works

Make a test payment from a page that runs the script, wait for the next sync, and open the payments list at /app/yourdomain.com/payments. The payment should show a channel instead of Unattributed. If it still shows Unattributed, check that the page you bought from loads the script, that app.use(cookieParser()) runs in main.ts, and that the checkout request goes to the same domain or one of its subdomains, so the cookie is sent.

Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Stripe revenue by traffic source.

Frequently asked questions

How do I pass UTM parameters to Stripe Checkout in NestJS?

Read the visitor ID from the virling_vid cookie in the controller that creates the Checkout Session and pass it as client_reference_id. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

Why is req.cookies undefined in NestJS?

NestJS does not parse cookies by itself. Install cookie-parser and call app.use(cookieParser()) in main.ts before app.listen, then read req.cookies.virling_vid in the controller.

Should I use client_reference_id or metadata.virling_vid?

Use client_reference_id unless it already holds your own user or order ID. In that case put the visitor ID in the session's metadata.virling_vid. Virling reads either.

Are subscription renewals attributed?

Yes. A renewal takes the attribution of the customer's first payment, so every monthly or yearly charge is credited to the visit that led to the first one, even though the renewal itself has no visit.

What happens if the cookie is missing?

The session is created without a visitor ID, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.
