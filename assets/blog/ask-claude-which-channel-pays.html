Ask Claude which marketing channel pays: the setup

By Devendra Variya, co-founder of Virling. Published 2026-10-22, updated 2026-11-28.

Most founders ask their analytics "where did my visitors come from?"

The better question is "where did my paying customers come from?" And now you can ask it in plain English, inside Claude or any assistant that speaks MCP.

Here is the exact setup, step by step. It takes about 15 minutes.

What you need

  1. Your analytics has to know which visit came before each payment. Visitor counts alone can't answer "which channel pays". Revenue analytics tools compared by the question they answer shows which kinds can.
  2. That data has to be reachable by your AI assistant. That is what MCP (Model Context Protocol) is for: a small, standard door your assistant can knock on to read data.

Step 1: give every visitor an ID

Your tracking script sets one first-party ID per visitor and remembers the first source: referrer, UTM tags or "direct".

Step 2: pass that ID into checkout

When someone clicks Buy, put the visitor ID in the checkout's metadata. On Stripe that's metadata, on Dodo Payments and Polar it's the same idea. One line where you create the checkout. The Stripe steps are in tracking Stripe revenue by traffic source.

Step 3: join payments to visits

When the payment webhook arrives, look up the visitor ID and credit the payment to the channel of the visit before it. Now every dollar has a source.

Step 4: expose it over MCP

This is where it gets fun. I built this into Virling, an open-source revenue analytics tool written in Rust. It serves an MCP endpoint at /mcp with read-only tools:

  • get_overview: visitors, revenue, conversion, revenue per visitor, vs the previous period
  • get_breakdown: revenue per channel, referrer, campaign, landing page, country, device
  • get_retention: which channel's customers keep paying
  • list_payments and get_visitor_timeline: the full path of any payment

Add it to Claude Code with one command:

claude mcp add --transport http virling https://your-server/mcp \
  --header "Authorization: Bearer vk_..."

On claude.ai you add the same URL and sign in with Virling. Setup details are in the MCP docs.

Connect the Virling MCP server

With Virling you do not build steps 3 and 4. The script sets the visitor ID, checkout carries it, Virling joins each payment to the visits before it, and the MCP server is already running. Once payments show a channel, connecting an assistant takes about five minutes.

  1. Get the URL. On hosted Virling it is https://mcp.virling.com/mcp. On your own server it is /mcp on your public address, such as https://stats.example.com/mcp, with the app on (--app).
  2. Choose how to sign in. With OAuth, the assistant opens Virling and you click Allow; only the account owner can connect an app, and your own server needs a public https:// address at the root of its host. With an API key, create one in Account settings > API keys and send it as Authorization: Bearer vk_.... Both read every site of your account and cannot change anything.
  3. Add it to your assistant, as below.
  4. Check it. Ask "Which sites can you read?" The assistant should answer with your domains.

claude.ai

For hosted Virling, open the Claude directory listing, click Connect, and click Allow when Virling opens. For your own server, open Customize > Connectors, click Add custom connector, enter a name and your URL, leave the advanced settings empty, click Add, then Connect. On Team and Enterprise plans an Owner adds it under Organization settings > Connectors. Then turn the connector on in a chat from the + menu.

Claude Code

On an https server, add the URL, then run /mcp in a session to sign in. No key is needed:

claude mcp add --transport http virling https://mcp.virling.com/mcp

The command in step 4 sends an API key instead, which also works on a local http server.

Claude Code plugin

On hosted Virling the fastest path is the Virling plugin, which bundles the MCP server and an agent skill. Install it with two commands:

claude plugin marketplace add virling/virling
claude plugin install virling@virling

Then run /mcp in a session, choose virling and sign in. No key is needed. The steps are in the plugin docs.

The skill tells Claude which tool answers which question and how to read the results: money is USD net of refunds, changes are against the previous period of the same length, and payments with no credited visit sit in their own Unattributed row. It also carries a weekly channel review. With it installed you can ask:

  • "Which channel made the most money last month?"
  • "Which channel is worth more per visitor, and which only brings visitors?"
  • "Which channel brings customers who keep paying?"

The plugin points at hosted Virling. If you self-host, skip it and add your own server's /mcp URL with the command above. OAuth sign-in needs https; on http, use an API key.

ChatGPT and other clients

In ChatGPT, with developer mode on, create a custom app with the URL and OAuth authentication, then click Allow when Virling opens. Any other client that speaks the Streamable HTTP transport and can send a header works with an API key. The AI assistants guide has every step.

No traffic yet? Open a new site and choose Try with sample data: every tool then returns generated results until you click Remove sample data.

Step 5: ask questions

Things I ask now instead of clicking through dashboards:

  • "Which channel made the most money per visitor in the last 30 days?"
  • "Is AI traffic worth more than search traffic for me?"
  • "Show me the path of the last 5 customers who paid."
  • "Which channel's customers churn the fastest?"

On the demo site, the answer to the first one: Direct brought twice the visitors of AI, but AI visitors were worth almost 7x more each. You would never guess that from a traffic chart. For more to paste in, there is a list of questions to copy for SaaS founders, store owners and agencies. More on that in is AI search traffic worth anything.

Eight questions and what each answer uses

Name a range and, when your account has more than one site, the site. The tools take today, the last 7, 30 or 90 days, the last 12 months, all time, or two dates.

QuestionToolWhat the answer uses
Which channel made the most money per visitor in the last 30 days?get_breakdownVisitors, credited revenue and revenue per visitor for each channel
Which channel earned the most in the last 30 days, and what changed from the 30 days before?get_channel_verdictsOne plain line per channel against the period of the same length before
How did visitors, revenue and conversion in the last 7 days compare with the 7 days before?get_overviewSite totals for both periods and the change between them
Which landing pages got visitors but no revenue in the last 30 days?get_breakdownVisitors and credited revenue for each landing page
Which channel's customers have the highest 30-day churn?get_retentionCustomers who first paid 30 to 60 days ago, grouped by the channel of that first payment, and how many have no payment in the last 30 days and no live subscription
Show me the path of the last 5 customers who paid, from first visit to payment.list_payments, get_visitor_timelineThe newest payments, then the visits, pages and goals of the visitor behind each one
How many payments in the last 30 days are not matched to a visit?list_paymentsThe count of payments with no credited visit
Which AI assistants sent visitors who paid, and which of our pages did they cite?get_ai_answersVisitors and revenue credited to each assistant, and the pages its answers to your buyer questions cited

Payments with no credited visit stay in their own Unattributed row, so ask the seventh question before you trust a ranking: if many payments are unmatched, the order of channels can change once they are fixed. The tools return visitors, payments and revenue, not ad spend, so ROAS and cost per click are not answers they can give.

Why this matters

Traffic tells you which channel is loud. Revenue per visitor tells you which one pays. Once your assistant can see both, you stop arguing about channels and just ask.

Which channel brings you the most paying customers right now? Curious if anyone else is seeing AI traffic convert better than search.

Asking Claude about your numbers is separate from measuring the visitors it sends you. For that, see how Claude visits are counted and which ChatGPT visits pay.

Frequently asked questions

Can Claude tell me which marketing channel makes money?

Yes, if your analytics links payments to visits and exposes that data over MCP. Claude can then answer questions like which channel made the most revenue per visitor in the last 30 days.

What is an MCP server for analytics?

MCP (Model Context Protocol) is a standard way for AI assistants to read data from other tools. An analytics MCP server gives the assistant tools such as an overview, revenue by channel and the path behind each payment.

Can the assistant change my analytics data?

Not with Virling. Its MCP tools are read-only, and each connection uses an OAuth sign-in or an API key, and you can revoke either.

How do I connect Claude to Virling?

On claude.ai, open the Virling listing in the Claude directory, click Connect, and click Allow when Virling opens. For a self-hosted server, add a custom connector with your server's /mcp URL instead. In Claude Code, add the URL with claude mcp add and run /mcp to sign in.

Is there a Claude Code plugin for Virling?

Yes. Run claude plugin marketplace add virling/virling, then claude plugin install virling@virling, then run /mcp in a session and sign in. It bundles the read-only MCP server for hosted Virling and a skill that tells Claude which tool answers which question. Self-hosters add their own server's /mcp URL instead.

Can the assistant see who my customers are?

No. The tools return visitor IDs and generated names, with no names, emails or IP addresses. They do not return raw events or bulk exports either: payments come at most 200 per call and breakdowns at most 1,000 rows.
