Laravel Stripe UTM tracking: Checkout and Cashier

By Devendra Variya, co-founder of Virling. Published 2026-11-19.

Laravel Stripe UTM tracking comes down to one value. Load the Virling script in your Blade layout, leave the virling_vid cookie out of Laravel's cookie encryption, then read it with $request->cookie('virling_vid') in the controller that creates the Stripe Checkout Session and pass it as client_reference_id, or as metadata.virling_vid in Laravel Cashier's checkout options. Stripe keeps that one ID, and Virling joins the payment to every visit behind it, with the UTM tags of each.

This post covers Laravel with stripe-php and with Cashier. The same steps for other stacks are in Rails Stripe UTM tracking and Next.js Stripe UTM tracking. On another provider, see Paddle UTM tracking in Laravel and LemonSqueezy UTM tracking in Laravel. For Payment Links, metadata limits and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Why Stripe Checkout loses your UTM tags

UTM tags live on the landing URL. Stripe Checkout runs on Stripe's domain and only stores what your server passes when it creates the session, so the tags of the visit are gone unless you carry them over. The same thing happens on any redirect that drops the query string, as covered in UTM parameters lost after redirect. Passing one visitor ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too.

Step 1: add the script to the Blade layout

Paste the tag before </head> in the layout every page extends, usually resources/views/layouts/app.blade.php. If you self-host, replace app.virling.com with your Virling server.

<!-- resources/views/layouts/app.blade.php -->
<script defer src="https://app.virling.com/v.js"
  data-site="yourdomain.com"></script>

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it.

Step 2: leave the cookie out of encryption

Laravel encrypts cookies by default, and $request->cookie() returns nothing for a cookie it did not set itself. The script sets virling_vid in the browser, so exclude it. In Laravel 11 and later, in bootstrap/app.php:

->withMiddleware(function (Middleware $middleware) {
    $middleware->encryptCookies(except: ['virling_vid']);
})

In older versions, add it to $except in app/Http/Middleware/EncryptCookies.php:

protected $except = [
    'virling_vid',
];

Step 3: create the Checkout Session in a controller

Your server receives the cookie with every request from the browser. With stripe-php, read it where you create the session and pass it as client_reference_id:

// app/Http/Controllers/CheckoutController.php
namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Stripe\StripeClient;

class CheckoutController extends Controller
{
    public function store(Request $request)
    {
        $params = [
            'line_items' => [['price' => 'price_...', 'quantity' => 1]],
            'mode' => 'subscription',
            'success_url' => 'https://yourdomain.com/thanks',
        ];
        if ($vid = $request->cookie('virling_vid')) {
            $params['client_reference_id'] = $vid;
        }

        $stripe = new StripeClient(config('services.stripe.secret'));
        $session = $stripe->checkout->sessions->create($params);

        return redirect()->away($session->url, 303);
    }
}

Register it with Route::post('/checkout', [CheckoutController::class, 'store'])->name('checkout'); and post to it from a Blade form. The browser sends the cookie along:

<form action="{{ route('checkout') }}" method="POST">
    @csrf
    <button type="submit">Subscribe</button>
</form>

With Laravel Cashier

Cashier's checkout() takes an array of Checkout Session options and sends them to Stripe when it creates the session. Add the visitor ID there. This example uses metadata.virling_vid, so client_reference_id stays free for your own ID; Virling reads either:

use Illuminate\Http\Request;

Route::get('/subscribe', function (Request $request) {
    $options = [
        'success_url' => 'https://yourdomain.com/thanks',
        'cancel_url' => 'https://yourdomain.com/pricing',
    ];
    if ($vid = $request->cookie('virling_vid')) {
        $options['metadata'] = ['virling_vid' => $vid];
    }

    return $request->user()
        ->newSubscription('default', 'price_...')
        ->checkout($options);
})->middleware('auth');

For a single charge, $request->user()->checkout(['price_...' => 1], $options) takes the same options as its second argument. The full lookup order, including PaymentIntents you create for Elements, is in the Stripe docs, and the Stripe integration page shows what Virling imports.

Subscriptions and renewals

Only the first payment needs the visitor ID. A renewal takes the attribution of the customer's first payment, so each monthly or yearly charge Cashier's subscription creates is credited to the same visit, with no code on your side. Plan changes count as renewals too.

Check that it works

Make a test payment from a page that runs the script, wait for the next sync, and open the payments list at /app/yourdomain.com/payments. The payment should show a channel instead of Unattributed. Open it to see its journey. If it still shows Unattributed, check that the cookie is in the encryption exceptions, that the page you bought from loads the script, and that the checkout request goes to the same domain, so the cookie is sent.

Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Stripe revenue by traffic source, and the SaaS page shows what you get per channel.

Frequently asked questions

How do I pass UTM parameters to Stripe Checkout in Laravel?

Read the visitor ID with $request->cookie('virling_vid') in the controller that creates the Checkout Session and pass it as client_reference_id. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

Why does $request->cookie('virling_vid') return null?

Laravel encrypts cookies by default and returns nothing for a cookie it did not set. Leave virling_vid out of encryption: in Laravel 11 and later with $middleware->encryptCookies(except: ['virling_vid']) in bootstrap/app.php, in older versions by adding it to $except in app/Http/Middleware/EncryptCookies.php.

How do I add the visitor ID with Laravel Cashier?

Pass it in the session options of checkout(), for example newSubscription('default', 'price_...')->checkout(['metadata' => ['virling_vid' => $vid]]). Cashier sends those options to Stripe when it creates the Checkout Session. client_reference_id works there too.

Should I use client_reference_id or metadata.virling_vid?

Use client_reference_id unless it already holds your own user or order ID. In that case put the visitor ID in the session's metadata.virling_vid. Virling reads either.

Are subscription renewals attributed?

Yes. A renewal takes the attribution of the customer's first payment, so every monthly or yearly charge is credited to the visit that led to the first one, even though the renewal itself has no visit.

What happens if the cookie is missing?

The session is created without a visitor ID, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.
