Remix Stripe UTM tracking: tie each payment to its source

By Devendra Variya, co-founder of Virling. Published 2026-11-22.

To see which traffic source each Stripe payment came from in a Remix or React Router app, add the Virling script to the <head> in app/root.tsx, then read the virling_vid cookie from the request in the route action that creates the Checkout Session and pass it as client_reference_id. Stripe keeps that one ID, and Virling joins the payment to every visit behind it, with the UTM tags of each. Two files change, and the rest of your checkout stays as it is.

The same code works in Remix v2 and in React Router v7 framework mode; only the import paths differ. For Payment Links, metadata limits and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Why Stripe Checkout loses your UTM tags

UTM tags live on the landing URL. Stripe Checkout runs on Stripe's domain and only stores what your server passes when it creates the session, so the tags of the visit are gone unless you carry them over. Passing one visitor ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too. If the tags never reach your landing page at all, a redirect is usually dropping them; see UTM parameters lost after redirect.

Step 1: add the script to the root route

Put the tag in the <head> in app/root.tsx, next to <Meta /> and <Links />. It is rendered into the HTML of every page, and client-side navigation is counted on its own, so load it once here. If you self-host, replace app.virling.com with your Virling server.

// app/root.tsx
<head>
  <Meta />
  <Links />
  <script defer src="https://app.virling.com/v.js"
    data-site="yourdomain.com"></script>
</head>

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it.

Step 2: create the Checkout Session in a Remix action

Your server receives the virling_vid cookie with every request from the browser. There is no cookie helper for a plain cookie, so read it from the request's Cookie header in the action that creates the session and pass it as client_reference_id:

// app/routes/pricing.tsx
import { redirect, type ActionFunctionArgs } from "@remix-run/node";
import { Form } from "@remix-run/react";
import Stripe from "stripe";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function action({ request }: ActionFunctionArgs) {
  const vid = request.headers.get("Cookie")
    ?.match(/(?:^|;\s*)virling_vid=([^;]+)/)?.[1];
  const session = await stripe.checkout.sessions.create({
    client_reference_id: vid,
    line_items: [{ price: "price_...", quantity: 1 }],
    mode: "subscription",
    success_url: "https://yourdomain.com/thanks",
  });
  return redirect(session.url!, 303);
}

export default function Pricing() {
  return (
    <Form method="post">
      <button type="submit">Buy</button>
    </Form>
  );
}

The form posts to the route's own action, and the browser sends the cookie along. The redirect to Stripe's URL works from a <Form> too: an absolute URL makes the router load the page in full.

In React Router v7, with metadata

In React Router v7 framework mode the action is the same, with types from ./+types and imports from react-router. If client_reference_id already holds your own user or cart ID, put the visitor ID in the session's metadata.virling_vid instead. Virling reads either:

// app/routes/pricing.tsx
import { Form, redirect } from "react-router";
import Stripe from "stripe";
import type { Route } from "./+types/pricing";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function action({ request }: Route.ActionArgs) {
  const vid = request.headers.get("Cookie")
    ?.match(/(?:^|;\s*)virling_vid=([^;]+)/)?.[1];
  const session = await stripe.checkout.sessions.create({
    // client_reference_id stays free for your own ID
    metadata: vid ? { virling_vid: vid } : {},
    line_items: [{ price: "price_...", quantity: 1 }],
    mode: "subscription",
    success_url: "https://yourdomain.com/thanks",
  });
  return redirect(session.url!, 303);
}

export default function Pricing() {
  return (
    <Form method="post">
      <button type="submit">Buy</button>
    </Form>
  );
}

The full lookup order, including PaymentIntents you create for Elements, is in the Stripe docs and on the Stripe integration page. The checkout snippet generator writes the same call for other providers.

Check that it works

Make a test payment from a page that runs the script, wait for the next sync, and open the payments list at /app/yourdomain.com/payments. The payment should show a channel instead of Unattributed. Open it to see its journey. If it still shows Unattributed, check that the page you bought from loads the script and that the form posts to your own domain, so the cookie is sent.

Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Stripe revenue by traffic source, and the Stripe for SaaS page shows what you get per channel. On other frameworks, see Next.js and Express.

Frequently asked questions

How do I pass UTM parameters to a Stripe Checkout Session in Remix?

Read the visitor ID from the virling_vid cookie in the route action that creates the session, and pass it as client_reference_id. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

How do I read the virling_vid cookie in a Remix or React Router action?

Read it from the request's Cookie header with request.headers.get("Cookie") and take the virling_vid value. It is a first-party cookie on your domain, so the browser sends it with every request to your app, including form posts to an action.

Should I use client_reference_id or metadata.virling_vid?

Use client_reference_id unless it already holds your own user or cart ID. In that case put the visitor ID in the session's metadata.virling_vid. Virling reads either.

What happens if the cookie is missing?

The session is created without a visitor ID, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.

Do Stripe Payment Links in a Remix app need code?

No. Use a normal link to buy.stripe.com on a page that runs the script. The script adds client_reference_id to the link when the page loads and again on click, unless the link already has one.

What if my React Router app runs without a server?

Without a server there is no action to read the cookie. Read the visitor ID in the browser with window.virling?.vid?.(), check that it is set, and send it to the backend that creates the Checkout Session.
