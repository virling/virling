FastAPI Stripe UTM tracking: Checkout in Python

By Devendra Variya, co-founder of Virling. Published 2026-11-22.

To see which traffic source each Stripe payment came from in a FastAPI app, load the Virling script in your base Jinja template, then read the virling_vid cookie in the route that creates the Stripe Checkout Session and pass it as client_reference_id, or as metadata.virling_vid if that field is taken. Stripe keeps that one ID, and Virling joins the payment to every visit behind it, with the UTM tags of each, so every payment shows the channel that brought the buyer.

This post covers FastAPI with the stripe Python library. The same steps for other stacks are in Flask Stripe UTM tracking, Django Stripe UTM tracking and Next.js Stripe UTM tracking. For Payment Links, metadata limits and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Step 1: add the script to the base template

If FastAPI renders your pages with Jinja2Templates, paste the tag before </head> in the template every page extends, usually templates/base.html. If your pages come from a separate frontend, add it there instead. If you self-host, replace app.virling.com with your Virling server.

<!-- templates/base.html -->
<script defer src="https://app.virling.com/v.js"
  data-site="yourdomain.com"></script>

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it.

Step 2: create the Checkout Session in a route

Your server receives the cookie with every request from the browser. FastAPI reads it for you when you declare a parameter with the same name and Cookie(). Pass it as client_reference_id where you create the session with the stripe Python library:

# main.py
import os
from typing import Annotated

import stripe
from fastapi import Cookie, FastAPI
from fastapi.responses import RedirectResponse

app = FastAPI()
stripe.api_key = os.environ["STRIPE_SECRET_KEY"]


@app.post("/checkout")
def checkout(virling_vid: Annotated[str | None, Cookie()] = None):
    params = {
        "line_items": [{"price": "price_...", "quantity": 1}],
        "mode": "subscription",
        "success_url": "https://yourdomain.com/thanks",
    }
    if virling_vid:
        params["client_reference_id"] = virling_vid

    checkout_session = stripe.checkout.Session.create(**params)
    return RedirectResponse(checkout_session.url, status_code=303)

The route is a plain def because stripe.checkout.Session.create() blocks. FastAPI runs def routes in a thread pool, so the event loop stays free. The 303 makes the browser follow the redirect with a GET. Post to it from a form, and the browser sends the cookie along:

<form action="/checkout" method="post">
  <button type="submit">Subscribe</button>
</form>

The cookie is set on your registrable domain, so an API on a subdomain such as api.yourdomain.com receives it too. If your frontend calls that API with fetch, use credentials: "include" and set allow_credentials=True in CORSMiddleware. For other payment providers, the checkout snippet generator gives the matching code.

When client_reference_id is taken

If you already use client_reference_id for your own user or order ID, put the visitor ID in the session's metadata instead. Virling reads either:

    if virling_vid:
        params["metadata"] = {"virling_vid": virling_vid}

If you create your own PaymentIntent for Elements instead of a Checkout Session, set the same metadata on stripe.PaymentIntent.create(). The full lookup order is in the Stripe docs and in link checkout to visits. The Stripe integration page shows what Virling imports, and Stripe for SaaS shows the subscription view.

Optional: keep the UTM tags in Stripe too

Virling does not need the tags on the payment, since the visitor ID points to every visit. If you also want them readable in the Stripe Dashboard, save them from the landing URL in Starlette's SessionMiddleware (it needs the itsdangerous package) and copy them into metadata. Stripe does not copy session metadata to the Subscription, so set subscription_data.metadata as well, or payment_intent_data.metadata for mode="payment":

from fastapi import Request
from starlette.middleware.sessions import SessionMiddleware

UTM_KEYS = ("utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term")


@app.middleware("http")
async def keep_utm(request: Request, call_next):
    tags = {k: request.query_params[k] for k in UTM_KEYS if request.query_params.get(k)}
    if tags:
        request.session["utm"] = tags
    return await call_next(request)

# added last, so it runs first and request.session exists in keep_utm
app.add_middleware(SessionMiddleware, secret_key=os.environ["SESSION_SECRET"])

# add request: Request to checkout(), then before stripe.checkout.Session.create(**params):
    utm = request.session.get("utm", {})
    if utm:
        params["metadata"] = {**params.get("metadata", {}), **utm}
        params["subscription_data"] = {"metadata": utm}

These tags record one visit, the last tagged one. Keep passing the visitor ID: it is what ties the payment to the whole path.

Subscriptions and renewals

Only the first payment needs the visitor ID: renewals and plan changes keep the channel of the customer's first payment, with no code on your side, as described in renewals.

Check that it works

Run one tagged visit and one test payment as in test your setup. If the payment still shows Unattributed, check that the page you bought from loads the script and that the request to the checkout route goes to the same domain or one of its subdomains, so the cookie reaches the virling_vid parameter.

Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Stripe revenue by traffic source, and the SaaS page shows what you get per channel.

Frequently asked questions

How do I pass UTM parameters to Stripe Checkout in FastAPI?

Declare a virling_vid: Annotated[str | None, Cookie()] = None parameter on the route that creates the Checkout Session and pass it as client_reference_id. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

How do I read the virling_vid cookie in FastAPI?

Add a parameter named virling_vid with Cookie() to your path operation, or read request.cookies.get("virling_vid") from the Request. It is a first-party cookie on your domain, so the browser sends it with every request to your app.

Should I use client_reference_id or metadata.virling_vid?

Use client_reference_id unless it already holds your own user or order ID. In that case put the visitor ID in the session's metadata.virling_vid. Virling reads either.

Should the checkout route be async def or def?

Use def when you call stripe.checkout.Session.create(), since it is a blocking call. FastAPI runs def routes in a thread pool, so the call does not block the event loop.

What happens if the cookie is missing?

The virling_vid parameter is None, so the route creates the session without client_reference_id, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.

Do Stripe Payment Links in a FastAPI app need code?

No. Use a normal link to buy.stripe.com on a page that runs the script. The script adds client_reference_id to the link when the page loads and again on click, unless the link already has one.
