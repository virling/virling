Microsoft Copilot traffic: which Copilot visits pay

By Devendra Variya, co-founder of Virling. Published 2026-11-18.

To see which Microsoft Copilot visits pay, first work out which Microsoft surface the click came from. Copilot answers show up on copilot.microsoft.com, on Bing results pages and in the Edge sidebar, and Virling credits each by the referrer the browser sends, not by the product the person had open. Only copilot.microsoft.com lands in the AI channel; bing.com goes to Organic search. This post walks through each surface and what to do with the numbers.

The setup every assistant shares, from the tracking script to passing the visitor ID into checkout, is in is AI search traffic worth anything.

Where each Copilot click lands

  • copilot.microsoft.com. A link clicked in Copilot on the web arrives with copilot.microsoft.com as the referrer. Virling lists it as Copilot in the AI channel.
  • bing.com and www.bing.com. Virling drops the www and lists both as Bing in Organic search. Every click from a Bing results page lands here, including clicks on an AI answer or a Copilot feature shown on that page: the browser reports bing.com, so Virling cannot tell it from a blue link.
  • Other bing.com subdomains. Any host ending in .bing.com also counts as Organic search, but only bing.com and www.bing.com are named Bing. Another subdomain gets its own row under its full host name, so look for extra bing.com rows in the Source tab.
  • Other Microsoft hosts. Virling's AI list names copilot.microsoft.com only. A click that arrives from a different Microsoft address counts as Referral, under its own host.

The Edge sidebar

Copilot in the Edge sidebar opens links in a normal Edge tab, and the row follows the referrer that tab sends, using the rules above. If it sends copilot.microsoft.com, the visit is Copilot; a bing.com host means Organic search; no referrer at all means Direct. Virling has no rule that detects the sidebar itself. The Browser tab shows these visits as Edge, from the Edg/ mark in the user agent, but that covers every Edge visitor, not only sidebar clicks.

To check a given case, paste the landing URL and the referrer you see into the traffic source checker. Try copilot.microsoft.com, then www.bing.com, to see one land in AI and the other in Organic search.

Tags, ads and the referrer order

Virling reads the referrer first and falls back to utm_source only when there is none. With no referrer, utm_source=copilot.microsoft.com goes to the Copilot row and a bare copilot counts as AI, while bing or bing.com counts as Organic search. Microsoft does not document adding these tags to Copilot links. A tag cannot pull a bing.com visit into AI: the referrer wins.

The one thing that beats the referrer is the medium. A Microsoft Advertising click tagged utm_medium=cpc counts as Paid even though it comes from bing.com. Without that tag, ad clicks from Bing are indistinguishable from organic ones, so give your ad URLs UTM tags with a paid medium. See Microsoft Ads revenue tracking.

Bing decides what Copilot can cite

Microsoft says Copilot grounds its web answers in Bing search, so a page Bingbot cannot crawl or Bing has not indexed is unlikely to be cited. Copilot has no fetcher of its own that Virling recognizes, so Copilot answers do not appear as fetches on the AI card, and Bingbot is not on Virling's AI crawler list. Virling never counts either as a visitor. The Answers tab asks ChatGPT, Claude, Perplexity and Gemini, not Copilot, so it cannot show whether Copilot names you. Which Bing search visitors pay covers the index side.

Comparing Copilot with Bing

Once checkout carries the visitor ID, as described in link checkout to visits, open the Source tab and put the Copilot row next to the Bing row. Each has its own visitors, revenue and revenue per visitor. Because AI answers on Bing pages sit inside the Bing number, the Copilot row is the only part of Microsoft's AI you can measure on its own, and it is a floor.

With the default last non-direct model, a buyer who clicks in Copilot and comes back by typing your URL stays credited to Copilot; a later Bing search click takes the credit instead. First touch, in Site settings, shows how many journeys Copilot started.

When the Copilot numbers look off

  • A buyer says Copilot sent them, but the payment is under Bing. They probably clicked an answer on a Bing results page.
  • An unfamiliar bing.com host in Organic search. That is a Bing subdomain Virling does not name; it is still search, not Copilot.
  • A Microsoft host under Referral. It is not copilot.microsoft.com, so Virling does not treat it as AI.
  • Copilot visits but no revenue. Check the Matched revenue line under the Overview numbers. See Unattributed revenue.

Google has the same split between its assistant and its search engine: see Gemini visits versus AI Overviews.

Frequently asked questions

How do I see which Copilot visits turn into paying customers?

Pass the Virling visitor ID into checkout, then open the Source tab and click Copilot. The row shows visitors from copilot.microsoft.com, the revenue credited to them and revenue per visitor, and you can compare it with the Bing row.

Is Copilot traffic counted as Bing search?

Visits from copilot.microsoft.com are not: they are Copilot in the AI channel. Clicks on Copilot answers shown on a bing.com page arrive from bing.com, so they count as Bing in Organic search.

How are clicks from Copilot in the Edge sidebar counted?

By the referrer the new tab sends. copilot.microsoft.com counts as Copilot, a bing.com host as Organic search, and no referrer as Direct. Virling does not detect the sidebar itself.

Can a utm_source tag move a Bing visit into AI?

No. Virling reads the referrer first, so a visit from bing.com stays in Organic search whatever its utm_source says. The tag is used only when there is no referrer.

Does Copilot have its own crawler?

Not one that Virling recognizes. Microsoft says Copilot grounds web answers in Bing search, so Bingbot and the Bing index decide which pages it can cite.
