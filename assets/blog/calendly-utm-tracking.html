Calendly UTM tracking: which channel books calls that pay

By Devendra Variya, co-founder of Virling. Published 2026-11-25.

For Calendly UTM tracking, add the tags to your Calendly link after a ?, or pass them through the embed code. Calendly stores them with the booking, so you can count booked calls per campaign. It does not know which calls became paid invoices. For that, the booking has to be joined to the payment.

Calendly facts here come from its help and developer pages, linked below and read on 2026-11-25. Virling does not connect to Calendly. The join below uses your own page and server.

Step 1: tag a Calendly link

Put a ? after the link, join the tags with &, and write a space as %20 (source: Calendly, track conversions with UTM parameters):

https://calendly.com/YOUR_LINK/30min?utm_source=newsletter&utm_medium=email&utm_campaign=october-launch
  • Five names. Calendly takes utm_source, utm_medium, utm_campaign, utm_content and utm_term, plus one for a CRM record ID. Other custom names are not supported (source: Calendly, source track your embed).
  • Keep values short. The limit is 255 characters.
  • Keep one spelling. The free UTM builder makes tags you can reuse.

A direct link has one cost: the page is on calendly.com, so your script does not run there. A person who goes from your email straight to Calendly makes no visit to your site. If you want revenue, send them to a page of yours with the calendar embedded.

Step 2: tag an inline or popup embed

Fixed tags

For a page that only one campaign uses, put the tags in data-url (source: Calendly, source track your embed):

<div class="calendly-inline-widget"
  data-url="https://calendly.com/YOUR_LINK/30min?utm_source=newsletter&amp;utm_medium=email&amp;utm_campaign=october-launch"
  style="min-width:320px;height:700px;"></div>
<script src="https://assets.calendly.com/assets/external/widget.js" async></script>

A popup takes the tagged link as its url. Calendly says tags in the URL work for inline, popup text and popup widget. The button below follows its recipe (source: Calendly, embed recipes):

<link href="https://assets.calendly.com/assets/external/widget.css" rel="stylesheet">
<script src="https://assets.calendly.com/assets/external/widget.js" async></script>
<button onclick="Calendly.initPopupWidget({url: 'https://calendly.com/YOUR_LINK/30min?utm_source=newsletter&amp;utm_medium=email&amp;utm_campaign=october-launch'}); return false;">Book a call</button>

Tags from any landing page

Calendly says an embed also looks for the five tags in the address of the page it is on (source: Calendly, embed recipes). That covers the landing page only. If the visitor lands on your home page and then clicks through to the booking page, the tags are gone from the address. This inline embed reads them from a cookie instead, and adds the Virling visitor ID for step 5:

<div id="book-call" style="min-width:320px;height:700px;"></div>
<script src="https://assets.calendly.com/assets/external/widget.js"></script>
<script>
addEventListener("load", function () {
  var query = new URLSearchParams(location.search), utm = {};
  ["Source", "Medium", "Campaign", "Content"].forEach(function (k) {
    var name = "utm_" + k.toLowerCase();
    var value = window.leadUtm ? leadUtm.tags[name] : query.get(name);
    if (value) utm["utm" + k] = value;
  });
  var vid = window.virling?.vid?.();
  if (vid) utm.utmTerm = "vid-" + vid;
  Calendly.initInlineWidget({
    url: "https://calendly.com/YOUR_LINK/30min",
    parentElement: document.getElementById("book-call"),
    utm: utm
  });
});
</script>

leadUtm comes from the snippet in UTM parameters in hidden form fields, which goes on every page. Without it, the code reads only the page address. Values in the utm object win over those in the page URL, and Calendly says a field such as utm_term can hold a user ID if you do not use it for analytics (source: Calendly, source track your embed). If you do use it for keywords, put the ID in utm_content and leave Content out of the list, and read that field in step 5.

Step 3: see where the tags show

  • On one meeting. Open the Calendar page in Calendly and select the meeting (source: Calendly, source track your embed).
  • On many. On the Calendar page choose Filter, then Tracking IDs, All IDs, and enter the tag. The list can be exported as a CSV file (source: Calendly, track conversions with UTM parameters).
  • In code. A webhook has the tags in tracking, next to the invitee’s email (source: Calendly, webhook data). The API has them too.

Make a test booking from a tagged link and check all three.

Step 4: record the booking as a goal

Add the Virling script to every page of your site. The embed sends a calendly.event_scheduled message to your page when a call is booked (source: Calendly, advanced embed). Turn it into a goal:

<script>
addEventListener("message", function (e) {
  if (e.origin === "https://calendly.com" && e.data?.event === "calendly.event_scheduled") {
    window.virling?.("goal", "booking");
  }
});
</script>

Goal names are compared exactly, so keep one lowercase name, and leave names and emails out of it; see goals. Calendly says a plain iframe does not support these messages, so use the JavaScript embed.

What an embed on another domain hides

The calendar looks like part of your page, but it is a frame from calendly.com, and browsers keep the two apart.

  • Your page cannot read the form. The name, email and answers stay in the frame.
  • The message has no email. Its payload is two API addresses, one for the event and one for the invitee (source: Calendly, embed parent window events). Only a server with a Calendly token can look them up.
  • The frame cannot read your cookie. Calendly knows the visitor ID only if you pass it, as in step 2.
  • Virling does not see inside it. Steps in the frame are not pageviews on your site.

Calendly can also redirect to your site with the booking details in the address, the invitee’s email among them. It lists the redirect for its paid plans (source: Calendly, redirect invitees after booking). Leave the details off: addresses stay in browser history and server logs.

Step 5: join the booking to the paid invoice

A booked call is not a sale. The call, the proposal and the signature leave no visit, and an invoice you send from Stripe carries no visitor ID. Virling matches that invoice by email, so it needs the email and the visitor ID together, before the payment.

With a webhook. Subscribe your server to invitee.created, check the Calendly-Webhook-Signature header (source: Calendly, webhook signatures), then send one identify event. Here body is the parsed webhook:

const p = body.payload;
const vid = /^vid-([a-z0-9-]{8,64})$/i.exec(p.tracking?.utm_term || "")?.[1];
if (body.event === "invitee.created" && vid && p.email) {
  await fetch("https://app.virling.com/api/event", {
    method: "POST",
    headers: { "User-Agent": "booking-webhook/1.0" },
    body: JSON.stringify({ n: "identify", u: "https://yourproduct.com/", s: "yourproduct.com", v: vid, m: p.email }),
  });
}

Without a server. Ask for the work email in a short form on your own page, send the identify event from there, then show the calendar. The code is in demo booking revenue tracking.

Virling keeps only a SHA-256 hash of the trimmed, lowercased email with a salt of your site. A later Stripe payment with no visitor ID and the same payer email is credited to that visitor and shows Matched by email. Cover the email and the visitor ID in your privacy policy, and leave cookieless mode off, or there is no ID to pass.

Set the lookback window longer than your sales cycle: 30, 60, 90 or 365 days, with 90 as the default. The full setup is in the sales-led B2B guide, and the matching is explained in Stripe invoice attribution.

Read it in Virling

Click a channel on the Channels card, read its revenue, then open the Goals tab for its booking count. Divide one by the other yourself. A goal belongs to the visit it happened in, while revenue follows your attribution model, so the two can sit in different channels for one buyer.

What still cannot be joined

  • A booking from a direct link. No visit, so no visitor ID.
  • A different payer. Email matching is exact. An accounts team paying from its own address does not match.
  • A payment synced before the identify. Send it at the booking, not after the deal closes.
  • Blocked scripts. With no visitor ID, the booking still goes through, but nothing is joined.
  • Whether the call took place. Virling does not read calendars.

Those payments still count toward revenue, as Unattributed.

Frequently asked questions

How do I add UTM parameters to a Calendly link?

Put a question mark after the link, then the tags joined with an ampersand, such as ?utm_source=newsletter&utm_medium=email&utm_campaign=october-launch. Write a space as %20. Calendly stores the tags with the booking.

Where do I see UTM data in Calendly?

Select a meeting on the Calendar page to see its values, or use Filter, Tracking IDs, All IDs to find one tag and export the list as a CSV file. The tags are also in webhook payloads and in the API.

Why are the UTM tags missing from my Calendly bookings?

Often the visitor landed on one page and booked on another, so the embed found no tags in the address of the booking page. Other causes are a missing question mark or ampersand, a value that is too long, and a visit that had no tags.

Does Virling connect to Calendly?

No. Virling never sees your calendar or your bookings. It sees the visit to your page, the goal your page sends, the email your server sends in an identify event, and the payment from your provider.

How do I join a Calendly booking to a Stripe invoice?

Pass the Virling visitor ID in a UTM field you do not use, such as utm_term. When the Calendly webhook arrives, your server sends that ID and the email to Virling in an identify event. A later Stripe invoice paid with the same email is credited to that visitor.
