Calendly UTM tracking: which channel books calls that pay

By Devendra Variya, co-founder of Virling. Published 2026-11-25.

For Calendly UTM tracking, Calendly accepts five utm_* tags on a scheduling link or through its embed, saves them on the meeting and sends them in its webhooks. It stops at the booking: Calendly cannot see which meetings ended in a paid invoice. This guide covers how Calendly takes the tags, what its embed keeps from your page, the invitee.created webhook and round-robin team links, and uses them to carry a Virling visitor ID to your server.

Calendly’s help center and developer docs are cited inline: the UTM, webhook and round robin pages as read on 2026-11-27, the embed pages as read on 2026-11-25. Virling never connects to your Calendly account; the steps below use your own page and webhook receiver.

Step 1: tag a Calendly link

Append a ?, join the tags with &, and encode spaces as %20 (source: Calendly, track conversions with UTM parameters). UTM tracking is on every plan, Free included:

https://calendly.com/YOUR_LINK/30min?utm_source=newsletter&utm_medium=email&utm_campaign=october-launch
  • Five names and one extra. utm_source, utm_medium, utm_campaign, utm_content and utm_term, plus salesforce_uuid for a CRM record. Calendly does not support custom names (source: Calendly, source track your embed).
  • Up to 255 characters. Longer values may not be tracked.
  • One spelling per channel. The UTM builder keeps tags consistent.

Because there is no custom field, the visitor ID has to borrow one of those five names, which step 2 does. And since calendly.com is not your domain, a click from an email straight to the link is a meeting with no visit of yours behind it. For revenue per channel, embed the calendar on a page with the Virling script.

Step 2: tag an inline or popup embed

Fixed tags

A page that serves one campaign can carry the tags in data-url (source: Calendly, source track your embed):

<div class="calendly-inline-widget"
  data-url="https://calendly.com/YOUR_LINK/30min?utm_source=newsletter&amp;utm_medium=email&amp;utm_campaign=october-launch"
  style="min-width:320px;height:700px;"></div>
<script src="https://assets.calendly.com/assets/external/widget.js" async></script>

A popup takes the tagged link as its url; Calendly lists inline, popup text and popup widget as all reading tags from the URL. This button follows its recipe (source: Calendly, embed recipes):

<link href="https://assets.calendly.com/assets/external/widget.css" rel="stylesheet">
<script src="https://assets.calendly.com/assets/external/widget.js" async></script>
<button onclick="Calendly.initPopupWidget({url: 'https://calendly.com/YOUR_LINK/30min?utm_source=newsletter&amp;utm_medium=email&amp;utm_campaign=october-launch'}); return false;">Book a call</button>

Tags from any landing page

An embed also picks up the five tags from the address of the page it sits on (source: Calendly, embed recipes). That works only when the visitor books on the page they landed on. This inline embed takes remembered tags instead, and puts the Virling visitor ID in utm_term:

<div id="book-call" style="min-width:320px;height:700px;"></div>
<script src="https://assets.calendly.com/assets/external/widget.js"></script>
<script>
addEventListener("load", function () {
  var query = new URLSearchParams(location.search), utm = {};
  ["Source", "Medium", "Campaign", "Content"].forEach(function (k) {
    var name = "utm_" + k.toLowerCase();
    var value = window.leadUtm ? leadUtm.tags[name] : query.get(name);
    if (value) utm["utm" + k] = value;
  });
  var vid = window.virling?.vid?.();
  if (vid) utm.utmTerm = "vid-" + vid;
  Calendly.initInlineWidget({
    url: "https://calendly.com/YOUR_LINK/30min",
    parentElement: document.getElementById("book-call"),
    utm: utm
  });
});
</script>

The leadUtm object comes from the remembering snippet in UTM parameters in hidden form fields. The utm object overrides tags in the page URL, and Calendly suggests a field such as utm_term can hold a user ID when you do not need it for analytics (source: Calendly, source track your embed). If your ads use utm_term for keywords, move the ID to utm_content, drop Content from the list, and read that field in the webhook.

Step 3: find the tags in Calendly

  • One meeting. Select it on the Calendar page (source: Calendly, source track your embed).
  • Many meetings. On the Calendar page choose Filter, Tracking IDs, All IDs, enter the tag, and export the list as CSV (source: Calendly, track conversions with UTM parameters).
  • Webhooks and the API. The tracking object, covered below.

Step 4: count the booking as a goal

With the Virling script on the page, listen for the calendly.event_scheduled message the embed posts after a booking (source: Calendly, advanced embed):

<script>
addEventListener("message", function (e) {
  if (e.origin === "https://calendly.com" && e.data?.event === "calendly.event_scheduled") {
    window.virling?.("goal", "booking");
  }
});
</script>

Calendly says a bare iframe embed sends no such messages, so use the JavaScript widget. Goal names match exactly; keep one lowercase name with no personal data in it (see goals).

What an embed on calendly.com hides from your script

The widget looks like part of your page, but it is a calendly.com frame, and the browser walls it off from your code.

  • Form fields stay in the frame. Your script never sees the name, email or answers.
  • The booking message has two links and no email. Its payload is the API URI of the event and of the invitee (source: Calendly, embed parent window events); resolving them needs a Calendly token on a server.
  • Your cookie does not cross in. The visitor ID reaches Calendly only through the utm object.
  • Steps inside are invisible. Picking a time or filling the form makes no pageviews.

A redirect after booking can put the invitee’s email and other details in your page address; Calendly lists the redirect for paid plans (source: Calendly, redirect invitees after booking). Turn the details off, because addresses land in history and server logs.

The invitee.created webhook

Calendly says invitee.created is available on all plans, Free included; only routing form and meeting recap events need a plan with that feature (source: Calendly, create webhook subscription). Its payload has the invitee’s email and name, questions_and_answers from the booking form, scheduled_event, and a tracking object with the five tags and salesforce_uuid, each possibly null (source: Calendly, webhook data).

The Calendly-Webhook-Signature header looks like t=...,v1=...: the HMAC-SHA256 of the timestamp, a dot and the raw body, with a three-minute replay window (source: Calendly, webhook signatures). After checking it, pull the ID out of utm_term and send one identify event:

const p = body.payload;
const vid = /^vid-([a-z0-9-]{8,64})$/i.exec(p.tracking?.utm_term || "")?.[1];
if (body.event === "invitee.created" && vid && p.email) {
  await fetch("https://app.virling.com/api/event", {
    method: "POST",
    headers: { "User-Agent": "booking-webhook/1.0" },
    body: JSON.stringify({ n: "identify", u: "https://yourproduct.com/", s: "yourproduct.com", v: vid, m: p.email }),
  });
}

Round-robin team links

A round robin event type rotates meetings across teammates and books each invitee with the next available host. It needs a Teams, Teams Plus or Enterprise plan (source: Calendly, team round robin event type). Calendly picks the host in one of two ways (source: Calendly, round robin distribution):

  • Maximize for availability. Priority stars decide; on a tie the teammate without a recent meeting wins, then a random pick.
  • Optimize for equal distribution. No host gets more than three meetings ahead of the rest.

For attribution this means the channel and the host are unrelated: the tags and visitor ID describe how the invitee arrived, not who took the call. Rescheduled meetings are reassigned by default, so a host on the original booking may not be the one who closes. The scheduled_event in the webhook has event_memberships with each member’s user_email and user_name; store that next to the visitor ID in your own CRM if you want revenue per rep, since Virling reports by channel. Calendly’s UTM pages name no exception for team event types, but test one booking through the team link before relying on it.

From booked call to paid invoice

After that identify event, Virling can credit a Stripe invoice paid from the invitee’s email to the visit where the meeting was booked. Read demo booking revenue tracking for the setup without a server, the lookback window to choose and what to put in your privacy policy.

Gaps that remain

  • Direct calendly.com links. No page of yours loaded, so no ID.
  • Keyword data in utm_term. If it is already used, the ID needs utm_content instead.
  • A different payer. An invoice paid from a finance address will not match the invitee’s email.
  • No-shows. Virling does not read calendars, so whether the meeting happened is up to you.

Frequently asked questions

How do I put UTM tags on a Calendly link?

Start with a question mark and join each tag with an ampersand: ?utm_source=newsletter&utm_medium=email&utm_campaign=october-launch. Write spaces as %20. Calendly keeps only the five standard tags and salesforce_uuid.

Where does Calendly show UTM data?

Select a meeting on the Calendar page, or use Filter, Tracking IDs, All IDs to list meetings with one tag and export them as CSV. Webhook payloads and the API carry the tags too.

Why are the UTM tags missing from my Calendly bookings?

Usually the visitor landed on one page and booked on another, so the embed found no tags in the booking page address. A missing question mark or ampersand, a value over 255 characters, or an untagged visit also cause it.

Do UTM tags work on a Calendly round robin link?

Calendly's UTM help names no exception for team event types, so tag the link the same way and check one test booking. The tags describe how the invitee arrived; the host Calendly assigns has nothing to do with them.

Does Virling need access to my Calendly account?

No. Virling never asks for Calendly access. It only sees what your site and server send it: the visit, the booking goal, the identify event with the email, and the payment from your provider.

Can a Calendly booking be matched to a Stripe invoice?

Yes. Put the Virling visitor ID in a UTM field you do not use, such as utm_term. When invitee.created reaches your server, forward the ID and the invitee email to Virling in an identify event; an invoice paid from that email afterwards goes to the original visit.
