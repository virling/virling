Next.js Creem UTM tracking: pass the visit into checkout

By Devendra Variya, co-founder of Virling. Published 2026-11-23.

To tie a Creem payment from a Next.js app to the visit that brought it, load the Virling script once with next/script, then create the Creem checkout on your server with the visitor ID in its metadata as virling_vid. A route handler or a server action reads it from the virling_vid cookie in one line. Creem returns that metadata in its checkout.completed webhook, and Virling joins the payment to every visit behind that ID, with the UTM tags of each.

This post covers the App Router, with notes for the Pages Router. For what Creem does with metadata outside Next.js, see the general guide to Creem UTM tracking. Using Stripe instead? See Next.js Stripe UTM tracking. Comparing providers? The steps for Dodo are in Next.js Dodo Payments UTM tracking.

What happens to UTM tags on the way to Creem

UTM tags live on the landing URL. By the time a visitor clicks Buy they are usually a few pages in, and your app then redirects them to the checkout_url Creem returned, on Creem's own site. That redirect carries only Creem's URL, so nothing from your page travels with the buyer unless you put it in the checkout. The tags do not need to travel, though: the script records them against the visitor ID when the visitor lands, and the ID goes into the checkout's metadata. Passing one ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too.

Step 1: add the script once

Use next/script with strategy="afterInteractive" and load it once, so it runs on every route. defer does nothing on next/script, so leave it out. Client-side navigation is counted too. If you self-host, replace app.virling.com with your Virling server.

App Router, in app/layout.tsx:

import Script from "next/script";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Script src="https://app.virling.com/v.js"
          data-site="yourdomain.com" strategy="afterInteractive" />
      </body>
    </html>
  );
}

Pages Router, in pages/_app.tsx:

import Script from "next/script";

export default function App({ Component, pageProps }) {
  return (
    <>
      <Script src="https://app.virling.com/v.js"
        data-site="yourdomain.com" strategy="afterInteractive" />
      <Component {...pageProps} />
    </>
  );
}

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it. Because the cookie is on your own domain, your server receives it with every request from the browser.

Step 2: create the checkout in a route handler

The script does not add the visitor ID to Creem links on its own, so send your Buy button to your server rather than to a fixed Creem product link. Read the cookie where you create the checkout and set it in metadata:

// app/api/checkout/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function POST(req: NextRequest) {
  const res = await fetch("https://api.creem.io/v1/checkouts", {
    method: "POST",
    headers: { "x-api-key": process.env.CREEM_API_KEY!, "content-type": "application/json" },
    body: JSON.stringify({
      product_id: "prod_...",
      success_url: "https://yourdomain.com/thanks",
      metadata: { virling_vid: req.cookies.get("virling_vid")?.value },
    }),
  });
  const { checkout_url } = await res.json();
  return NextResponse.redirect(checkout_url, 303);
}

A plain form posts to it, and the browser sends the cookie along:

<form action="/api/checkout" method="POST">
  <button type="submit">Buy</button>
</form>

Use https://test-api.creem.io with a test mode key. In the Pages Router, do the same in an API route under pages/api/ and read the cookie as req.cookies.virling_vid.

Or in a server action

In a server action, cookies() from next/headers gives you the cookie, and redirect sends the buyer to Creem:

// app/actions.ts
"use server";
import { cookies } from "next/headers";
import { redirect } from "next/navigation";

export async function checkout() {
  const vid = (await cookies()).get("virling_vid")?.value;
  const res = await fetch("https://api.creem.io/v1/checkouts", {
    method: "POST",
    headers: { "x-api-key": process.env.CREEM_API_KEY!, "content-type": "application/json" },
    body: JSON.stringify({
      product_id: "prod_...",
      success_url: "https://yourdomain.com/thanks",
      metadata: { virling_vid: vid },
    }),
  });
  const { checkout_url } = await res.json();
  redirect(checkout_url);
}

Call it from a form with <form action={checkout}>. Virling reads virling_vid from the checkout's metadata first, then the subscription's metadata, then the customer's metadata.

Step 3: connect Creem

In Creem, open Developers, then API keys, and create a key with the transactions:read scope, plus subscriptions:read so Retention can tell who still pays, and webhooks:write so Virling can add its webhook. No other scopes are needed. Paste it into Virling. Live and test mode keys both work.

Creem returns checkout metadata only in webhooks, not on transactions. So when you connect, Virling adds one webhook for checkout.completed and checks each delivery against the creem-signature header. You do not write a webhook handler. The webhook needs Virling to be reachable over https; on plain http, payments still import but stay Unattributed. The full setup is in the Creem docs and on the Creem integration page.

Step 4: make a test purchase

  1. Connect a key that starts with creem_test_ to Virling. Virling must be reachable over https, so that Creem can reach the webhook.
  2. In your app, put a test mode key in CREEM_API_KEY, use a product from test mode, and point the checkout code at https://test-api.creem.io. Creem keeps test data separate from production.
  3. Open a private window and visit a page that runs the script through a tagged link, such as https://yourdomain.com/?utm_source=test&utm_medium=email. Run window.virling.vid() in the browser console and note the ID. The script does nothing on localhost, so use your domain or a subdomain such as staging.yourdomain.com.
  4. In the same window, go to checkout through your route handler or server action and pay with one of the test cards Creem lists.
  5. Wait a minute for the next sync, then open the payments list at /app/yourdomain.com/payments.

What the payment looks like: in the list it shows the test source and the Email channel of your tagged visit instead of Unattributed. Open it and Credited to shows the same, Journey starts at the tagged visit and ends with the Creem payment, and Details lists the ID from your browser console as Visitor.

Use a new email address for each test, because a later payment by the same customer is a renewal and keeps the first payment's channel. A site has one Creem connection, and test payments stay in your reports after you replace the key with a live one. If the payment lists no visitor ID, the checkout did not carry virling_vid: check that your server reads the cookie on the request that creates the checkout, and that Virling is on https so the webhook arrives. The full checklist is in test your setup.

When the payment still shows as Unattributed

Three things break this most often in a Next.js app.

  • The tags are gone before the script runs. A redirect that rebuilds the URL from the path alone, such as a middleware locale redirect or a redirects rule from / to /home, drops ?utm_source=... and the visit arrives as Direct. Carry the query string through every redirect; the causes and fixes are in UTM parameters lost after redirect.
  • The Buy button links straight to Creem. A fixed Creem product link has no metadata, and the script does not add the ID to it. Point the button at your route handler or server action instead.
  • The checkout request has no cookie. If the checkout is created from another domain, or by a job with no browser request behind it, there is no virling_vid cookie to read. Create it from a request the buyer's browser makes to your app.

Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Creem revenue by traffic source.

Frequently asked questions

How do I pass UTM parameters to Creem checkout in Next.js?

Pass the Virling visitor ID instead. Read the virling_vid cookie in the route handler or server action that creates the checkout and set metadata: { virling_vid } in POST /v1/checkouts. The script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

Do hosted Creem product links get the visitor ID by themselves?

No. The Virling script adds the ID on its own only to some providers' checkout links, and Creem is not one of them. Send the Buy button to a route handler or server action that creates the checkout instead.

How do I read the virling_vid cookie in the App Router?

In a route handler, use req.cookies.get("virling_vid")?.value on the NextRequest. In a server action, use cookies() from next/headers. In a Pages Router API route, use req.cookies.virling_vid.

Do UTM parameters survive the redirect to Creem?

They do not need to. The redirect to Creem carries only the checkout_url Creem returns. The UTM tags were already recorded against the visitor ID when the visitor landed, and the ID travels in the checkout metadata.

Why can I not see virling_vid on my Creem transactions?

Creem returns checkout metadata only in webhooks, not on transactions. Virling adds one checkout.completed webhook when you connect, so it needs to be reachable over https.

What happens to payments with no visitor ID?

They have no visit to join, so Virling shows them as Unattributed. They still count toward revenue.

Does Creem test mode work with Virling?

Yes. Connect a key that starts with creem_test_ and point your Next.js code at https://test-api.creem.io. Virling reads test transactions and adds its webhook in test mode. Test payments stay in your reports after you replace the key with a live one.
