utm_id parameter and the newer UTM tags, explained

By Devendra Variya, co-founder of Virling. Published 2026-11-26.

The utm_id parameter is the campaign ID: a short, stable code that names one campaign, so a report can join visits to rows in another system, such as a spend sheet or a campaign data upload. Google's help page lists it next to three other tags: utm_source_platform for the platform that sent the traffic, utm_creative_format for the type of creative and utm_marketing_tactic for the targeting. All four are optional. If your analytics tool does not read them, the five classic tags are enough.

The four newer UTM parameters

The definitions below come from Google's help page URL builders: collect campaign data with custom URLs, as it reads in November 2026. Every example URL is made up.

ParameterWhat Google says it isGoogle's examplesReported in Google Analytics
utm_idCampaign ID for a specific campaign or promotionThe same IDs you use when uploading campaign dataYes
utm_source_platformThe platform that directed the traffic, such as a buying platform that sets budgets and targetingSearch Ads 360, Display & Video 360Yes
utm_creative_formatType of creativedisplay, native, video, searchNot currently
utm_marketing_tacticTargeting criteria applied to a campaignremarketing, prospectingNot currently

Google's page also says values are case sensitive, recommends setting utm_id and utm_source_platform next to source, medium and campaign, and shows (not set) in reports for any of them that is missing.

utm_id

Use one ID per campaign and keep it for the life of the campaign. Google asks you to use the same ID you use in a campaign data upload, which is the point of the tag: the ID is the key that joins the two.

https://example.com/pricing?utm_source=linkedin&utm_medium=paidsocial&utm_campaign=spring-launch&utm_id=c0142

utm_source_platform

This is the tool that bought or managed the traffic, which is not always the site that sent it. A search ad bought through Search Ads 360 has utm_source=google and a source platform of Search Ads 360. The space must be encoded in the URL.

https://example.com/?utm_source=google&utm_medium=cpc&utm_campaign=brand-search&utm_id=c0150&utm_source_platform=Search+Ads+360

utm_creative_format

The kind of ad, not which ad. Two video ads in one campaign share utm_creative_format=video; utm_content is what tells them apart.

https://example.com/?utm_source=youtube&utm_medium=cpv&utm_campaign=spring-launch&utm_creative_format=video

utm_marketing_tactic

Who the ad was shown to: people who visited before, or new people.

https://example.com/pricing?utm_source=facebook&utm_medium=paidsocial&utm_campaign=spring-launch&utm_marketing_tactic=remarketing

For the five tags these sit beside, see utm_source vs utm_medium and utm_content vs utm_term.

What Virling stores from them today

When the Virling script sends a pageview, the server reads five tags from the landing URL's query string: utm_source (or ref when it is missing), utm_medium, utm_campaign, utm_content and utm_term. Each value is trimmed and cut to 200 characters and stored with the pageview.

  • utm_id, utm_source_platform, utm_creative_format and utm_marketing_tactic are not read. The page is stored as its path without the query string, so these values are not kept anywhere in Virling.
  • They do no harm. The link still works, the five classic tags on it are still read, and the channel is set the same way as without them.
  • The UTM checker knows all nine names. It does not flag the newer four as unknown, but it does flag a made-up utm_ name such as utm_campain.
  • The UTM builder has fields for the five classic tags only. Add utm_id to the end of the link by hand if you need it.

Do you need the newer tags?

For revenue in Virling, no: rows come from utm_campaign (the Campaign tab), utm_term (the Keyword tab) and the channel set from utm_medium, the referrer and utm_source. Add utm_id when another tool joins on it, such as a Google Analytics campaign data upload, or when your own spend sheet keys rows on an ID. Leave utm_creative_format and utm_marketing_tactic out unless a tool you use reads them, because Google says its own reports do not yet.

A naming table to join campaigns to a spend sheet

A small team usually keeps spend in a sheet: one row per campaign, with what it cost. The join only works if every link for that campaign carries the same ID, and the ID maps to exactly one campaign name. Since Virling reports by utm_campaign, keep the two locked together: one ID, one name, for good. This sheet is made up:

utm_idutm_campaignWhere it runs, and spend
c0142spring-launchLinkedIn ads (linkedin, paidsocial), $600
c0143spring-launch-searchGoogle search ads (google, cpc), $450
c0144issue-42Newsletter (newsletter, email), $0

The rules behind it:

  • The ID is a code, not a description. A letter and a number, such as c0142. Descriptions belong in utm_campaign.
  • Give out IDs from the sheet. Add the row first, then build the links, so no one invents an ID in an ad platform.
  • One source and medium per ID if you want spend per channel. A campaign on LinkedIn and Google gets two IDs and two names, as above.
  • Never reuse an ID. When a campaign ends, its ID retires with it.
  • Lowercase, no spaces. Google treats values as case sensitive, so C0142 and c0142 are two campaigns.

Then the join is a lookup: take the rows of the Campaign tab in Virling, or the campaign dimension of the read API, look up each utm_campaign in the sheet, and put spend next to revenue.

Mistakes that split one campaign into many rows

  • Capitals in one link. Spring-Launch and spring-launch are two rows in Virling and two in Google Analytics.
  • Two names for one ID. An ad set copied from last month keeps utm_id=c0142 but says utm_campaign=spring-launch-v2. The ID join still works in a tool that reads utm_id, but Virling shows two campaign rows and your lookup misses one.
  • The spreadsheet ate the ID. An ID such as 0142 becomes 142 when a sheet reads it as a number. Start IDs with a letter.
  • The month in the campaign name. spring-launch-march and spring-launch-april split one campaign in two. Use the date range of the report instead.
  • A space or a stray character. spring launch may arrive as spring+launch or spring%20launch, and a trailing space copied from a sheet makes another value in tools that do not trim.
  • The platform ID in one place and yours in another. If the Google Ads URL suffix fills utm_id with the platform's campaign ID and your other links use sheet IDs, pick one scheme and use it everywhere.

Paste a batch of finished links into the UTM checker before they go out. It flags capitals, spaces, empty values and duplicate tags. Two names for one ID only show up in the sheet, so check new rows there.

Frequently asked questions

What is the utm_id parameter?

utm_id is the campaign ID. Google describes it as the parameter that identifies a specific campaign or promotion, and asks you to use the same IDs you use when you upload campaign data to Google Analytics.

Is utm_id required?

No. A link with utm_source, utm_medium and utm_campaign is complete. Add utm_id when a report or a spend sheet joins rows on a campaign ID rather than a campaign name.

What is utm_source_platform for?

It names the platform that sent the traffic, such as a buying platform that sets budgets and targeting. Google gives Search Ads 360 and Display & Video 360 as examples.

Does Google Analytics report utm_creative_format and utm_marketing_tactic?

Not at the time of writing. Google's help page says both are not currently reported in Google Analytics properties, so they only help a tool that reads the raw URL.

Does Virling store utm_id or the other newer tags?

No. Virling stores utm_source, utm_medium, utm_campaign, utm_content and utm_term. It ignores utm_id, utm_source_platform, utm_creative_format and utm_marketing_tactic, and keeps the page path without its query string, so those values are not saved.
