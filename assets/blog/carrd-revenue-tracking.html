Carrd revenue tracking: see which channel brings each sale

By Devendra Variya, co-founder of Virling. Published 2026-11-19, updated 2026-11-26.

A Carrd site is usually one page with one job: get the click on the Buy button. That makes it easy to track, as long as the button is a plain link to a Stripe Payment Link or a LemonSqueezy checkout. Carrd also has its own ways to take money (a Stripe Checkout widget, payment-enabled forms, Gumroad and PayPal widgets), and those are where the channel gets lost. Below: the embed element that carries the Virling tag, the Carrd plan it needs, and what happens with each kind of Carrd checkout.

The hidden embed that carries the tag

Carrd has no site-wide code box; scripts go in an embed element. In the builder, choose Add Element, then Embed, set Type to Code and paste the tag the Virling app gives you:

<script defer src="https://app.virling.com/v.js" data-site="yourdomain.com"></script>

Set Style to Hidden and pick Head from the three spots Carrd offers (Head, Body Top, Body End). An Inline embed would also run, but Hidden keeps it out of your layout. Carrd's embed docs say the element outputs nothing in the builder, so publish before you check anything. The framework setup docs show the same element.

Embeds come with Pro Standard, which also adds custom domains. Pro Lite has neither, so on Pro Lite the tag cannot go in at all. Put the address you actually publish to in data-site, without www.: either your own domain or the .carrd.co one, since visits on any other host are not recorded.

Each Carrd checkout, and what Virling sees

On your Carrd pageRevenue in VirlingChannel
A button whose URL is a Stripe Payment Link, a LemonSqueezy checkout, or a Polar or Dodo Payments checkoutYes, from the connected providerYes, when the click came from the published page
The Stripe Checkout widgetYes, if you connect the same Stripe accountNo. The widget starts checkout from a Price ID and your API keys, with no link to tag
A form that requires payment (Pro Plus)Yes, if you connect the same Stripe accountNo. The form opens Stripe Checkout itself, between submit and processing
The Gumroad widget or a PayPal widgetNo. Virling does not connect to Gumroad or PayPalNo

Gumroad sales are the case people ask about most. Virling cannot import them, so they never show as revenue. A click on a plain link to Gumroad is still recorded on the visitor as an exit link, which tells you which channel sends people to the product page, but not who bought. To get revenue by channel, sell the product through a provider Virling connects to and put that checkout link on the button.

The two Stripe options are easier to fix. Make a Payment Link in Stripe for the same price, then replace the widget or the payment step with a normal Carrd button pointing at it. A button set to run code on click instead of opening a URL, or a checkout shown inside an IFRAME embed, has the same problem as the widget: there is no link on your page for the script to tag.

From a Carrd button to a credited sale

  1. Copy your Stripe Payment Link, for example https://buy.stripe.com/abc123, or your https://STORE.lemonsqueezy.com/checkout/buy/VARIANT_ID link.
  2. Paste it as the button's URL in Carrd, with nothing added. Publish.
  3. A visitor arrives from ?utm_source=producthunt. The script stores a visitor ID in the first-party virling_vid cookie and records the visit with its source.
  4. On that page the button now opens the link with client_reference_id set to the ID for Stripe, or checkout[custom][virling_vid] for LemonSqueezy. An existing value is left as it is.
  5. The visitor pays. With Stripe connected through a restricted key with Read access, Virling finds the Checkout Session and reads the ID. With LemonSqueezy connected through an API key, Virling registers a webhook on your stores, since custom data only comes back there. The sale is credited to producthunt under last non-direct, or first touch or last touch if you choose.

Polar uses reference_id and Dodo Payments uses metadata_virling_vid; the checkout docs and the integrations page cover each one.

Check the published Carrd page

  1. After Publish, load the live page with a hard refresh. Carrd's troubleshooting page points out that browsers keep an older copy for a while.
  2. In a private window, open https://yourdomain.com/?utm_source=test&utm_medium=test.
  3. Virling should list the visitor under Visitors and test on the Channels card. If not, check the embed's code and the host in data-site, then publish again.
  4. Copy the button's link address: a Stripe link ends in client_reference_id= and an ID, a LemonSqueezy link contains virling_vid. Pay through a test Payment Link with a Stripe key starting rk_test_. Polar sandbox and Dodo Payments test links are not tagged, so use a small live payment there and refund it.
  5. After a minute, open /app/yourdomain.com/payments. The payment says test, and Visitor under Details leads to the visit.

Test payments stay after you switch to a live key. See test your setup if a step fails, and the no-code guide for other builders.

Why a Carrd sale has no channel

  • You checked in the builder. Embeds do nothing there.
  • The embed has a typo. Carrd warns that a syntax error in custom code can stop the whole site from loading; paste the tag unchanged.
  • The sale came from a widget or a payment form. Neither creates a link the script can reach.
  • The buyer skipped the page. A Payment Link shared in a launch post, an email or a QR code carries no visitor ID. Share the Carrd page instead.
  • The checkout runs on your own domain, or the tag has data-cookieless. The script tags only the four provider hosts, and in cookieless mode there is no visitor ID at all. For a checkout on another domain, add window.virling.vid() to the link yourself.

For what a Stripe Payment Link keeps and drops, see Stripe Payment Link UTM tracking. Other builders: Framer, Wix and Squarespace.

Frequently asked questions

Can Carrd show which channel brought a sale?

Not by itself. The payment happens on the checkout provider's page, which never sees where the visit came from. With the Virling tag in a hidden embed, Stripe Payment Links and LemonSqueezy, Polar or Dodo checkout links on your buttons carry a visitor ID, and Virling joins each payment to the visit and its channel.

Which Carrd plan do I need?

Pro Standard or higher, because the tag goes in an embed element and Pro Lite has no embeds. Payment-enabled forms need Pro Plus, but you do not need them for tracking.

Does the Carrd Stripe Checkout widget or payment form carry the visitor ID?

No. Both start Stripe Checkout themselves, so there is no buy.stripe.com link for the script to tag. If you connect the same Stripe account, the payments count as revenue but show as Unattributed. A normal button with a Payment Link gets the channel.

Does Virling track Gumroad sales from a Carrd site?

No. Virling does not connect to Gumroad, so those sales are not imported. A click on a plain Gumroad link is recorded as an exit link on the visitor, which shows interest by channel but not revenue.

Does it work with LemonSqueezy checkout links?

Yes. The script adds checkout[custom][virling_vid] to every lemonsqueezy.com checkout link on the page. LemonSqueezy only returns that custom data in webhooks, so Virling registers a webhook on your stores when you connect it.

Why does my Carrd sale show as Unattributed?

Usually the buyer opened the checkout link from a launch post, an email or a QR code, or the sale came from a Carrd widget or payment form. Testing in the builder, a custom checkout domain or cookieless mode also leave the sale without a channel.
