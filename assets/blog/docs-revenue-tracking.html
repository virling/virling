Do your docs bring paying customers? How to find out

By Devendra Variya, co-founder of Virling. Published 2026-11-21.

Your docs bring paying customers when the people who land on them, or read them before buying, go on to pay. Page views and time on page cannot tell you that. To see it, each payment has to be joined to the visit before it, and the visit has to keep its pages, including the docs, in one record.

This guide is for developer-tool and B2B SaaS founders who write docs and want to know whether they earn their keep. It covers two questions, which need two different views: do docs pages find customers, and do customers read the docs before they pay. Both rest on tracking revenue by traffic source.

What you need first

Two links must exist before any page report means something. The payment provider must be connected, and the visitor ID must reach checkout, so a payment can be joined to the visit before it. See link checkout to visits.

Then it is a matter of which visit gets the credit. Virling describes a session by its first pageview: its channel, referrer, campaign and landing page. When a payment is matched, the whole payment, after refunds, is credited to one session in the lookback window, 90 days by default. The default model picks the latest session that was not Direct. See the attribution model.

Where your docs live matters

Docs on a path or a subdomain

Put the same script tag on your docs as on the rest of the site. With data-site="example.com", pages on example.com/docs, docs.example.com and app.example.com all count for the same site and share the virling_vid cookie, which is set on your registrable domain. Links between them are not exits, and referrers from your own domain and its subdomains are ignored, so moving from the homepage to the docs never changes the channel the visit came from. This is the setup that measures docs best.

Docs on a separate domain

Events are kept only when the page’s host is the site’s domain or one of its subdomains. Docs on another domain, such as example.dev, do not show up on the site’s Pages card. Add that domain under Same-visit domains in Site settings: clicks to it are no longer counted as exits, and a return from it continues the visit instead of starting a new one, so the channel that brought the reader keeps the credit. What you will not see is which docs pages were read. If that matters to you, serving the docs on a subdomain is the fix. See Add the script.

How to read it in Virling

1. Do docs pages find customers? Use Landing page

The Pages card on the dashboard has two tabs. Landing page lists the first page of the visit that was credited with the payment. Each row shows visitors, revenue and revenue per visitor, with a chip that compares the row with your site average: green above it, red below. A docs page with paying visitors here is a page that found customers, for example through organic search or an AI assistant answering a “how do I” question.

Sort by revenue per visitor, not by visitors. A popular reference page with a red chip is loud but does not pay. A small integration guide with a green chip is worth more of your time. Wait until a page has a few hundred visitors before you trust its chip.

2. Do docs close customers? Use Before paying

The Before paying tab lists the last page viewed before the payment. If a quickstart or a pricing-limits page keeps showing up here, the docs are doing closing work, even when the visit landed somewhere else.

3. Did paying customers read the docs at all? Use Visitors

The two tabs only see the first and last page. For everything in between, open the Visitors page, search pages for your docs path, and use Filters to pick visitors who paid, then visitors who did not. Open a visitor to see their timeline: every visit, the time on each page, and each payment where it happened with the source it was credited to. The Recent customers card shows the same thing for your last 10 customers, with visits before paying and a short path.

4. Check whether the docs are read by buyers

The Reading card shows, for each page, how long it stays visible and how far it is scrolled, for every visitor or only for buyers. If buyers read your quickstart to the end and everyone else leaves at the top, the end of the quickstart is doing the work.

A worked example

This is a hypothetical example with made-up numbers, to show the method. A developer tool with docs on docs.example.com, over 90 days:

  • An integration guide for a popular framework lands 1,200 visitors and 8 credited payments. Its chip is green.
  • The API reference lands 9,000 visitors and 2 credited payments. Its chip is red.
  • The quickstart lands few visitors but is the Before paying page for 11 payments.
  • On the Visitors page, most paying visitors viewed at least one docs page; among visitors who did not pay, far fewer did.

What to change: the integration guide finds buyers, so write the guide for the next framework your users ask about, and link the signup from it. The API reference is read by people who already use the product, so it is not failing; do not judge it by new revenue. The quickstart closes, so link it from pricing and the homepage. And because paying visitors read the docs more often than others, a docs link on the landing pages that bring the most visitors is worth testing.

Do not read the last bullet as proof that docs cause payment. People who are about to buy read docs because they are about to buy. Treat it as a reason to make the docs easy to find, and compare the next 90 days against this one.

What to check if the numbers look off

  • Most revenue has no landing page. The payment was not matched to a visit. The Matched revenue line under the Overview numbers gives the share matched and why the rest was not. See Unattributed revenue.
  • No docs pages show up at all. Check that the docs run the script with the same data-site, and that they are on the site’s domain or a subdomain.
  • Docs pages you expected to win are missing from Landing page. By default the payment goes to the latest visit that was not Direct, which can be a later visit than the docs visit that found the customer. Switch the model to first touch in Site settings to credit the earliest session, and compare. See first touch or last touch.

Frequently asked questions

Do docs bring paying customers?

Sometimes, and you can check. Credit each payment to the landing page of the visit that brought the customer, then compare docs pages with the rest of the site by revenue per visitor. Docs pages that show up as landing pages with paying visitors are bringing customers.

How do I see if people who read the docs went on to pay?

Open the Visitors page, search pages for your docs path, and filter to visitors who paid. Open a visitor to see every visit, the time on each page, and the payment where it happened. The Before paying tab on the Pages card shows whether a docs page was the last page viewed before paying.

Are visits to docs.example.com part of the same visit?

Yes. With data-site set to example.com, pages on docs.example.com count for the same site and share the visitor ID cookie. Referrers from your own domain and its subdomains are ignored, so reading the docs never changes the channel the visit came from.

What if my docs are on a separate domain?

Events are kept only for the site's domain and its subdomains, so docs pages on another domain, such as example.dev, do not appear on the site's Pages card. Add that domain under Same-visit domains in Site settings so clicks to it are not exits and a return from it continues the visit. To measure docs pages themselves, serve them on a subdomain.

Should I cut docs that bring no revenue?

No. Docs also keep paying customers and save support time, which revenue attribution does not measure. Use the result to decide which docs pages to link to the product and pricing more clearly, not which ones to delete.
