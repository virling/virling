Do your docs bring paying customers? How to find out

By Devendra Variya, co-founder of Virling. Published 2026-11-21.

Docs bring paying customers when readers who arrive on a docs page, or open the docs while deciding, become buyers. Page views and time on page cannot show that. Each payment has to be joined to the visit before it, and that visit has to keep every page it touched, docs included.

This guide is for developer-tool and B2B SaaS founders who write docs and want to know whether they earn their keep. Developers often meet a tool through its docs before they ever see the homepage: a search for how to do something lands on an integration guide or an error page. So the questions are whether docs pages find customers, and whether customers read the docs before they pay or only after.

What you need first

Connect your payment provider and pass the visitor ID into checkout, so a payment can be tied back to a visit. Link checkout to visits covers each provider.

Where your docs live matters

Virling keeps every page of a visit, and by default credits a payment to the latest earlier session that did not come in as Direct, so a reader who later returns by typing your address is not lost to Direct. Whether docs pages count as part of that visit depends on where they are hosted. See the attribution model.

Docs on a path

Docs at example.com/docs are ordinary pages of the site. Add the same script tag to the docs template and they show up next to every other page, with nothing else to set.

Docs on a subdomain

With data-site="example.com", pages on docs.example.com and app.example.com count for the same site and share the virling_vid cookie, which is set on your registrable domain. Links between them are not exits, and referrers from your own domain and its subdomains are ignored, so moving from the homepage to the docs never changes the channel the visit came from.

Docs on a separate domain

Events are kept only when the page’s host is the site’s domain or one of its subdomains. Docs on another domain, such as example.dev, do not show up on the site’s Pages card. Add that domain under Same-visit domains in Site settings: clicks to it are no longer counted as exits, and a return from it continues the visit instead of starting a new one, so the channel that brought the reader keeps the credit. What you will not see is which docs pages were read. If that matters to you, serving the docs on a subdomain is the fix. See Add the script.

Buyers who land on the docs first

On the dashboard’s Pages card, the Landing page tab shows each docs page that started a credited visit, with its visitors, revenue and a chip against your site average. A docs page with paying visitors here found customers on its own, usually through organic search or an AI assistant answering a “how do I” question.

Rank docs pages by revenue per visitor rather than traffic. A popular reference page with a red chip is loud but does not pay; a small integration guide with a green chip deserves the next hour of writing. Pages with only a few dozen visitors need a longer date range before their chip means much.

To see where those developers came from before the docs, click a docs row to filter the page by it, then open the Source tab on the Channels card. For how GitHub, package registries and communities send developers, see revenue attribution for developer tools.

Before buying or after?

A docs page read before the payment helped someone decide. One read only after it is onboarding, which matters for keeping customers but did not win them. Virling can tell the two apart.

1. Last page before paying

The Before paying tab on the Pages card shows the page each buyer viewed right before the payment. A quickstart or a pricing-limits page that keeps appearing here is doing closing work, even when the visit landed somewhere else.

2. One customer at a time

Open the Visitors page, search pages for your docs path, and use Filters to keep visitors who paid. Open one to see the timeline: every visit with the time on each page, and the payment placed where it happened. Docs visits above the payment were read while deciding; docs visits below it came after. The Recent customers card shows your last 10 customers with their visits before paying and a short path.

3. Buyers against everyone else

Run the same Visitors search with the filter set to visitors who did not pay, and compare. The Reading card adds depth: for each page, how long it stays visible and how far it is scrolled, for every visitor or only for buyers. If buyers read your quickstart to the end and others leave at the top, the end of the quickstart is doing the work.

A worked example

Made-up numbers, for illustration only. A developer tool with docs on docs.example.com, over 90 days:

  • An integration guide for a popular framework lands 1,200 visitors and 8 credited payments. Its chip is green.
  • The API reference lands 9,000 visitors and 2 credited payments. Its chip is red.
  • The quickstart lands few visitors but is the Before paying page for 11 payments.
  • On the Visitors page, most paying visitors viewed at least one docs page before paying; among visitors who did not pay, far fewer did.

What to change: the integration guide finds buyers, so write the guide for the next framework your users ask about, and link the signup from it. The API reference is read by people who already use the product, so it is not failing; do not judge it by new revenue. The quickstart closes, so link it from pricing and the homepage. And because paying visitors read the docs more often than others, a docs link on the landing pages that bring the most visitors is worth testing.

Do not read the last bullet as proof that docs cause payment. People who are about to buy read docs because they are about to buy. Treat it as a reason to make the docs easy to find, and compare the next 90 days against this one.

Common docs tracking problems

  • No docs pages show up at all. Check that the docs run the script with the same data-site, and that they are on the site’s domain or a subdomain.
  • Visits break in two at the docs. The docs are on a separate domain that is not listed under Same-visit domains, so a return from them starts a new visit.
  • A guide that found a customer gets no credit. The default model credits the latest non-Direct visit, which can come after the docs visit. First touch, set in Site settings, credits the earliest session instead; see first touch or last touch.

Frequently asked questions

Do docs bring paying customers?

Sometimes, and you can check. Docs pages that start visits ending in a payment are bringing customers; put them next to the rest of the site by revenue per visitor to see how much.

How do I see if people who read the docs went on to pay?

Open the Visitors page, search pages for your docs path, and filter to visitors who paid. Open a visitor to see every visit, the time on each page, and the payment where it happened. The Before paying tab on the Pages card shows whether a docs page was the last page viewed before paying.

Can I tell if customers read the docs before or after they paid?

Yes. A paying visitor's timeline places the payment among their visits, so docs pages above it were read before buying and docs pages below it after. Docs read only after paying are onboarding, not the reason for the sale.

Are visits to docs.example.com part of the same visit?

Yes. With data-site set to example.com, pages on docs.example.com count for the same site and share the visitor ID cookie. Referrers from your own domain and its subdomains are ignored, so reading the docs never changes the channel the visit came from.

What if my docs are on a separate domain?

Events are kept only for the site's domain and its subdomains, so docs pages on another domain, such as example.dev, do not appear on the site's Pages card. Add that domain under Same-visit domains in Site settings so clicks to it are not exits and a return from it continues the visit. To measure docs pages themselves, serve them on a subdomain.

Should I cut docs that bring no revenue?

No. Docs also keep paying customers and save support time, which revenue attribution does not measure. Use the result to decide which docs pages to link to the product and pricing more clearly, not which ones to delete.
