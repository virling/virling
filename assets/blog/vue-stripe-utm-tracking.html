Vue Stripe UTM tracking: pass UTM tags to Stripe Checkout

By Devendra Variya, co-founder of Virling. Published 2026-11-24.

To tie a Stripe Checkout payment in a Vue app to the visit and UTM tags that brought it, add the Virling script to index.html, create the Checkout Session in a small Node endpoint, and have that endpoint read the virling_vid cookie and set it as metadata.virling_vid on the session. Stripe keeps that one ID, and Virling joins the payment to every visit behind it, with the UTM tags of each. No tags have to survive in the URL.

This post covers a Vue 3 app built with Vite. With Nuxt, the server is part of the framework; see Nuxt Stripe UTM tracking. The same flow in React is in React Stripe UTM tracking. For Payment Links and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Why Vue apps lose UTM tags before checkout

A visitor lands on /?utm_source=newsletter&utm_campaign=launch, then clicks a RouterLink to /pricing. The new URL has only the query you gave the link, so the tags are gone by the time the visitor clicks Buy. Stripe Checkout then runs on Stripe's domain and only stores what your server passes when it creates the session.

The Virling script records the tags with the landing pageview. It hooks into history.pushState, history.replaceState and the back button, so route changes are counted as pageviews and stay in the same session and channel as the landing. Checkout only needs the visitor ID. If the tags never reach your landing page at all, see UTM parameters lost after redirect.

Step 1: add the script to index.html

A project made with npm create vue@latest uses Vite (Vue quick start), and its index.html is at the project root (Vite guide). Paste the tag before </head>. If you self-host, replace app.virling.com with your Virling server.

<!-- index.html -->
<script defer src="https://app.virling.com/v.js"
  data-site="yourdomain.com"></script>

Load it once, here, so it runs on every route. The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it.

Step 2: call your endpoint from a Vue component

The browser sends the cookie with every request to your own domain, so the component has nothing to pass. The script loads with defer, so a click can come before it has set the cookie; wait for it briefly. If the script is blocked, the request goes out after two seconds without the cookie. The component uses <script setup> (Vue SFC reference) and a method handler (Vue event handling):

<!-- src/components/BuyButton.vue -->
<script setup>
import { ref } from "vue";

const error = ref("");

async function scriptReady() {
  for (let i = 0; i < 20 && !window.virling?.vid; i++) {
    await new Promise((r) => setTimeout(r, 100));
  }
}

async function buy() {
  error.value = "";
  await scriptReady();
  const res = await fetch("/api/checkout", { method: "POST" });
  if (!res.ok) {
    error.value = "Checkout could not start. Please try again.";
    return;
  }
  window.location.href = (await res.json()).url;
}
</script>

<template>
  <button type="button" @click="buy">Buy</button>
  <p v-if="error">{{ error }}</p>
</template>

Step 3: read the cookie in Node and set it in metadata

The endpoint holds the Stripe secret key. Install it with npm install express cookie-parser stripe, outside the Vue bundle. It reads the virling_vid cookie, sets it as metadata.virling_vid and returns the session URL (Stripe API reference):

// server.mjs
import cookieParser from "cookie-parser";
import express from "express";
import Stripe from "stripe";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);
const appUrl = process.env.APP_URL || "http://localhost:5173";
const app = express();
app.use(cookieParser());

app.post("/api/checkout", async (req, res) => {
  const vid = req.cookies.virling_vid ?? "";
  const session = await stripe.checkout.sessions.create({
    mode: "subscription",
    line_items: [{ price: process.env.STRIPE_PRICE_ID, quantity: 1 }],
    success_url: `${appUrl}/thanks`,
    metadata: /^[A-Za-z0-9-]{8,64}$/.test(vid) ? { virling_vid: vid } : {},
  });
  res.json({ url: session.url });
});

app.listen(3000);

The price stays on the server, so the browser cannot choose its own. For a one-time payment, use a one-time price and set mode to payment. The regular expression drops anything that does not look like a visitor ID, and a missing cookie leaves the metadata empty.

Stripe allows 50 metadata keys per object, with up to 40 characters in a key and 500 in a value (Stripe metadata). The key must be exactly virling_vid. Passing the ID as client_reference_id, which holds up to 200 characters, works too; use metadata when that field has your own user or cart ID. If you create your own PaymentIntent for Elements, set the same metadata on it, as in Stripe Elements UTM tracking.

The full lookup order is in the Stripe docs, and the Stripe integration page shows what Virling imports. The checkout snippet generator writes the server call for other providers.

Test it locally

Send /api requests from the Vite dev server to the Node endpoint, so the fetch stays on one origin and carries the cookie (Vite server options). Restart npm run dev after the change:

// vite.config.js
import vue from "@vitejs/plugin-vue";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: { "/api": "http://localhost:3000" },
  },
});
  1. Keep the plugins your vite.config.js already has and add only server.proxy.
  2. Add data-dev to the script tag while you test. Without it the script does nothing on localhost, so there is no cookie. Put a separate test site of yours in data-site to keep these visits out of your real reports.
  3. Connect a restricted Stripe key that starts with rk_test_ to that test site in Virling, and start the endpoint with your test secret key and a test price: STRIPE_SECRET_KEY=sk_test_... STRIPE_PRICE_ID=price_... node server.mjs.
  4. In a private window, open http://localhost:5173/?utm_source=test&utm_medium=test, go to another route and click Buy.
  5. Pay with the card 4242 4242 4242 4242, any future date and any three-digit CVC (Stripe testing).
  6. Wait a minute for the next sync and open the site's payments list in Virling. The payment should show the test source instead of Unattributed. Open it to see its journey.

Virling reads payments from Stripe, so this needs no webhook on your machine. Before you deploy, remove data-dev, set data-site back to your domain, set APP_URL, and serve /api/checkout from the same domain as the app: the proxy above only exists in the dev server. The full checklist is in test your setup.

Usual mistakes

  • The API is on another domain. The virling_vid cookie belongs to your site's domain, so the browser does not send it to a different one. Send the result of window.virling?.vid?.() in the request body and allow the app's origin with CORS. On a subdomain such as api.yourdomain.com the cookie is shared, but the fetch needs credentials: "include" and the API must allow that origin with credentials.
  • req.cookies is undefined. Express does not parse cookies by itself. Call app.use(cookieParser()) before the route.
  • The app uses hash URLs. With createWebHashHistory() the path never changes, so only the first page is counted. Use createWebHistory(), the mode Vue Router recommends (Vue Router history modes).
  • The script tag is in a Vue template. Vue does not allow <script> tags in component templates. Keep the tag in index.html.
  • The ID is only in subscription_data.metadata. That goes to the subscription, which Virling does not read. Set metadata on the session itself.
  • The secret key is in a VITE_ variable. Those values are compiled into the public bundle (Vite env variables). Keep the key in the environment of the Node process.

If a payment still shows Unattributed, check in the browser console that window.virling.vid() returns an ID, in the network tab that the request to /api/checkout carries the cookie, and that the session in Stripe has virling_vid in its metadata. How the join works from visit to payment is in how to track Stripe revenue by traffic source. For more on the server side, see Express Stripe UTM tracking.

Frequently asked questions

How do I pass UTM parameters to Stripe Checkout from a Vue app?

Read the virling_vid cookie in the endpoint that creates the Checkout Session, and set it as metadata.virling_vid on the session. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

Why are my UTM parameters gone after the first route change?

A RouterLink to another path does not carry the current query string over, so the tags leave the URL. The Virling script records them from the landing pageview, so checkout only needs the visitor ID.

Can I create the Checkout Session in Vue, without a backend?

No. Creating a session needs your Stripe secret key, and everything in a Vue bundle is public. Use a small endpoint or serverless function. If you do not want a backend, use a normal link to a Stripe Payment Link on a page that runs the script, and the script adds the visitor ID to it.

Should I use client_reference_id or metadata.virling_vid?

Either works. Virling reads metadata.virling_vid or client_reference_id on the session. Metadata leaves client_reference_id free for your own user or cart ID.

Why is the virling_vid cookie missing on my endpoint?

The usual reasons are a tag without data-dev on localhost, cookieless mode, a blocked script, or an API on another domain, where the browser does not send the cookie. In the last case send the ID in the request body instead.

What happens if the visitor ID is missing?

The session is created without it, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.
