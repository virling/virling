Wix revenue tracking: see which channel brings each sale

By Devendra Variya, co-founder of Virling. Published 2026-11-19.

To see which channel brought each sale from a Wix site, every payment needs an ID that points back to the visit. A Wix site that sells through a Stripe Payment Link, a LemonSqueezy or a Polar checkout link sends buyers to the provider's page, and that page never sees the UTM tags or the referrer of the visit that led there. Add the Virling script through Wix Custom code, keep your checkout links as they are, and connect the provider. The script adds a visitor ID to every checkout link by itself, so each sale shows the post, search or ad that brought it, with no code beyond the script.

Why a Wix site loses the source at checkout

A visitor lands on your Wix site from a search, a post or an ad, then clicks a button that opens buy.stripe.com, a lemonsqueezy.com checkout or buy.polar.sh. The visit and its source stay on your site; the payment happens on the provider's page. Your analytics can see the visit but not the payment, and the provider sees the payment but not where the visit came from. On a Stripe Payment Link, for example, the UTM tags on your page are dropped and the Checkout Session has no field for the referrer.

What joins the two is one ID that the checkout keeps and hands back with the payment. Each provider has its own field:

  • Stripe: buy.stripe.com links get client_reference_id, read from the Checkout Session.
  • LemonSqueezy: lemonsqueezy.com checkout links get checkout[custom][virling_vid], read from the webhook's custom data.
  • Polar: buy.polar.sh links get reference_id, read from the order's metadata.

Dodo Payments (checkout.dodopayments.com) links are tagged the same way. The full list is in the checkout docs.

Set up revenue tracking on a Wix site

Step 1: add the script through Custom code. In the Wix dashboard, open Settings, then Custom code under Advanced. Click Add Custom Code, paste the tag, choose All pages and Load code once, and place it in Head. The app shows the exact tag for your site:

<script defer src="https://app.virling.com/v.js" data-site="yourdomain.com"></script>

Apply, then publish the site. Custom code needs a premium plan and a connected domain, and it runs on the published site, not in the editor. Wix moves between pages without a full reload; the script counts each page change on its own. It records the referrer and UTM tags of every visit against a visitor ID in the first-party virling_vid cookie. Every step is in the framework setup docs.

Step 2: use plain checkout links. Set the link on your Wix button or text to the checkout URL from your provider, such as https://buy.stripe.com/abc123 or https://STORE.lemonsqueezy.com/checkout/buy/VARIANT_ID. Nothing else goes on the link. The script adds the visitor ID to every Stripe, LemonSqueezy and Polar checkout link when the page loads and again on click, and never replaces a parameter that is already there. The link must be a normal link: a checkout opened from an embed or from JavaScript is not tagged. How each link is tagged is in Link checkout to visits.

Step 3: connect the provider. In Virling, add your provider under Payment connections in site settings. Stripe takes a restricted key with Read access. LemonSqueezy takes an API key, and Virling registers a webhook on each of your stores, since LemonSqueezy only returns checkout custom data in webhooks. Polar takes an organization access token. Virling reads the visitor ID from each payment and credits it to the visit, under the attribution model you pick: last non-direct by default, or first touch or last touch. Setup for each provider is on the integrations page.

Step 4: make a test payment. Use test mode and a test checkout link, open your published Wix site from a tagged URL such as ?utm_source=test, and pay with a test card. Wait a minute for the next sync, and the payment shows the test source instead of Unattributed. The UTM builder makes tagged links for your real campaigns.

Wix Stores checkout is not supported

Virling does not connect to Wix as a payment source. Orders paid through Wix Stores checkout are not imported, so they never show up in Virling and cannot be joined to a visit. Revenue tracking on Wix works only for sales through a checkout link to a provider Virling connects to, such as a Stripe Payment Link or a LemonSqueezy or Polar checkout link.

When a Wix sale has no source

  • You tested in the editor or preview. Custom code does not run there, so links are not tagged. Test on the published site.
  • The link was opened off your site. Checkout links in emails, social posts or QR codes never pass through a page with the script, so they carry no visitor ID. Send people to your Wix site and let them click through from there.
  • The checkout is not a plain link. Embedded checkout widgets and buttons that open the URL from JavaScript are not tagged. Link the button to the checkout URL instead.
  • The link is on a custom checkout domain. Only the provider hosts above are tagged. For another domain, add the ID yourself from window.virling.vid().
  • Cookieless mode. With data-cookieless there is no visitor ID to pass, so new payments are Unattributed.

Frequently asked questions

Can Wix show which channel brought a sale?

Not for a sale through a checkout link. A Wix site sends buyers to a hosted checkout, and the checkout page never sees the referrer or UTM tags of the visit. With the Virling script added through Custom code, Stripe Payment Links, LemonSqueezy and Polar checkout links carry a visitor ID, and Virling joins each payment to the visit and its channel.

Which Wix plan do I need?

Custom code needs a premium plan and a connected domain. The script goes in through Custom code, so a free Wix site cannot run it.

Do I need code to track Stripe Payment Links on Wix?

No code beyond the script. Paste it into Custom code, place it in Head on all pages, and publish. The script adds client_reference_id with the visitor ID to every buy.stripe.com link on the page, and Virling reads it from the Checkout Session.

Does it work with Wix Stores checkout?

No. Wix Stores checkout is not a supported payment source, so orders paid in the Wix cart are not imported and cannot be joined to a visit. Sell through a Stripe Payment Link, a LemonSqueezy or a Polar checkout link instead.

Why does my Wix sale show as Unattributed?

The buyer did not click the link on the published site running the script: they opened it from an email, a social post or a QR code, or you tested in the Wix editor or preview, where custom code does not run. It also happens when the checkout opens from an embed instead of a plain link, when the link is on a custom checkout domain, or in cookieless mode.
