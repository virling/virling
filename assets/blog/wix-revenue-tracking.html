Wix revenue tracking: see which channel brings each sale

By Devendra Variya, co-founder of Virling. Published 2026-11-19, updated 2026-11-26.

Most Wix sites that sell a digital product or a service do it one of two ways: through Wix's own checkout (Wix Stores, a Pay Button, a Pay Link or a payment form), or through a button that opens a Stripe Payment Link or a LemonSqueezy or Polar checkout. Virling can only give a channel to the second kind. This post shows where the Virling tag goes in the Wix dashboard, how it copes with Wix's page changes, and exactly which Wix payment features stay invisible to it.

Add the tag in Wix Custom Code

Wix keeps site-wide scripts in the dashboard, not in the editor. Go to Settings, find Development & integrations and open Custom Code, then click + Add Custom Code. Paste the tag the Virling app shows for your site:

<script defer src="https://app.virling.com/v.js" data-site="yourdomain.com"></script>

Under Add Code to Pages pick All pages, which also covers pages you add later, and choose to load the code once per visit rather than on each page. Under Place Code in pick Head. Save and publish. Wix's custom code article asks for a published site with a connected domain before you start, so a site that only lives on a free Wix address has nowhere to run the tag. Put that connected domain in data-site; the framework setup docs list the same steps.

One Wix rule catches people later: snippets belong to a domain, and Wix deletes them if you assign a different domain to the site. After a domain change, open Custom Code and add the tag again.

Why once per visit is the right load setting

A Wix site often switches pages without loading a fresh document. The Virling script hooks the browser history, so it logs each of those page changes itself and keeps the referrer and UTM tags from the first page for the whole visit. Loading the snippet on every page would add a second copy on top. Checkout links that Wix draws after the first page still get the visitor ID, because the script tags links when the page loads and again at the moment of a click.

What the script writes on a Wix button

Give your Wix button an ordinary link to the checkout URL, such as https://buy.stripe.com/abc123, with no parameters of your own. When a visitor clicks it from the published site, the URL gains client_reference_id with their visitor ID. LemonSqueezy links gain checkout[custom][virling_vid], buy.polar.sh links gain reference_id, and checkout.dodopayments.com links gain metadata_virling_vid. A parameter you set yourself is never overwritten. Once the provider is connected under Payment connections in site settings, Virling reads that ID back from each payment and credits the sale to the visit: last non-direct by default, or first touch or last touch. Each connection is described on the integrations page.

Wix's own payment features

Virling has no Wix connection, so nothing Wix charges for itself arrives with a visitor ID. Feature by feature:

Wix featureWhat Virling seesWhy
Wix Stores cart and checkoutStore page visits onlyWix orders are not imported
Pay ButtonVisits onlyThe button opens the Wix checkout page, not a provider link
Wix Pay LinksVisits onlyThey point at Wix, not at a host the script tags
Payments in Wix FormsVisits onlyThe form hands off to the Wix checkout page
A checkout link or Stripe Buy Button inside Embed HTMLThe payment, as Unattributed, if the provider is connectedWix says its HTML and URL elements are iFrames, so the script on your page cannot reach the link

There is one partial exception. Wix lets you connect a Stripe account as its payment provider. If you connect the same Stripe account to Virling, the charges it finds there count toward revenue, but with no channel, because a Wix checkout never passes through a buy.stripe.com link. To get the channel for a product, create a Payment Link for it and put that link on a regular Wix button in place of the Pay Button or the embed.

Test it on the published Wix site

  1. In Custom Code, confirm the snippet is on, set to All pages and Head, and that the latest version of the site is published.
  2. Open a private window and visit https://yourdomain.com/?utm_source=test&utm_medium=test.
  3. The Virling dashboard lists the visitor under Visitors and adds test to the Channels card. Nothing there after a domain change usually means Wix removed the snippet.
  4. Click through your menu to a second page and check that the visit lists it once. Then click your checkout button: the checkout page address should carry client_reference_id for Stripe or virling_vid for LemonSqueezy. Pay with a test Payment Link and a Stripe restricted key starting rk_test_. Polar sandbox and Dodo Payments test links are not tagged, so use a small live payment and refund it.
  5. About a minute later, /app/yourdomain.com/payments shows the payment under test, and its Visitor under Details opens your test visit.

Test payments remain in reports after you move to a live key. For anything that does not match, see test your setup or the no-code guide.

Why a Wix sale shows as Unattributed

  • It was tested in the Wix editor or preview. Test on the published site with your connected domain instead.
  • The domain changed. Wix dropped the snippet along with the old domain, so no link was tagged.
  • The buyer never visited the site first. A Payment Link pasted into an email, a post or a QR code has no visitor ID. Link those to a Wix page.
  • The checkout sits in Embed HTML. The iFrame keeps the link out of the script's reach.
  • The sale went through Wix's checkout. Pay Buttons, Pay Links, Wix Forms payments and Wix Stores never produce a tagged link.
  • The link uses your own checkout domain, or data-cookieless is set. Only the provider hosts above are tagged, and cookieless mode has no visitor ID to pass. For a custom domain, read the ID from window.virling.vid() and add it yourself.

For what a Stripe Payment Link keeps and drops, see Stripe Payment Link UTM tracking. Other builders: Squarespace, Carrd and Webflow.

Frequently asked questions

Can Wix show which channel brought a sale?

Not for sales that leave Wix for a hosted checkout. Wix sees the visit and the provider sees the payment, but neither sees both. With the Virling tag in Custom Code, Stripe Payment Links and LemonSqueezy, Polar or Dodo checkout links carry a visitor ID, and Virling joins each payment to the visit and its channel.

What does Wix need before Custom Code works?

Wix asks for a published site with a connected domain. Custom code then runs on the live site, so a site on a free Wix address cannot run the tag.

Should the Virling tag load once per visit or on each page?

Once per visit, on all pages, in Head. The script follows Wix page changes by itself, so loading it on each page would add a second copy.

Does Virling track Wix Stores, Pay Buttons or Pay Links?

No. Virling does not import Wix orders, and these features open the Wix checkout page instead of a provider link the script can tag. Sell through a Stripe Payment Link or a LemonSqueezy or Polar checkout link on a normal Wix button to get the channel.

Why is my Wix sale Unattributed?

Usually the test ran in the editor or preview, the domain changed and Wix deleted the snippet, or the buyer opened the checkout link from an email or a post. A checkout inside Embed HTML, a custom checkout domain or cookieless mode also leave the sale without a channel.

What if Stripe is the payment provider for my Wix checkout?

If you connect that same Stripe account to Virling, the charges count as revenue but show as Unattributed, since a Wix checkout has no buy.stripe.com link to tag. A Payment Link on a regular Wix button gets the channel.
