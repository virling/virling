Track QR code sales: which printed codes bring paying customers

By Devendra Variya, co-founder of Virling. Published 2026-11-17.

To track QR code sales, encode a URL that carries UTM tags, with utm_source=qr and one campaign per printed placement, and point it at a page on your site rather than straight at checkout. Test every code with an iPhone and an Android camera before it goes to print, then read revenue per code in the Campaign tab. The scan count a QR service shows tells you how many phones opened a code, not which scans paid.

This guide is for businesses that print codes on packaging, receipts, menus, table cards, posters and event signs.

Why scans land in Direct

A phone camera opens the URL with no page before it, so an untagged scan, and the order after it, count as Direct. With no referrer, Virling reads utm_source, and qr puts the scan in Referral under its own campaign; the full rule order is in channels. The rest of this guide is about what only printed codes have: placements, redirects, cameras and checkout links.

Where codes get printed, and what each placement needs

  • Packaging and inserts. The buyer has already paid once, and the code sits in a cupboard or on a shelf for months. Send it to a reorder, refill or review page rather than the home page, and expect the response to show up as repeat orders. A 365-day lookback window in Site settings keeps late reorders credited to the scan.
  • Receipts. Narrow paper and small print make codes hard to read, so print at a size your receipt printer renders cleanly. Point it at something worth coming back for, such as a loyalty signup or the next order.
  • Events and booth signs. Codes are scanned from a distance and at an angle, so they need to be large, with strong contrast. Give the banner and the table card separate codes so each is its own row; revenue per conference or meetup covers the rest.
  • Menus and table cards. Most scans only want the menu, so sales are not the point. Give these codes their own campaign anyway, so menu scans do not blur the revenue of the codes that sell.
  • Posters and flyers. They go up where you cannot see who reads them and get reprinted often. Add the month to the campaign so each run is a new row.

Keep utm_source=qr and a fixed medium such as print on every code, and put the placement in utm_campaign, since the Campaign tab groups revenue by that value. Use cpc only for a code inside a paid print ad that you want counted with your other ads. The QR code generator with UTM tags builds the URL and draws the code in one step, and the UTM naming template keeps the values consistent across placements.

Static or dynamic codes, and why the redirect must keep UTM tags

A static code stores the final URL in its pattern. It depends on no service and never expires, but it cannot change after printing, and every character of a long tagged URL makes the pattern denser and harder to scan when small. A dynamic code stores a short redirect URL instead; the service forwards each scan to a target you can usually change later, and counts scans on the way.

With a dynamic code, the redirect target is what reaches your site, so set the target to the full tagged URL and scan it to see the tags arrive. A target saved as your plain home page sends every scan to Direct, however good the service's own scan report looks. The code also depends on that service: if it stops forwarding, for example when a subscription ends, every printed copy stops working.

A Virling tracked link is a redirect you host yourself. In the Campaign tab of the Channels card, click + Tracked link, pick QR code and enter the page. You get a short URL such as https://stats.example.com/l/35b6cac to encode with any generator, since Virling does not draw the code. Each scan is sent on with utm_source=qr, utm_medium=referral and the link's id as utm_campaign, and tags already on the page are kept. Unlike most hosted dynamic codes, its page cannot be changed later, so print only once the page is settled. Its clicks and visitors rarely match: clicks are counted at the redirect for all time, visitors by the script for the range you pick. See tracked links.

Test scans on iOS and Android cameras

Scan a printed proof, not the file on your screen, at the final size and on the final material:

  • iPhone. Point the Camera app at the code and tap the link it offers. The page opens in the default browser.
  • Android. Depending on the phone, the camera app or Google Lens reads the code. Try at least one phone that is not your own model, since makers handle codes differently.
  • On each phone, check that the page that opens still has its utm_ tags in the address, or that the short link landed on the tagged page. Then place a test order and confirm it appears on the Payments page under the code's campaign.
  • On the material. Curved bottles, glossy laminate, dark backgrounds and small receipt print fail more often than a flat proof. Leave a clear margin around the code, and scan from the distance people will really stand at.

Codes that point at a payment link

It is tempting to encode a Stripe, Polar, Dodo or LemonSqueezy payment link so the buyer lands straight in checkout. The script adds the visitor ID to those links only when they are normal links on a page that runs it, so a payment link opened from a camera carries none, and the payment is Unattributed. A Virling tracked link cannot target one either, because its page must be on your site.

Point the code at a short page on your site with a single buy button that uses the same payment link instead. The script adds the visitor ID when the button is clicked, such as client_reference_id on buy.stripe.com, so the payment is credited to the scan, at the cost of one extra tap. What to check when the numbers look wrong

  • Your QR service counts scans but Referral shows none. The dynamic code's target lost its tags. Scan it and read the address the phone opens.
  • A tracked link has clicks but no visits. A messaging app may have opened it for a preview, the page may not run the script, or a redirect on your site, such as / to /en, dropped the query string.
  • Payments from code buyers are Unattributed. The code opens a payment link directly. Reprint it pointing at a page on your site.
  • A buyer scanned, but the order is credited elsewhere. They scanned on a phone and paid on a laptop. The visitor ID belongs to one browser, so the laptop order has no link to the scan.
  • Visitors who block the script are not counted, so a code's real visitor number can be higher than any analytics tool shows.

For codes on postcards, catalogs and inserts sent by post, tracking revenue per mailing covers lists, offers and drop dates.

Frequently asked questions

How do I track sales from a QR code?

Encode a URL with utm_source=qr and the placement in utm_campaign, one code per placement, pointing at a page on your site that runs the script. Connect your store so each order carries the visitor ID, and read revenue per code in the Campaign tab.

Should I use a static or a dynamic QR code?

A static code holds the tagged URL itself and depends on no service, but cannot change and gets dense with long tags. A dynamic code holds a short redirect; if you use one, set its target to the full tagged URL so the tags reach your site.

Can a QR code point straight to a payment link?

It can, but the payment is not credited. A payment link opened from a camera carries no visitor ID, so the payment is Unattributed. Point the code at a page on your site with a buy button that uses the payment link, and the script adds the visitor ID on click.

Why is a scan on my phone not matched to a purchase on my laptop?

The visitor ID lives in the phone's browser, so a payment made on another device has no link to the scan. The payment is credited to a visit on the laptop if there is one inside the window. Otherwise it is Unattributed, unless you send the buyer's email as an identify event and the payment email matches.

How should I test a QR code before printing?

Print a proof at the final size on the final material, scan it with an iPhone camera and with an Android camera or Google Lens, and check that the page opens with its tags. Then place a test order and look for it on the Payments page under the code's campaign.
