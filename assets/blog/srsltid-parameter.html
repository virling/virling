srsltid parameter: what it is in a URL, and does it affect revenue reports?

By Devendra Variya, co-founder of Virling. Published 2026-11-25.

The srsltid parameter is a code that Google Merchant Center auto-tagging adds to the link when someone clicks one of your products on Google. It lets Merchant Center track what happens after the click, such as a purchase. It is not a UTM tag and it names no campaign. In Virling it changes nothing: the channel comes from the referrer and the UTM tags, and the page is stored without its query string. A report that lists full URLs can show the same page once per value.

What adds srsltid

Google’s help page says that when someone clicks a product on Google Search that leads to your online store, auto-tagging adds “a parameter called srsltid”, and its example ends in ?srsltid=123xyz (source: Google, About auto-tagging). It also says:

  • It is on by default for new accounts. So it can be there without anyone setting it up.
  • It measures free listings. The page says auto-tagging lets you check how well clicks on free listings and free local listings lead to activity such as purchases. These are reported in Merchant Center Analytics under Organic traffic.
  • It is only the first step. Auto-tagging alone does not turn on key event tracking. You also add a key event source, which is a Google Analytics property or a tag on your site.

A second page calls the same parameter a result id, and says key event tracking adds it after a customer clicks your free product listings (source: Google, Set up key event tracking in Merchant Center).

Where it appears

In the address of the page a shopper lands on, and wherever that address is copied. Free listings can show on Search, Images, Lens, YouTube, Gemini, the Shopping tab and a Business Profile (source: Google, free listings). The pages above do not list which of those add srsltid, so do not read the parameter as proof of the Shopping tab.

What it does not tell you

  • Not one code per click. Google says the result id is created at the time of an impression, and the same id is used again if a customer clicks the same free listings again (source: Google, key event tracking). Counting values does not count clicks.
  • Not a campaign. Google’s pages describe no way for you to turn the value into a product, a search or a campaign.
  • Not a paid click. Google describes it for free listings. A paid click from Google Ads can carry its own ID, gclid; see gclid, fbclid and msclkid vs UTM tags.

What Virling does with a srsltid visit

Virling does not read srsltid, and does not store it. The script sends the page address, and the server keeps the path, the five UTM tags (with ref standing in for a missing source) and the referrer’s host. Nothing in the channel rules looks for srsltid. With no UTM tags on the link, the result depends on the referrer:

An untagged Shopping ad with a Google referrer is Organic search too. The order follows the visit: in the default model, last non-direct, a Direct visit takes the credit only when the buyer had no other kind of visit inside the lookback window.

To see Shopping clicks apart, put your own UTM tags on the product links in your feed. If the link attribute has tracking parameters, Google recommends adding the canonical_link attribute (source: Google, link attribute). See Google Shopping revenue tracking for the tags, and Shopify UTM tracking for getting them joined to orders in a Shopify store.

Duplicate URLs in reports

A report that counts full URLs treats each value as a new page. Google Analytics has both kinds: page path and query string, and landing page and query string, keep what comes after the ? (source: Google, Analytics dimensions and metrics). Choose a dimension without it, or group by path in a spreadsheet.

This example is made up to show the arithmetic:

AddressVisitsRevenue
/products/oak-board?srsltid=EXAMPLE140$120
/products/oak-board?srsltid=EXAMPLE235$0
/products/oak-board25$180
One row by path: /products/oak-board100$300

Read by full URL, the second address looks like a page that never sells. Read by path, there is one page with 100 visits and $3.00 per visit. Virling stores the path only, so its landing page report shows the single row.

Canonical tags

To search engines, an address with srsltid is a second address for the same page. Google’s guide to duplicate URLs does not name srsltid, but its own example is a product link with a gclid. It calls rel="canonical" a strong signal for which URL to show, and recommends one on the clean page as well (source: Google, How to specify a canonical URL).

<link rel="canonical" href="https://example.com/products/oak-board">

Open a product page with ?srsltid=test added, view the source, and check that the canonical is still the clean address. The same guide says not to use robots.txt for canonicalization, and to link to the canonical URL within your site. A canonical tag does not change the address a visitor has open, so reports by full URL stay split.

On redirects, Google’s auto-tagging page says the GCLID must reach the final landing page for key events to be tracked. It does not name srsltid there, so the safe reading is to pass the whole query string on.

A redirect made in JavaScript has one more risk. If it sends the visitor to a clean address before the Virling script runs, the referrer on the new page is your own site, which is never counted as a source. A Google visit then becomes Direct.

For the last row, paste links into the free URL cleaner. It removes srsltid along with UTM tags and other click IDs, and keeps the parameters your page needs.

How to turn auto-tagging off

  1. In Merchant Center, open Settings in the left menu and choose General.
  2. Open the Key event setup tab.
  3. Turn Auto-tagging off.

These steps are from Google’s auto-tagging page. Two things to know first. Creating a new key event action turns auto-tagging on again (source: Google, key event tracking). And links that were already shared or saved keep the srsltid they have, so keep the canonical tag.

There is one case where Google tells you to turn it off: your site shows an error page when a link has a parameter it does not expect. Add ?srsltid=test to a product page and load it. If it fails, turn auto-tagging off, get the site to allow unknown parameters, then turn it back on.

Frequently asked questions

What is srsltid in a URL?

srsltid is a parameter that Google Merchant Center auto-tagging adds to the link when someone clicks a product on Google and goes to your store. Google also calls it a result id. It helps Merchant Center track key events such as purchases. It is not a UTM tag and names no campaign.

Does srsltid affect revenue reports?

Not in Virling. The channel comes from the referrer and the UTM tags, and the stored path leaves out the query string, so every srsltid version of a page is one landing page row. In a report that lists the full URL, such as page path and query string in Google Analytics, each value can be its own row.

Is a visit with srsltid paid or organic?

Google says auto-tagging in Merchant Center is for clicks on free listings and free local listings, which it reports as Organic. Virling does not read srsltid: with a google.com referrer and no UTM tags the visit is Organic search, and with no referrer it is normally Direct.

Should I remove srsltid from my URLs?

Not on arrival. A redirect that removes it can stop Merchant Center from tracking the sale, and it gains nothing in a report that ignores query strings. Set a canonical tag to the clean URL, and remove srsltid from links you copy and share.

How do I turn srsltid off?

In Merchant Center, open Settings, General, then the Key event setup tab, and turn Auto-tagging off. Google calls auto-tagging the first step in setting up key event tracking and says some browsers require it, so expect to lose key event data. Creating a new key event action turns it on again.

Is srsltid the same as gclid?

No. Google Ads auto-tagging adds gclid to clicks on ads, and Merchant Center auto-tagging adds srsltid to clicks on product listings. Neither one is a UTM tag, and Virling uses neither to pick a channel.
