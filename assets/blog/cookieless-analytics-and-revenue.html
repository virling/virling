Cookieless analytics and revenue: what you lose and keep

By Devendra Variya, co-founder of Virling. Published 2026-10-26, updated 2026-11-24.

Cookieless analytics keeps your visit counts but loses the link between a visitor and a payment. You can still see how much money came in. You can no longer see which channel it came from. There is also a mode in between, Until consent, which starts every visitor cookieless and sets the cookie only when they accept it.

What cookieless mode does

Instead of storing an ID in the browser, the server makes a visitor ID from a hash of the site, the IP address and the browser's user agent, mixed with a random salt. The salt changes every day and is never stored, so a returning visitor is recognised only within the same day, on the same network and browser. Even with a cookie, a second device is a new visitor; cross-device attribution explains what can be joined without cookies or fingerprinting.

What you keep

  • Page views, referrers and top pages
  • Sessions, because they only need 30 minutes of continuity
  • Revenue totals from your payment provider
  • No cookie, so no cookie banner for this tracking

What you lose

  • A returning visitor counts as new each day, so visitor totals run high
  • Two people behind one IP address with the same browser can count as one
  • Payments cannot be linked to visits, because there is no stable ID to pass into checkout. New payments show as Unattributed

Virling runs either way: cookieless, it shows visits by channel and your revenue total, and with the cookie it also credits payments to a channel when checkout carries the ID.

Until consent: cookieless first, cookie after a yes

In Virling, set Visitor cookie to Until consent in your site's settings, keep data-cookieless on the script tag, and call this from your consent tool when the visitor accepts:

virling("consent");

Before consent

Every visit is counted with the daily hash, exactly as in cookieless mode: page views, referrers, sessions and goals are recorded, and nothing is stored in the browser. A visitor who never answers the banner, or declines, stays counted this way.

On consent

The script asks your Virling server for the hash ID the visitor is counted under right now and stores it in the first-party virling_vid cookie, which lasts one year, or less where Safari ITP caps it. The visit already running continues as the same visitor and session, so it keeps the referrer and campaign it arrived with. The script never sets or renews the cookie by itself in this mode, and calling virling("consent") again on later pages does nothing once the cookie is there.

Your server can read the cookie at once. The script itself reads it when a page loads, so window.virling.vid() and the ID it adds to payment links start with the next page load. If you serve the script through your own proxy with data-api, forward GET requests to that path too.

What can be credited after it

  • Payments after consent, when checkout carries the ID. They can be credited to the visit that was running when the visitor accepted, to earlier visits that same day under the same hash, and to later visits with the cookie.
  • Not visits from earlier days without the cookie. Each was counted under a different hash. The hash also changes at midnight UTC and when the server restarts, so a visit that was under way then starts over with a new ID.
  • Not payments made without consent. No ID reached checkout, so they show as Unattributed and still count toward revenue.

The cookie holds the hash ID, so two people on one IP address with the same browser version who both accept on the same day share an ID.

When consent is withdrawn

Virling does not watch your consent tool. Delete the virling_vid cookie in its withdrawal callback. The cookie sits on your main domain with the path /, so delete it there. A page that is already open keeps the ID until it reloads; after that, the visitor is counted with the daily hash again. Deleting the cookie does not remove visits and payments already recorded.

The trade

If you want to know which channel earns money, you need a stable visitor ID, which means a first-party cookie and, depending on where your visitors live, consent. If you need to ask first, Until consent counts everyone and links payments only for the visitors who accept, so revenue by channel covers part of your buyers and the rest is Unattributed; cookie consent and revenue tracking shows how to measure that part. If you only want clean traffic stats and no banner, cookieless is the better fit. With the cookie, the ID still has to reach checkout when it runs on another domain; cross-domain checkout attribution shows how. Unattributed payments are a separate problem from a large Direct channel, which why Direct is your biggest traffic source explains.

Do it per site

Pick per site, not per company. A marketing site where you want revenue by channel can use the cookie, from the first page or after consent, and a docs site where you only want traffic can go cookieless. The steps are in cookieless mode and cookieless until consent, and privacy and consent covers when consent is needed. Frequently asked questions

Can I track revenue by channel without cookies?

Not per payment. Without a stable visitor ID there is nothing to pass into checkout, so payments show as Unattributed. Revenue totals still count. Until consent links payments from visitors who accept the cookie, and only those.

Is cookieless analytics less accurate?

For visitors, yes: a returning person counts as new each day. Page views and sessions are not affected.

Do I still need a cookie banner for cookieless analytics?

Cookieless mode sets no cookie, which removes the cookie banner for this tracking. Until consent sets one after a yes, so it needs a consent tool that asks. Check the rules where your visitors live.

Do I lose the first visit if the visitor accepts later?

Not if they accept during that visit: it continues as the same visitor and session, with the referrer it arrived with. If they accept on another day, the earlier visit stays counted but cannot be credited with a payment.

What happens to visitors who decline?

They are counted with the daily hash and no cookie is set. Their payments count toward revenue and show as Unattributed.

Can I send nothing at all before consent?

Yes. Leave the script tag off the page and add it from your consent tool's callback when the visitor accepts. Visits without consent are then not counted at all.
