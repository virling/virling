Next.js Dodo Payments UTM tracking: carry the visitor into checkout

By Devendra Variya, co-founder of Virling. Published 2026-11-23.

To tie each Dodo Payments sale from a Next.js app to the channel that brought the buyer, load the Virling script once with next/script and carry its visitor ID into checkout. Static payment links on checkout.dodopayments.com/buy/... need no code: the script adds the ID as metadata_virling_vid. If you create checkout sessions, read the virling_vid cookie in the route handler that calls client.checkoutSessions.create and set it in metadata. Virling reads metadata.virling_vid back from the payment and joins it to every visit behind it, with the UTM tags of each.

This post covers the App Router and the Pages Router. For what Dodo does with metadata outside Next.js, see the general guide to Dodo Payments UTM tracking. Using Stripe instead? See Next.js Stripe UTM tracking. Comparing providers? The steps for Creem are in Next.js Creem UTM tracking.

Why Dodo checkout loses your UTM tags

UTM tags live on the landing URL. By the time a visitor clicks Buy they are usually a few pages in, and checkout runs on Dodo's domain, which only stores the metadata you hand it. Passing one visitor ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too.

Step 1: add the script once

Use next/script with strategy="afterInteractive" and load it once, so it runs on every route. defer does nothing on next/script, so leave it out. Client-side navigation is counted too. If you self-host, replace app.virling.com with your Virling server.

App Router, in app/layout.tsx:

import Script from "next/script";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Script src="https://app.virling.com/v.js"
          data-site="yourdomain.com" strategy="afterInteractive" />
      </body>
    </html>
  );
}

Pages Router, in pages/_app.tsx:

import Script from "next/script";

export default function App({ Component, pageProps }) {
  return (
    <>
      <Script src="https://app.virling.com/v.js"
        data-site="yourdomain.com" strategy="afterInteractive" />
      <Component {...pageProps} />
    </>
  );
}

The script sets the first-party virling_vid cookie on your domain, records the UTM tags of each visit against it, and window.virling?.vid?.() returns the same ID in the browser.

Step 2a: payment links, no code

Keep the link to checkout.dodopayments.com/buy/... as a normal <a href> on a page that runs the script. When a visitor clicks it, the script adds metadata_virling_vid=<visitor ID> to the link, unless it is already there, and Dodo stores it as the payment's metadata.virling_vid. A plain <a href> or next/link both render a normal link:

<a href="https://checkout.dodopayments.com/buy/pdt_...">Buy now</a>

If you build the payment link URL in your own code instead, for example to pick a product, do it in a client component, since window.virling only exists in the browser, and add the parameter yourself on click:

// app/buy-button.jsx
"use client";

export default function BuyButton() {
  function buy() {
    const url = new URL("https://checkout.dodopayments.com/buy/pdt_...");
    const vid = window.virling?.vid?.();
    if (vid) url.searchParams.set("metadata_virling_vid", vid);
    location.href = url.href;
  }
  return <button onClick={buy}>Buy now</button>;
}

The same component works in the Pages Router without the "use client" line.

Step 2b: checkout sessions in a route handler

If your server creates the checkout session, the browser sends the virling_vid cookie with the request. Read it where you call client.checkoutSessions.create and set it in metadata:

// app/api/checkout/route.ts
import { NextRequest, NextResponse } from "next/server";
import DodoPayments from "dodopayments";

const client = new DodoPayments({ bearerToken: process.env.DODO_PAYMENTS_API_KEY });

export async function POST(req: NextRequest) {
  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: "pdt_...", quantity: 1 }],
    return_url: "https://yourdomain.com/thanks",
    metadata: { virling_vid: req.cookies.get("virling_vid")?.value },
  });
  // Send the customer to session.checkout_url
  return NextResponse.redirect(session.checkout_url, 303);
}

A plain form posts to it, and the browser sends the cookie along:

<form action="/api/checkout" method="POST">
  <button type="submit">Buy</button>
</form>

In the Pages Router, do the same in an API route under pages/api/, where the cookie is req.cookies.virling_vid, as in the Dodo Payments docs. If the cookie is missing, for example when the script is blocked, the session is created without a visitor ID and the payment counts as Unattributed.

Step 3: connect Dodo Payments

Create an API key in the Dodo Payments dashboard and paste it into Virling. Live mode and test mode keys both work: Virling tries the key against live mode first and test mode second, and remembers which one accepted it. It imports payments from the last 90 days on the first run, then new ones every minute. Refunds update the payment they belong to, and for subscriptions every paid payment after the first paid one is marked as a renewal. There is no webhook to add to your Next.js app. The full setup is on the Dodo Payments integration page.

Check that it works

  1. Connect a test mode key to Virling.
  2. In your app, put a test mode key in DODO_PAYMENTS_API_KEY, use a test mode product ID, and set environment: "test_mode" on the client. The SDK defaults to live mode, and API keys and products belong to one mode.
  3. Open a private window and visit a page that runs the script through a tagged link, such as https://yourdomain.com/?utm_source=test&utm_medium=email. Run window.virling.vid() in the browser console and note the ID. The script does nothing on localhost, so use your domain or a subdomain such as staging.yourdomain.com.
  4. In the same window, press Buy on the form that posts to your route handler and pay with one of Dodo's test cards.
  5. Wait a minute for the next sync, then open the payments list at /app/yourdomain.com/payments.

What the payment looks like: in the list it shows the test source and the Email channel of your tagged visit instead of Unattributed. Open it and Credited to shows the same, Journey starts at the tagged visit and ends with the Dodo Payments payment, and Details lists the ID from your browser console as Visitor.

The script adds the visitor ID by itself only to links on checkout.dodopayments.com, not to test links, so test through a checkout session or add metadata_virling_vid in your own code. Use a new email address for each test, because a later payment by the same customer is a renewal and keeps the first payment's channel. A site has one Dodo Payments connection, and test payments stay in your reports after you replace the key with a live one. The full checklist is in test your setup.

If the payment lists no visitor ID, checkout did not carry virling_vid: check that the page you bought from loads the script and, for checkout sessions, that the request to your route handler comes from the same domain, so the cookie is sent. Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Dodo Payments revenue by traffic source.

Common mistakes

Start from an Unattributed payment. Open it from /app/yourdomain.com/payments and look for Visitor under Details. If there is none, checkout did not carry the ID. The table lists what usually goes wrong in an App Router app.

SymptomCauseFix
No payment has a visitor ID, and every buyer gets the same checkoutclient.checkoutSessions.create runs in a GET handler with dynamic = "force-static", where cookies are empty and the response is cachedCreate it in a POST handler. Only GET handlers can be cached

The server action fails with cookies(...).get is not a functioncookies() is async, and Next.js 16 removed synchronous accessWrite (await cookies()).get("virling_vid")?.value
An error about cookies() inside use cacheCached functions cannot read cookiesRead the cookie outside the cached function, and do not cache the one that creates the checkout
A server action creates the checkout, but the buyer stays on the pageredirect() is inside a try block. It works by throwing an error, which your catch swallowsCreate the checkout inside try and call redirect() after it
The browser blocks the request to /api/checkout with a CORS errorA client component calls fetch(), which follows the redirect to Dodo's domain as a cross-origin requestPost a form as in step 2b, or return session.checkout_url as JSON and set location.href

Frequently asked questions

How do I pass UTM parameters to Dodo Payments checkout in Next.js?

Pass the Virling visitor ID instead. In the route handler that calls client.checkoutSessions.create, read the virling_vid cookie and set metadata: { virling_vid }. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

Do Dodo payment links in a Next.js app need code?

No. Keep the link to checkout.dodopayments.com/buy as a normal <a href> on a page that runs the script. The script adds metadata_virling_vid=<visitor ID> to it, unless it is already there, and Dodo stores it as the payment's metadata.virling_vid.

How do I add the visitor ID to a payment link I build in a client component?

Read it on click with window.virling?.vid?.() and, when there is a value, set metadata_virling_vid on the URL before you send the buyer to it. window.virling only exists in the browser, so the file needs "use client".

What happens if the cookie is missing?

The checkout is created without a visitor ID, for example when the script is blocked. The payment still counts toward revenue, as Unattributed.

Do I need a Dodo Payments webhook in my Next.js app?

No. Virling reads payments, refunds and subscriptions from the Dodo Payments API with an API key and checks for new payments every minute.

Can a server action create the Dodo checkout session?

Yes. Read the cookie with (await cookies()).get("virling_vid")?.value from next/headers, set it in metadata as virling_vid, and call redirect(session.checkout_url) outside any try block, because redirect works by throwing an error.
