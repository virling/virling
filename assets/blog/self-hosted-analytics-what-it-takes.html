Self-hosted analytics: server size, cost and upkeep

By Devendra Variya, co-founder of Virling. Published 2026-10-26.

Self-hosted analytics means the tracking and the data run on a server you control, not in a vendor's cloud. It costs a small server, an hour of setup and a little attention for upgrades and backups. The tool you pick changes that a lot: some need several databases, others run as one program. If you want a self-hosted Google Analytics alternative that also shows revenue by channel, Virling is open source on GitHub.

Why teams self-host analytics

  • Data stays with you: visits are stored on your server, under your domain, and are not shared with an ad network.
  • Fewer blocked scripts: a script served from your own subdomain is blocked less often than a well-known third-party one.
  • No per-event bill: you pay for the server, not for each pageview.
  • You can read the code: with open source you can check what is collected and change it.

What server you need

Less than most people expect. In a load test on 2026-10-31, Virling ran in a container limited to one vCPU and 1 GB of RAM:

  • 100,000 pageviews were ingested at 2,829 a second, with none failed and a p99 of 34 ms
  • Memory after the ingest was 157 MB
  • Dashboard queries on the demo data took 0.6 to 7.6 ms at the median

So a 1 vCPU, 1 GB server covers 100,000 pageviews a month with room to spare. The test script is in the repository, so you can run it on your own server. For other tools, ask the vendor for the same three numbers before you buy a bigger machine than you need.

The costs you can count

  • A server: a small virtual server is enough for a young site. Price it with the provider you already use
  • A domain: a subdomain such as stats.yourdomain.com, with HTTPS
  • Storage: events pile up. Ask how much disk a million page views takes

The costs people forget

  • Upgrades: who reads the release notes and updates it, and how often
  • Backups: where the data lives and how you copy it off the machine
  • Moving parts: each extra database is another thing to patch and watch
  • Downtime: events sent while the server is down are lost, so restarts should be short

Questions to ask before you pick

  • How many services does it need to run?
  • What is the smallest server it has been measured on?
  • Where is the data stored and how do I back it up?
  • Can I upgrade by changing one version number?
  • What happens if the server restarts?
  • Can it show which visits led to a payment, or only page views?

What it looks like with Virling

Virling is one program with its own embedded storage, so there is no separate database to run. You run it with Docker or a release binary, point a domain at it and keep one data folder. That folder holds the event database, the settings database and the key that encrypts your payment provider keys, so back them up together. Pin a version, read the changelog before you upgrade, and copy the folder on a schedule. The steps are in the Docker guide, the backup guide and the self-host page.

When hosted is the better choice

If nobody on your team wants to look after a server, use the hosted version. Self-hosting is free in money and costs time; hosting costs money and saves it. With an open-source tool you can start hosted and move to your own server later, or the other way round.

Frequently asked questions

What is self-hosted analytics?

Website analytics that runs on a server you control instead of the vendor's cloud. The tracking script sends visits to your own domain, and the data stays on your machine.

What server do I need to self-host analytics?

For Virling, one vCPU and 1 GB of RAM handled 100,000 pageviews a month in a load test, using 157 MB of memory. Tools that need several databases need more.

How much does it cost to self-host analytics?

A small server, a domain and some time. The software can be free; the real cost is the hours spent on upgrades and backups.

What should I back up?

The data folder. For Virling that is one folder holding the event database, the settings database and the secret key.

Is self-hosting analytics hard?

With a tool that runs as one program, it takes about an hour. Tools that need several databases take longer and need more upkeep.

Is self-hosted analytics GDPR friendly?

It helps, because visitor data never leaves your server. You still need a lawful basis and a privacy notice, so check with your own adviser.
