Nuxt Stripe UTM tracking: tie each payment to its source

By Devendra Variya, co-founder of Virling. Published 2026-11-22.

To see which traffic source each Stripe payment came from in a Nuxt app, add the Virling script to app.head in nuxt.config.ts, then read the virling_vid cookie in the server/api route that creates the Checkout Session and pass it as client_reference_id. Stripe keeps that one ID, and Virling joins the payment to every visit behind it, with the UTM tags of each. Two files change, and the rest of your checkout stays as it is.

This post covers Nuxt 3. For Payment Links, metadata limits and where the values show up in Stripe, see the general guide to Stripe Checkout UTM parameters.

Why Stripe Checkout loses your UTM tags

UTM tags live on the landing URL. Stripe Checkout runs on Stripe's domain and only stores what your server passes when it creates the session, so the tags of the visit are gone unless you carry them over. Passing one visitor ID instead of the tags keeps earlier visits and untagged ones, such as search and referrals, too. If the tags never reach your landing page at all, a redirect is usually dropping them; see UTM parameters lost after redirect.

Step 1: add the script to nuxt.config.ts

Add the tag to the app head in the Nuxt config. Nuxt renders it into the HTML of every page, and route changes are tracked through history.pushState, so client-side navigation is counted. If you self-host, replace app.virling.com with your Virling server.

// nuxt.config.ts
export default defineNuxtConfig({
  app: {
    head: {
      script: [
        { src: "https://app.virling.com/v.js", defer: true,
          "data-site": "yourdomain.com" },
      ],
    },
  },
  runtimeConfig: {
    stripeSecretKey: "", // set NUXT_STRIPE_SECRET_KEY
  },
});

The script sets the first-party virling_vid cookie on your domain and records the UTM tags of each visit against it. The runtimeConfig entry keeps your Stripe secret key on the server.

Step 2: create the Checkout Session in a server/api route

Your server receives the virling_vid cookie with every request from the browser, and getCookie reads it from the event. Read it in the route that creates the session and pass it as client_reference_id:

// server/api/checkout.post.ts
import Stripe from "stripe";

export default defineEventHandler(async (event) => {
  const stripe = new Stripe(useRuntimeConfig(event).stripeSecretKey);
  const session = await stripe.checkout.sessions.create({
    client_reference_id: getCookie(event, "virling_vid"),
    line_items: [{ price: "price_...", quantity: 1 }],
    mode: "subscription",
    success_url: "https://yourdomain.com/thanks",
  });
  return sendRedirect(event, session.url!, 303);
});

A plain form posts to it, and the browser sends the cookie along:

<!-- pages/pricing.vue -->
<template>
  <form method="POST" action="/api/checkout">
    <button type="submit">Buy</button>
  </form>
</template>

Or return the URL to the page, with metadata

If you would rather start checkout from a click handler, return the session URL as JSON and navigate to it. If client_reference_id already holds your own user or cart ID, put the visitor ID in the session's metadata.virling_vid instead. Virling reads either:

// server/api/checkout-url.post.ts
import Stripe from "stripe";

export default defineEventHandler(async (event) => {
  const stripe = new Stripe(useRuntimeConfig(event).stripeSecretKey);
  const vid = getCookie(event, "virling_vid");
  const session = await stripe.checkout.sessions.create({
    // client_reference_id stays free for your own ID
    metadata: vid ? { virling_vid: vid } : {},
    line_items: [{ price: "price_...", quantity: 1 }],
    mode: "subscription",
    success_url: "https://yourdomain.com/thanks",
  });
  return { url: session.url };
});

Call it from the page. $fetch runs in the browser here, so the cookie goes with the request:

<!-- pages/pricing.vue -->
<script setup lang="ts">
async function buy() {
  const { url } = await $fetch("/api/checkout-url", { method: "POST" });
  await navigateTo(url!, { external: true });
}
</script>

<template>
  <button type="button" @click="buy">Buy</button>
</template>

The full lookup order, including PaymentIntents you create for Elements, is in the Stripe docs and on the Stripe integration page. The checkout snippet generator writes the same call for other providers.

Check that it works

Make a test payment from a page that runs the script, wait for the next sync, and open the payments list at /app/yourdomain.com/payments. The payment should show a channel instead of Unattributed. Open it to see its journey. If it still shows Unattributed, check that the page you bought from loads the script and that the request goes to your own domain, so the cookie is sent.

Payments without a visitor ID still count toward revenue, as Unattributed. How the join works from visit to payment is in how to track Stripe revenue by traffic source, and the SaaS page shows what you get per channel. On other frameworks, see Next.js and SvelteKit.

Frequently asked questions

How do I pass UTM parameters to a Stripe Checkout Session in Nuxt?

Read the visitor ID from the virling_vid cookie with getCookie in a server/api route, and pass it as client_reference_id when you create the session. The Virling script records the UTM tags of every visit against that ID, so the payment is joined to all of them.

How do I read the virling_vid cookie in a Nuxt server route?

Call getCookie(event, "virling_vid") inside defineEventHandler. Both are auto-imported in the server directory. It is a first-party cookie on your domain, so the browser sends it with every request to your app, including $fetch calls from the page.

Should I use client_reference_id or metadata.virling_vid?

Use client_reference_id unless it already holds your own user or cart ID. In that case put the visitor ID in the session's metadata.virling_vid. Virling reads either.

What happens if the cookie is missing?

The session is created without a visitor ID, for example when the script is blocked or runs in cookieless mode. The payment still counts toward revenue, as Unattributed.

Do Stripe Payment Links in a Nuxt app need code?

No. Use a normal link to buy.stripe.com on a page that runs the script. The script adds client_reference_id to the link when the page loads and again on click, unless the link already has one.

Is client-side navigation in Nuxt counted?

Yes. With the script in app.head of nuxt.config.ts it is rendered into every page, and route changes made by the Nuxt router are tracked through history.pushState.
