Cal.com UTM tracking: which channel books calls that pay

By Devendra Variya, co-founder of Virling. Published 2026-11-25.

For Cal.com UTM tracking, add the tags to your booking link after a ?, or pass them in the embed code. Cal.com stores them with the booking. It does not say which calls became paid invoices. For that, the booking has to be joined to the payment.

Cal.com facts here come from its help pages, linked below and read on 2026-11-25. Steps they do not cover are left out. Virling does not connect to Cal.com. The join below uses your own page and server.

Step 1: tag a Cal.com booking link

Cal.com tracks utm_source, utm_medium, utm_campaign, utm_term and utm_content with no setup (source: Cal.com, UTM parameter tracking):

https://cal.com/YOUR_NAME/30min?utm_source=newsletter&utm_medium=email&utm_campaign=october-launch

Any other name needs a hidden booking question of type Short Text, not required, with the name as its identifier. The free UTM builder makes tags you can reuse.

A direct link has one cost: the page is on cal.com, so your script does not run there. A person who goes from your email straight to Cal.com makes no visit to your site. If you want revenue per channel, send them to a page of yours first.

Step 2: add the visitor ID to links on your site

Put the Virling script on every page of your site and leave cookieless mode off, or there is no visitor ID to pass. Then add a hidden Short Text question with the identifier virling_vid to the booking form. Cal.com prefills a question from a URL parameter with the same identifier (source: Cal.com, pre-fill fields). This code adds the ID and the tags to each Cal.com link on the page:

<script>
addEventListener("load", function () {
  var query = new URLSearchParams(location.search);
  var vid = window.virling?.vid?.();
  document.querySelectorAll('a[href^="https://cal.com/"]').forEach(function (a) {
    var link = new URL(a.href);
    ["utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term"].forEach(function (k) {
      var value = window.leadUtm ? leadUtm.tags[k] : query.get(k);
      if (value) link.searchParams.set(k, value);
    });
    if (vid) link.searchParams.set("virling_vid", vid);
    a.href = link.href;
  });
});
</script>

leadUtm comes from the snippet in UTM parameters in hidden form fields, which goes on every page and remembers the tags. Without it, the code reads only the address of the current page, so a visitor who lands on one page and books on another loses them.

Step 3: tag an embed

Cal.com gives two ways. You can pass the tags in the config of an inline, popup or floating button embed (source: Cal.com, UTM tracking in embeds). Or you can turn on forwarding, right after the code from the embed snippet generator (source: Cal.com, auto-forwarding query parameters):

<script>
  Cal.config = Cal.config || {};
  Cal.config.forwardQueryParams = true;
</script>

Forwarding is off by default and sends every parameter in the page address as it is, so do not use it on pages whose addresses hold anything private. Cal.com says it does not work on Framer. It also sees only the booking page’s own address. The config way can use remembered tags, and can carry the visitor ID as metadata.

Cal.com documents metadata[myKey] in the embed config: the value arrives in the webhook as payload.metadata["myKey"] and is not shown on the booking details page (source: Cal.com, prefill booking form in embed). Keep the loader and init lines of your own snippet, and replace its inline call with this. 30min stands for your namespace, which the generator derives from the event type:

<div id="my-cal-inline"></div>
<script>
addEventListener("load", function () {
  var query = new URLSearchParams(location.search), config = {};
  ["utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term"].forEach(function (k) {
    var value = window.leadUtm ? leadUtm.tags[k] : query.get(k);
    if (value) config[k] = value;
  });
  var vid = window.virling?.vid?.();
  if (vid) config["metadata[virling_vid]"] = vid;
  Cal.ns["30min"]("inline", {
    elementOrSelector: "#my-cal-inline",
    calLink: "YOUR_NAME/30min",
    config: config
  });
});
</script>

An embed is a frame from another domain, so it cannot read the virling_vid cookie. Cal.com knows the visitor ID only if you pass it. Cal.com documents metadata for embeds, not for plain links, which is why step 2 uses a hidden question.

Step 4: see the tags and record a goal

Make a test booking from a tagged link, then open its booking details page while logged in. Only the hosts of the booking can see the tags and the hidden answers (source: Cal.com, UTM parameter tracking).

To count bookings in Virling, send a goal when the embed reports one. bookingSuccessfulV2 fires on a fresh booking, which might not be confirmed yet (source: Cal.com, embed events). Put this in the same load function:

Cal.ns["30min"]("on", {
  action: "bookingSuccessfulV2",
  callback: function () { window.virling?.("goal", "booking"); }
});

The properties listed for that event include no email, so the goal cannot do the join. A redirect after booking does carry the email in the address, because Forward parameters is on by default (source: Cal.com, booking success redirect parameters). Addresses stay in browser history and server logs, so turn it off if your page does not need it.

Step 5: join the booked call to the payment

A booked call is not a sale. The call and the contract leave no visit, and an invoice you send from Stripe carries no visitor ID. Virling matches that invoice by email, so it needs the email and the visitor ID together, before the payment.

With a webhook

In Cal.com, open /settings/developer/webhooks, subscribe your server to Booking Created and set a secret. Check the X-Cal-Signature-256 header, an SHA-256 HMAC of the body made with that secret (source: Cal.com, webhooks). Then send one identify event. Here body is the parsed webhook. An embed booking has the ID in metadata, and a link booking has it under the question’s identifier, which Cal.com uses in webhook payloads (source: Cal.com, booking questions):

const p = body.payload;
const vid = p?.metadata?.virling_vid || p?.responses?.virling_vid?.value;
const email = p?.responses?.email?.value;
if (body.triggerEvent === "BOOKING_CREATED" && vid && email) {
  await fetch("https://app.virling.com/api/event", {
    method: "POST",
    headers: { "User-Agent": "booking-webhook/1.0" },
    body: JSON.stringify({ n: "identify", u: "https://yourproduct.com/", s: "yourproduct.com", v: vid, m: email }),
  });
}

The webhook examples show no UTM fields, so read the tags on the booking details page.

Without a server

Ask for the work email in a short form on your own page, send the identify event from there, then show the calendar. The code is in demo booking revenue tracking.

When the invoice is paid

Virling keeps only a SHA-256 hash of the trimmed, lowercased email with a salt of your site. A later Stripe payment with no visitor ID and the same payer email, from the billing details or the receipt, is credited to that visitor and shows Matched by email. If the deal closes in a Checkout Session your server creates instead, pass the ID as client_reference_id or metadata.virling_vid, and no email is needed. Renewals follow the channel of the customer’s first payment.

Set the lookback window longer than your sales cycle: 30, 60, 90 or 365 days, with 90 as the default. Name the email and the visitor ID in your privacy policy. The full setup is in the sales-led B2B guide, and the matching is explained in Stripe invoice attribution.

A made-up example: bookings, calls held and revenue

These numbers are invented to show the method. One quarter of booked calls, and the invoices those calls led to:

Made upBookingsCalls heldPaid revenueRevenue per call held
Paid5025$3,000$120
Organic search2016$9,600$600
Email1512$4,800$400
All8553$17,400about $328

Paid brought 50 of the 85 bookings, but half were not held, and the calls that were held brought $3,000. Organic search brought 20 bookings, 16 were held, and they brought $9,600. Counted by bookings, Paid looks best. Counted by money it is last, at $60 per booking against $480 for Organic search and $320 for Email. Two things went wrong for Paid: people did not turn up, and the calls that were held brought less each. The first may be worth fixing before the campaign is cut.

Calls held come from your calendar, not from Virling. Cal.com sends Booking No-show Updated when someone is marked on the /bookings/past page. Do not use Meeting Ended for this: it fires at the scheduled end time (source: Cal.com, webhooks). Few deals make a shaky ranking, so wait until most have had time to close. To turn a close rate and a deal size into what one booking is worth, use the lead value calculator.

Read it in Virling

Click a channel on the Channels card, read its revenue, then open the Goals tab for its booking count. Divide one by the other yourself. A goal belongs to the visit it happened in, while revenue follows your attribution model, so the two can sit in different channels for one buyer.

What still cannot be joined

  • A booking from a link outside your site. No visit, so no visitor ID.
  • A different payer. Email matching is exact. An accounts team paying from its own address does not match.
  • A payment synced before the identify. Send it at the booking, not after the deal closes.
  • Blocked scripts. With no visitor ID, the booking still goes through, but nothing is joined.

Those payments still count toward revenue, as Unattributed. If you use Calendly, the same join is in Calendly UTM tracking.

Frequently asked questions

How do I add UTM parameters to a Cal.com link?

Put a question mark after the booking link, then the tags joined with an ampersand, such as ?utm_source=newsletter&utm_medium=email&utm_campaign=october-launch. Cal.com stores the five standard tags with the booking, with no setup.

Where do I see UTM data in Cal.com?

On the booking details page, when you are logged in. Cal.com says only the hosts of the booking can view the UTM parameters and the answers to hidden booking questions.

Do UTM tags work in a Cal.com embed?

Yes, but not by default. Pass them in the config of the embed code, or set Cal.config.forwardQueryParams to true, which forwards every parameter in the address of the page, not only the UTM tags.

Does Virling connect to Cal.com?

No. Virling never sees your calendar or your bookings. It sees the visit to your page, the goal your page sends, the email your server sends in an identify event, and the payment from your provider.

How do I join a Cal.com booking to a Stripe invoice?

Pass the Virling visitor ID with the booking. When the Cal.com webhook arrives, your server sends that ID and the email to Virling in an identify event. A later Stripe invoice paid with the same email is credited to that visitor.
