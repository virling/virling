Webflow analytics revenue: track Stripe sales by channel

By Devendra Variya, co-founder of Virling. Published 2026-11-19.

To see which channel brought each sale from a Webflow site, every payment needs an ID that points back to the visit. A Webflow site often sells through a hosted checkout link, such as a Stripe Payment Link, and the checkout page never sees the UTM tags or the referrer of the visit that led there. Paste the Virling script into your Webflow site settings, keep your Stripe, Polar, Dodo or LemonSqueezy checkout links as they are, and connect the provider. The script adds a visitor ID to every checkout link by itself, so each sale shows the channel that brought it, with no code beyond the script.

Why Webflow analytics stop at the checkout link

A visitor lands on your Webflow page from a search, a post or an ad, then clicks a button that opens buy.stripe.com or another hosted checkout. The visit and its source stay on your site; the payment happens on the provider's page. Your analytics can see the visit but not the payment, and the provider sees the payment but not where the visit came from. On a Stripe Payment Link, for example, the UTM tags on your page are dropped and the Checkout Session has no field for the referrer.

What joins the two is one ID that the checkout keeps and hands back with the payment. For Stripe that is client_reference_id; each provider has its own field:

  • Stripe: buy.stripe.com links get client_reference_id, read from the Checkout Session.
  • Polar: buy.polar.sh links get reference_id, read from the order's metadata.
  • Dodo Payments: checkout.dodopayments.com links get metadata_virling_vid, read from the payment's metadata.
  • LemonSqueezy: lemonsqueezy.com checkout links get checkout[custom][virling_vid], read from the webhook's custom data.

Set up Stripe tracking on a Webflow site

Step 1: add the script in Webflow site settings. In Webflow, open Site settings, then Custom code. Paste the tag into Head code so it loads on every page. Custom code needs a paid site plan. The app shows the exact tag for your site:

<script defer src="https://app.virling.com/v.js" data-site="yourdomain.com"></script>

Publish the site to your domain. Custom code runs on the published site, not in the Designer. The script records the referrer and UTM tags of every visit against a visitor ID in the first-party virling_vid cookie. Every step is in the framework setup docs.

Step 2: use plain checkout links. Set the link on your Webflow button or link block to the checkout URL from your provider, such as https://buy.stripe.com/abc123. Nothing else goes on the link. The script adds the visitor ID to every Stripe, Polar, Dodo and LemonSqueezy checkout link when the page loads and again on click, and never replaces a parameter that is already there. The link must be a normal link: a checkout opened from an embed or from JavaScript is not tagged.

Step 3: connect the provider. In Virling, add your provider under Payment connections in site settings. Stripe takes a restricted key with Read access; Polar, Dodo and LemonSqueezy take an API key or access token. Virling reads the visitor ID from each payment and credits it to the visit, under the attribution model you pick: last non-direct by default, or first touch or last touch. The Stripe setup is on the Stripe integration page.

Step 4: make a test payment. Use test mode and a test checkout link, open your published Webflow site from a tagged URL such as ?utm_source=test, and pay with a test card. Wait a minute for the next sync, and the payment shows the test source instead of Unattributed. The UTM builder makes tagged links for your real campaigns.

When a Webflow sale has no source

  • You tested in the Designer. Custom code does not run there, so links are not tagged. Test on the published site.
  • The link was opened off your site. Checkout links in emails, social posts or QR codes never pass through a page with the script, so they carry no visitor ID. Send people to your Webflow page and let them click through from there.
  • The checkout is not a plain link. Embedded checkout widgets and buttons that open the URL from JavaScript are not tagged. Link the button to the checkout URL instead.
  • The sale went through Webflow's own cart. The script only tags links to the checkout hosts above, so orders from the built-in Webflow Ecommerce checkout carry no visitor ID. Sell through a checkout link instead.
  • The link is on a custom checkout domain. Only the provider hosts above are tagged. For another domain, add the ID yourself from window.virling.vid().
  • Cookieless mode. With data-cookieless there is no visitor ID to pass, so new payments are Unattributed.

Frequently asked questions

Can Webflow analytics show revenue?

Webflow's analytics can count the visit, but a sale through a hosted checkout link happens on the provider's page, which they do not see. To see revenue by channel, the payment has to carry an ID that joins it to the visit. With the Virling script in Webflow custom code, Stripe, Polar, Dodo and LemonSqueezy checkout links carry that ID by themselves.

How do I track Stripe sales from Webflow?

Paste the script into Head code under Site settings, Custom code, and publish. Link your buttons to your Stripe Payment Links as they are. The script adds client_reference_id with the visitor ID to every buy.stripe.com link on the page, and Virling reads it from the Checkout Session once you connect Stripe with a restricted key.

Do I need a paid Webflow plan?

Yes for the script. Webflow only runs custom code in Head code on a paid site plan, and the script has to run on the page that holds the checkout link.

Why does my Webflow sale show as Unattributed?

The buyer did not click the link on a published page running the script: they opened it from an email, a social post or a QR code, or you tested in the Webflow Designer, where custom code does not run. It also happens when the checkout opens from an embed instead of a plain link, when the link is on a custom checkout domain, or in cookieless mode.

Which checkout links are tagged?

Links to buy.stripe.com, buy.polar.sh, checkout.dodopayments.com and any lemonsqueezy.com checkout. Links to other providers are left alone, and a parameter that is already on a link is never replaced.
