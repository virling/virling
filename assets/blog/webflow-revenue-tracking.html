Webflow analytics revenue: track Stripe sales by channel

By Devendra Variya, co-founder of Virling. Published 2026-11-19, updated 2026-11-26.

Webflow sites sell in two ways: a button that sends the buyer to a hosted checkout such as a Stripe Payment Link, or Webflow Ecommerce with its own cart. Virling gives the first kind a channel with no code beyond one tag in your Webflow custom code. The tag keeps a visitor ID for each visit and appends it to Stripe, Polar, Dodo and LemonSqueezy checkout links, and the provider returns it with the payment. Webflow Ecommerce is a different case, explained below. For why a hosted checkout loses the referrer and UTM tags at all, see Stripe Payment Link UTM tracking.

Site custom code or page custom code

Webflow has two places for code. Site settings, Custom code holds Head code and Footer code that load on every page. Each page's own settings also have a custom code box, but that code runs on that page only, and on a Collection template it runs on every item of that one collection. Put the Virling tag in the site-wide Head code; visitors arrive on blog posts, landing pages and CMS items alike, and a page without the tag hands the checkout no ID. Copy the tag from the Virling app:

<script defer src="https://app.virling.com/v.js" data-site="yourdomain.com"></script>

Webflow only allows custom code on a paid Site plan or certain paid Workspace plans, and saved code reaches visitors only after a publish. Payment Links themselves need no Ecommerce plan: Webflow says they work on any paid site plan. The framework setup docs list the steps too.

Webflow Ecommerce checkout

Virling cannot read Webflow Ecommerce orders. It has no Webflow connection, and the Webflow cart and checkout pages contain no link the script can tag, so no order carries a visitor ID. The script still counts visits to your product, cart and checkout pages, but the order itself gets no channel. If those orders are charged through the same Stripe account you connect to Virling, Virling imports each charge as revenue, marked Unattributed.

To get the channel for a product, sell it through a Stripe Payment Link or another supported checkout link on a normal Webflow button instead of the Ecommerce cart.

Worked example: a Webflow CMS button linking to checkout

  1. Add a Link field named Checkout link to your Products (or Courses) collection, and paste each item's Payment Link into it, such as https://buy.stripe.com/abc123.
  2. On the Collection template page, or inside a Collection list, select the Buy button. In its link settings choose the URL option, then Get URL from the collection and pick Checkout link.
  3. Publish to your domain. A visitor comes from yourdomain.com/courses/intro?utm_source=youtube; the script records the visit and stores its ID in the first-party virling_vid cookie.
  4. The bound button now points to https://buy.stripe.com/abc123?client_reference_id= plus that ID. Each item's button gets its own Payment Link with the same ID, and a link that already has client_reference_id is left as it is.
  5. The visitor pays. Stripe stores the ID on the Checkout Session, Virling imports the charge, reads the ID from that session and credits the sale to youtube, using your attribution model: last non-direct unless you pick first touch or last touch.

Connect Stripe under Payment connections in site settings with a restricted key that has Read access; the Stripe integration page walks through it. Polar, Dodo and LemonSqueezy links in the same field work the same way once their provider is connected.

Test it on the published domain

  1. In the Publish menu, tick your custom domain as well as the staging address, then publish.
  2. Open https://yourdomain.com/?utm_source=test&utm_medium=test in a private window.
  3. In Virling, the visitor appears under Visitors and test on the Channels card. If not, check that the tag is in site-wide Head code and that the domain was ticked.
  4. Before you click, right-click your Buy button and copy the link. A Stripe link should end in client_reference_id= and an ID. Then click it and pay. For Stripe, connect a test restricted key (rk_test_) and use a test Payment Link. Polar sandbox and Dodo Payments test links do not carry the ID, so make one small live payment there and refund it.
  5. After about a minute, open /app/yourdomain.com/payments. The payment should say test, and its Visitor under Details leads back to your visit.

Why a Webflow sale shows as Unattributed

  • The domain was not ticked. Webflow publishes only to the domains ticked in the Publish menu, so the tag can be live on staging and missing on your domain.
  • The test ran on webflow.io or in preview. Virling records only the domain in data-site. The staging subdomain and the canvas.webflow.com preview are other hosts, so visits there are not recorded.
  • The tag is in one page's settings. Buyers who land on any other page have no ID. Move it to site-wide Head code.
  • The buyer used the Ecommerce cart. Those orders carry no visitor ID, as above.
  • The checkout link was opened elsewhere. A Payment Link sent by email, posted on social or printed as a QR code never passes through your site.
  • The link points to your own checkout domain or opens from JavaScript. Only the four provider hosts are tagged; for others, read window.virling.vid() and add the ID yourself.
  • Cookieless mode is on. data-cookieless drops the visitor ID, so new sales cannot be joined to a visit.

Frequently asked questions

Can Webflow analytics show revenue by channel?

Not for sales on a hosted checkout, because the payment happens on the provider's page. Virling puts a visitor ID on your checkout links and reads it back from each payment, so every sale shows the channel of the visit behind it.

Should the script go in site or page custom code?

Site custom code, in Head code. Page custom code runs on that page only, so visitors who enter anywhere else would reach checkout without an ID.

Does Virling track Webflow Ecommerce orders?

No. Virling has no Webflow connection and Webflow's cart carries no visitor ID, so those orders get no channel. If they are charged through a Stripe account you connected, they count as Unattributed revenue. Sell through a Payment Link on a normal button to get the channel.

Can a CMS button link to a different checkout per item?

Yes. Store each item's checkout link in a Link field and bind the button to it. The script tags the bound link like any other, on page load and on click.

Do I need a paid Webflow plan?

Yes, for the script. Custom code needs a paid Site plan or one of the paid Workspace plans Webflow lists. Payment Links do not need an Ecommerce plan.

Why is my Webflow sale Unattributed?

Usually the custom domain was not ticked at publish, the test ran on webflow.io or in preview, or the tag sits in one page's settings. Checkout links opened from emails or posts, the Ecommerce cart, embeds, custom checkout domains and cookieless mode also leave the sale without a channel.
