How to track Shopify revenue by traffic source

By Devendra Variya, co-founder of Virling. Published 2026-11-12.

To track Shopify revenue by traffic source, give each visitor an ID, store it on the cart so Shopify copies it onto the order, and join each order back to the visits that came before it. Shopify knows who ordered and how much. It does not know which page or channel brought them, and many orders end up as Direct.

Step 1: set a visitor ID

Your analytics script sets one first-party ID per visitor and remembers the first source: referrer, UTM tags or direct. Put the script in your theme so it runs on every page of the store, and on any blog or landing page that links to it.

Step 2: store the ID on the cart

Shopify copies cart attributes onto the order as note attributes. So add a small snippet to theme.liquid, after the analytics script, that reads the visitor ID and posts it to /cart/update.js as a cart attribute. Now every order carries the visitor who placed it. If the snippet can run before the analytics script has loaded, run it on the page load event, or the value will be empty.

Step 3: read orders and join them to visits

Read paid orders from Shopify with a token that can only read orders, then match each order's visitor ID to that visitor's earlier visits. Credit one of them with a rule you keep fixed (see first touch or last touch).

Step 4: handle refunds and renewals

Two things change the numbers after the first order. Refunds lower an order's revenue, so a channel that looks good on day one can shrink later. Orders from a subscription renewal carry no cart attribute of their own, so they should keep the channel of the customer's first payment instead of landing in Direct.

Step 5: report revenue per channel

Group the joined orders by channel and divide by visitors to get revenue per visitor. That is the table that tells you where to spend time and ad budget.

What goes wrong

  • Skipping step 2: orders arrive with no visitor ID and fall into Direct
  • Running the snippet before the analytics script has loaded, so the cart attribute is empty
  • Draft, POS and staff-created orders, which have no web visit and so no visitor ID
  • Counting only paid orders and ignoring refunds, which overstates a channel

Frequently asked questions

Can Shopify show which traffic source an order came from?

Only partly. Shopify's own reports show a source for some orders, and many land in Direct. For a view you control, store a visitor ID on the cart and join each order to that visitor's earlier visits in your analytics.

Where do I put the visitor ID in Shopify?

On the cart, as an attribute. Shopify copies cart attributes onto the order as note attributes, so the order carries the visitor ID. A short snippet in theme.liquid, after your analytics script, does it.

Which channel do Shopify subscription renewals get?

An order from a Shopify Subscriptions renewal is marked as a renewal and keeps the channel of the customer's first payment.

How far back does the first import go?

Virling imports the last 60 days of orders on the first run, the most Shopify gives without the read_all_orders permission, then new orders every minute.
