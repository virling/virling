How to track LemonSqueezy revenue by traffic source

By Devendra Variya, co-founder of Virling. Published 2026-11-09.

To track LemonSqueezy revenue by traffic source, give each visitor an ID, pass it to LemonSqueezy as checkout custom data, and join each order back to the visits that came before it. LemonSqueezy knows who paid and how much. It does not know which page or channel they came from.

Step 1: set a visitor ID

Your analytics script sets one first-party ID per visitor and remembers the first source: referrer, UTM tags or direct. Put the script on the pages that link to checkout, not only on the checkout itself.

Step 2: send the ID to LemonSqueezy at checkout

LemonSqueezy checkouts accept custom data. Pick the option that matches how you sell:

  • Checkout links: add the ID to the link as checkout[custom][name]=value
  • Checkouts you create on your server: when you call POST /v1/checkouts, set data.attributes.checkout_data.custom to an object holding the ID from the visitor's cookie

If your link is built before the analytics script has loaded, the value will be empty, so wait for the script first.

Step 3: catch the custom data in a webhook

This is the step that surprises people. LemonSqueezy only returns checkout custom data in webhooks. Reading orders from the API is not enough, because the ID will not be there. Register a webhook for order_created and subscription_payment_success, check each request's X-Signature against your signing secret, and attach the ID to the order or invoice it came with. The webhook address must be a public https:// URL that LemonSqueezy can reach.

Step 4: join orders to visits

Match each order's ID to that visitor's earlier visits and credit one of them with a rule you keep fixed (see first touch or last touch). Orders with no ID have no visit to join, so they show as Unattributed.

Step 5: handle refunds and renewals

Refunds do not change an order's creation time, so a scan that only looks at new orders will miss them. Rescan recent orders for refunds on a schedule, or a channel will look better than it is. Renewal invoices should keep the channel of the subscription's first payment.

Step 6: report revenue per channel

Group the joined orders by channel and divide by visitors to get revenue per visitor. That is the table that tells you where to spend time.

Checkout on another domain or a second site? See cross-domain checkout attribution.

What goes wrong

  • Passing the ID but never registering the webhook: orders import with no visitor and fall into Unattributed
  • A webhook address that LemonSqueezy cannot reach, such as a private or http URL
  • Building the checkout link before the script has loaded, so the ID is empty
  • Ignoring refunds, which overstates a channel

Frequently asked questions

Can LemonSqueezy show which traffic source a sale came from?

Not on its own. LemonSqueezy records the order, not the visit. You need to pass a visitor ID into checkout as custom data and join it to your analytics.

Why does LemonSqueezy need a webhook for this?

LemonSqueezy only returns checkout custom data in webhooks, not in its API responses for orders. A webhook for new orders and subscription payments is how the visitor ID reaches your analytics.

Which channel do LemonSqueezy renewals get?

Renewal invoices keep the channel of the subscription's first payment instead of landing in Direct.

Can I limit the LemonSqueezy API key to read-only?

No. LemonSqueezy API keys cannot be made read-only and they cover every store on your account, so store the key encrypted and delete it in LemonSqueezy to revoke access.
