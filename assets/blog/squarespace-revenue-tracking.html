Squarespace revenue tracking: see which channel brings each sale

By Devendra Variya, co-founder of Virling. Published 2026-11-19.

To see which channel brought each sale from a Squarespace site, every payment needs an ID that points back to the visit. If your site sells through a Stripe Payment Link, a LemonSqueezy checkout link or a Polar checkout link, the checkout page never sees the UTM tags or the referrer of the visit that led there. Add the Virling script with Squarespace Code injection, keep your checkout links as they are, and connect the provider. The script adds a visitor ID to every checkout link by itself, so each sale shows the post, search or ad that brought it, with no code beyond the script.

Why a Squarespace site loses the source at checkout

A visitor lands on your Squarespace page from a search, a post or a newsletter, then clicks a button that opens buy.stripe.com, a lemonsqueezy.com checkout or buy.polar.sh. The visit and its source stay on your site; the payment happens on the provider's page. Your analytics can see the visit but not the payment, and the provider sees the payment but not where the visit came from. On a Stripe Payment Link, for example, the UTM tags on your page are dropped and the Checkout Session has no field for the referrer.

What joins the two is one ID that the checkout keeps and hands back with the payment. Each provider has its own field:

  • Stripe: buy.stripe.com links get client_reference_id, read from the Checkout Session.
  • LemonSqueezy: lemonsqueezy.com checkout links get checkout[custom][virling_vid], read from the webhook's custom data.
  • Polar: buy.polar.sh links get reference_id, read from the order's metadata.

Dodo Payments (checkout.dodopayments.com) links are tagged the same way. The full list is in the checkout docs.

Squarespace Commerce is not supported. Virling does not import orders paid through the Squarespace cart and checkout, so this setup is for sites that link out to a provider's hosted checkout. If you sell with Squarespace Commerce, those sales will not appear in Virling.

Set up revenue tracking on a Squarespace site

Step 1: add the script with Code injection. In Squarespace, open Settings, Developer tools, then Code injection. On older menus it is under Settings, Advanced. Paste the tag into Header and save, so it loads on every page. The app shows the exact tag for your site:

<script defer src="https://app.virling.com/v.js" data-site="yourdomain.com"></script>

Code injection needs a Squarespace plan that includes it. The script records the referrer and UTM tags of every visit against a visitor ID in the first-party virling_vid cookie. Every step is in the framework setup docs.

Step 2: use plain checkout links. Set the link on your Squarespace button to the checkout URL from your provider, such as https://buy.stripe.com/abc123, https://STORE.lemonsqueezy.com/checkout/buy/VARIANT_ID or your Polar checkout link. Nothing else goes on the link. The script adds the visitor ID to every Stripe, LemonSqueezy and Polar checkout link when the page loads and again on click, and never replaces a parameter that is already there. The link must be a normal link: a checkout opened from an embedded widget or from JavaScript is not tagged. How each link is tagged is in Link checkout to visits.

Step 3: connect the provider. In Virling, add your provider under Payment connections in site settings. Stripe takes a restricted key with Read access. LemonSqueezy takes an API key, and Virling registers a webhook on each of your stores, since LemonSqueezy only returns checkout custom data in webhooks. Polar takes an organization access token. Virling reads the visitor ID from each payment and credits it to the visit, under the attribution model you pick: last non-direct by default, or first touch or last touch. Setup for each provider is on the integrations page.

Step 4: make a test payment. Use test mode and a test checkout link, open your published Squarespace site from a tagged URL such as ?utm_source=test, and pay with a test card. Wait a minute for the next sync, and the payment shows the test source instead of Unattributed. The UTM builder makes tagged links for your real campaigns.

When a Squarespace sale has no source

  • The sale went through Squarespace Commerce. Orders paid in the Squarespace checkout are not imported. Only payments from a connected provider show up.
  • The link was opened off your site. Checkout links in emails, social posts or QR codes never pass through a page with the script, so they carry no visitor ID. Send people to your Squarespace page and let them click through from there.
  • The checkout is not a plain link. Embedded checkout widgets and buttons that open the URL from JavaScript are not tagged. Link the button to the checkout URL instead.
  • The link is on a custom checkout domain. Only the provider hosts above are tagged. For another domain, add the ID yourself from window.virling.vid().
  • Cookieless mode. With data-cookieless there is no visitor ID to pass, so new payments are Unattributed.

Frequently asked questions

Can Squarespace show which channel brought a sale?

Not for a sale on a hosted checkout. When a Squarespace site sends buyers to a Stripe Payment Link, a LemonSqueezy checkout link or a Polar checkout link, the checkout page never sees the referrer or UTM tags of the visit. With the Virling script added through Code injection, those links carry a visitor ID, and Virling joins each payment to the visit and its channel.

Does Virling track Squarespace Commerce orders?

No. Squarespace Commerce checkout is not a supported payment source, so orders paid in the Squarespace cart are not imported. Virling tracks sales on Squarespace sites that link out to Stripe Payment Links, LemonSqueezy or Polar checkout links, or to another provider Virling connects to.

Which Squarespace plan do I need?

One that includes Code injection, since the script goes in through the Header field there. Check your plan before you start: without Code injection the script cannot run on the site.

Do I need code to track Stripe Payment Links on Squarespace?

No code beyond the script. Paste it into the Header field of Code injection and save. The script adds client_reference_id with the visitor ID to every buy.stripe.com link on the page, and Virling reads it from the Checkout Session.

Why does my Squarespace sale show as Unattributed?

The buyer did not click the link on a page running the script: they opened it from an email, a social post or a QR code. It also happens when the checkout opens from an embedded widget instead of a plain link, when the link is on a custom checkout domain, when the payment went through Squarespace Commerce, or in cookieless mode.
