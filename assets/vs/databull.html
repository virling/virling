Virling vs DataBull

DataBull is a paid, self-hosted tool that joins your payments to your visits. Virling does the same job as open source software that runs on any server, with a hosted option.

When DataBull is the better fit

You already run on Cloudflare, want a one-time licence instead of a subscription, and are happy with Stripe, Polar, Dodo Payments or Creem.

When Virling is the better fit

You want open source code you can read and change, a server that is not tied to one platform, LemonSqueezy or RevenueCat payments read with a key, or a free self-hosted install with every feature.

Which one fits a SaaS, a store or an agency

SaaS

DataBull is the better fit if you bill through Stripe, Polar, Dodo Payments or Creem, already use Cloudflare and want to pay once. Its attribution docs cover first touch, last touch and last non-direct, renewals credited to the visitor who bought the subscription, and lifetime value by first source. Timing matches can also credit a sale that arrives without its visitor.

Virling is the better fit if you bill through Paddle, LemonSqueezy or RevenueCat and want payments read with a key, if you want open source code, or if you want to see which pages AI crawlers read. It has the same three attribution models with a 30, 60, 90 or 365 day lookback, and retention by first channel.

Online store

Virling is the better fit for a Shopify or WooCommerce store: it reads orders and refunds with a read-only key. DataBull connects neither with a key, so each sale would be posted to its payments API from your server.

DataBull is the better fit if you sell digital products through one of its four providers, or through one that neither product reads with a key, such as Gumroad or PayPal, and you can send each sale from your own webhook.

Agency

DataBull is the better fit if you want one licence for your own team: its terms allow unlimited websites and team members on one production install, including websites you run for clients.

Virling is the better fit if clients need their own reports. An Agency account has white-label weekly emails and a report link per client, so a client does not need a login. Self-hosted accounts include up to 3 users.

Switching from DataBull, or running both

What to install

Three steps, and the first one differs by how your goals are written.

  • Add your site in the app, or with add-site on your own server, and put the Virling script in your page head. If your pages still use datafast() calls or data-fast-goal buttons, which DataBull also understands, add the compatibility script and they keep working. Other goal calls become virling("goal", "signup").
  • Connect your payment provider with a key. Virling reads the last 90 days of payments (60 for Shopify, one-time purchases only for RevenueCat), then new ones every minute, or by webhook for RevenueCat.
  • Pass the visitor ID into checkout. Stripe Payment Links, Polar, Dodo Payments and LemonSqueezy links get it automatically; a checkout you create on your server needs one field. Checkout code that sends the datafast_visitor_id cookie keeps working with the compatibility script. Code that sends databull_visitor_id needs the virling_vid cookie instead.

What history carries over

  • Payments from the backfill. They count toward revenue, but they are usually Unattributed, because Virling was not on your site when those visits happened.
  • Plausible history, if you still have the export you imported there. Self-hosted Virling can import the same export from the command line. Hosted accounts cannot.

What does not carry over

  • Visits, goals and journeys recorded by DataBull. Virling has no import for them.
  • Attribution of old payments. Virling only credits a payment to a visit it tracked. Renewals of a subscription that started before you connected are usually Unattributed too.
  • Your DataBull database stays in your Cloudflare account. Its uninstall page shows how to export it before you remove anything.

Running both

The two scripts use different cookies, so both can be on the page while you compare. Leave the compatibility script out until you switch, because it takes over datafast() calls.

Payment links need care: both scripts use the same field on Stripe and Polar links, and Virling never replaces a value that is already there. To compare fairly, create checkout on your server and send both IDs, with virling_vid in the metadata.

Frequently asked questions

Is DataBull open source?

No. Its FAQ says it isn't open source and the source code isn't included. Virling is open source under AGPLv3.

What does DataBull cost compared with Virling?

DataBull sells a one-time licence that showed $49 when we checked. Self-hosting Virling is free, with every feature.

Where does DataBull run, and where does Virling run?

DataBull deploys into your own Cloudflare account, using Workers and a D1 database. Virling is one binary that runs on a Linux or macOS server or in Docker, and there is a hosted version.

Can I move my DataBull history to Virling?

No. Virling has no import for DataBull data. It reads the last 90 days from your payment provider, and self-hosted Virling can import a Plausible or Google Analytics 4 export.

Does DataBull connect to Shopify or WooCommerce?

Not with a key. Its docs list Stripe, Polar, Dodo Payments and Creem, and a payments API for sales you send from your server. Virling reads Shopify and WooCommerce orders with a read-only key.
